# 2026-08-29 制作一键全自动与数字人重定义

> 按 [任务执行模板](../任务执行模板.md) 填写。规划全文见 `.trae/documents/production-oneclick-avatar-rework.md`。

## 目标

- 用户可感知的结果：
  1. 一键全自动成为制作默认行为：智能成片、爆款复刻、数字人三个入口在「上传素材」之后，脚本 → 配音 → 组装 → 本机合成全链自动完成，用户零额外点击；分步编辑保留为逃生口。
  2. 数字人模式重定义：用户只上传**一段**预处理数字人视频；配音（云端 TTS）、全量字幕由应用完成，AI 规划器把短视频裁剪、复制、回绕拼接成任意配音时长（10 秒素材配 30 秒配音也能成功）。旧「逐字稿 + 原声切片」仅存量项目保留。
  3. 分镜脚本流式生成：骨架句卡 + 流水文本实时上屏（`script-progress` 事件），与其他 AI 板块的流式体验一致。
  4. AI 自动配置字幕强调词：分镜句最多带 2 个 `emphasisWords`（必须逐字出现在句内），组装时进入对应字幕 cue。
  5. 去过度校验：单镜 300ms 硬下限改为软违规；原创性校验移到脚本生成期，配音完成后不再被合成期原创性阻断。

## 允许修改

- `packages/core`（script-storyboard 契约、avatar-segment-plan 规划器、subtitle-timing、production-bounds）
- `packages/ai`（schema、prompt、字幕时间轴、计划校验、脚本生成流）
- `packages/capacitor-runtime`（standalone-production-service 编排、脚本/计划记录、AutomaticPipelineResult DTO）
- `apps/web`（制作工作台、管线面板、复刻向导、制作表单）
- `apps/cli`（真 API 复现 harness `production-e2e`，仅开发回归）
- `android/app`（ProductionRenderer avatar 静音视频 + TTS 音轨路径、计划 parser 窗口字段、SubtitleTimeline 消费确认）
- `tests/` 与上述模块的定向测试

- 不新增云端后端、登录、同步、数据库或后台服务。
- 不改 Release 版本号与发布流程（版本发版不在本任务）。
- 不删除 v3 存量项目兼容渲染路径。

## 架构归属

- 分镜契约与净化：core；AI Schema/Prompt/校验：ai；管线编排与持久化：capacitor-runtime；页面接线：web；媒体合成 I/O：Android。

## 权威状态与数据

- `projectId` 单一权威状态源；`runAutomaticPipeline` 经 `#exclusive` 串行化，与既有分步方法互斥。

## 评审修复（review 应修项）

1. **avatar 合成失败根因**：AI 逐句建议贴纸不知全片上限，>6 条会被计划 schema 硬拒导致合成失败。服务端组装期确定性截断到 `MAX_DECORATIONS_PER_PLAN`，Prompt 同步声明全局上限；回归测试「8 句 7 贴纸截断到 6」。
2. **一键失败错误可见**：`#runAutomaticPipeline` 任一阶段失败把可行动 `issue` 落盘进 `project.issue` 后 rethrow；向导「一键制作成片」先带 `?project=` 跳转制作页再启动管线，失败原因在制作页可见、可重试。
3. **planning 状态跨页可见**：制作页识别 `planning`（脚本在别处生成中）并补挂 `script-progress` 流式订阅，阶段推导映射到分镜文稿生成中，不显示空白脚本区。
4. **软违规可见性**：制作页创建项目的一键路径捕获 `runAutomaticPipeline.softViolations` 并保留为信息性展示（成片照常产出，非确认闸门）；向导一键跳转、重开应用等没有组装结果的路径由面板从项目记录旁路推导 `avatar-source-short`（源视频 <5s 提示），与真实组装结果按 reason 去重；已出片后的提示文案改为信息性说明。
