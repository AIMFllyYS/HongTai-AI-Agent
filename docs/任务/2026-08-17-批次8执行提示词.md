## 与上一轮的唯一区别：无人值守授权

上一轮每遇到一点不确定就停下来问用户。本轮是夜间无人值守，没有人在旁边回答问题，因此授权范围明确放宽，同时把「什么时候必须停」写死。

### 明确授权（不需要请示，直接做）

- 读取仓库任何文件、任意搜索、运行任意只读命令。
- 修改各 sub-issue「影响范围」列出的文件，以及为了让改动自洽而必须连带修改的相邻文件。
- 新增、修改、删除测试；新增组件、样式、hook、helper 与文档。
- 运行 `pnpm check`、定向测试、`pnpm --filter @hongtai/web build`、Gradle 单测 / `lintRelease` / `assembleRelease`。
- 安装依赖前先确认确有必要，并在报告里写明原因。
- 在当前分支上逐条 commit。
- **执行过程中发现的、由本批改动引入的 bug，自己修掉，不要留给用户。**
- 发现与本批无关的既有缺陷：不要顺手改，用 `gh issue create` 登记一条新 Issue，在报告里给出编号后继续原任务。

### 硬性禁止（任何情况下都不做）

- `git push`、创建 PR、合并分支。用户没有授权推送。
- `git add .`、`git reset --hard`、`git clean`、删除未跟踪文件、丢弃工作区里不属于本批的改动。开工前工作区可能已有 `CHANGELOG.md`、`download.html`、`tests/android-version-lineage.test.ts` 等无关改动，必须原样保留，精确暂存。
- 创建 Git worktree 或复制式隔离工作区（`AGENTS.md` 明令禁止）。
- 为了让测试变绿而放宽断言、跳过用例、关闭 lint 规则、注释掉检查。
- 伪造进度、伪造成功、把 fixture 或模拟器结果表述成真机 / 真网验证通过。
- 在代码、日志、测试、文档或 commit 中写入任何真实 API Key、Cookie、Token、签名 URL。
- 新增宽泛 Android 权限、放宽 TLS 校验、引入云端后端或登录。
- 构建或归档 Debug APK。
- 修改 `android/app/build.gradle.kts` 的版本号（发布是独立动作，本批不做）。

### 只有这四种情况才停下来等用户

1. P 阶段判定某条 Issue「已不成立」——记录证据、跳过该条、继续下一条，在最终报告里说明；不要硬改。
2. 修复需要改变医疗边界措辞、发布口径，或删除用户可见的既有能力。
3. 同一条 sub-issue 返修两次仍未通过 C 阶段复查——记录卡点，跳到下一条，最后统一汇报。
4. 出现只能靠真机 / 真网才能判定的分歧（见下面 #86、#87 的处理约定）。

**注意第 1、3 条是「记录并继续」，不是「整批停摆」。** 一条卡住不影响其余六条推进。

## 各条注意事项

### #87 B 站链接解析（P0，packages/platforms、packages/core）

- 最可疑的主因是 Android 侧 `resolve()` 会先抓 2MB 上限的整页 HTML，而 `parse()` 根本不用这份 HTML。这条不需要真网就能改。
- wbi 是公开签名算法，不属于 Cookie / 登录 / 绕过风控，可以实现。但**不得**引入 Cookie、buvid 伪造或任何绕过风控的手段。
- 无 Cookie 拿不到的东西要明确失败，不能降级成模糊错误，更不能假装成功。
- 新增 `-352` 风控码必须同步登记进 `docs/错误码与前端通知约定.md`。
- 补的测试仍是 fixture，**不能**在报告里写成「真网已通过」。真网验证列为待办。

### #86 视频合成失败（P0，android/app、packages/capacitor-runtime、packages/core、apps/web）

- Issue 第一条验收是「先拿真机 logcat 再动代码」。无人值守拿不到真机，因此本轮**允许**在没有设备证据的前提下做以下不依赖根因判定的部分：
  - 把 `MEDIA_EXPORT_FAILED` 这个兜底垃圾桶拆成可区分的错误码，并登记进 `docs/错误码与前端通知约定.md`；
  - 允许硬件编码器失败后回退软件 H.264 编码器；
  - 让 `verifyOutput` 的契约与实际导出设定自洽（关闭 MIME fallback 或放开校验，二选一并写明理由，产物声明不得撒谎）；
  - `CreatePage` 传入 `retry`，`ProductionProjectCard` 持久展示 `project.issue`；
  - 纯图片工程失败时不再提示「请更换兼容的 MP4 素材」；
  - 补 `ProductionRenderer` 失败分类的 JVM 单测与 TS 侧映射断言。
- **不允许**在没有设备证据的情况下断言根因，也不允许把 Gradle 构建成功写成「真机合成已修复」。报告里必须写明：真机 logcat 与产物 MIME 验证仍待白天补做。

### #91 模板卡删除按钮（P2，apps/web/src/styles）

- 根因是 `analysis.css:310-315` 一段无调用点的 `.template-card` 两列 grid 泄漏到了 `library.css` 的模板卡上。删死样式前先全仓搜索确认真的无调用点。
- 桌面宽度不得回归。

### #89 底栏与页头（P1，apps/web）

- **先读 `docs/交互信息架构规范.md` 全文。** 四条硬规则和差异表是验收基准。
- 移除 `AppShell` 默认的无行为通知铃后，**必须逐页确认页头没有塌**。这是本条唯一容易造成大面积视觉回归的改动。
- 素材库入口的动效必须尊重 `prefers-reduced-motion: reduce`，静止就是静止。浅红走 token，不硬编码。
- `/publish` 的处置要么给真实入口、要么移出路由表，二选一并写明理由。

### #88 拆解链路（P1，apps/web）

- **先读 `docs/交互信息架构规范.md` 全文。**
- 核心手法是「一个页面组件，三个 URL 别名」：`/tasks/:id/processing`、`/tasks/:id`、`/tasks/:id/analysis` 渲染同一组件，旧链接不失效。这样改动面小、回滚容易。
- 合并页面时**必须**沿用 `apps/web/src/features/tasks/latest-read-guard.ts`（#61 的请求代次令牌）和 #58 的单实例挂载约束。不要另起一套订阅逻辑，这是上一轮刚修好的东西。
- `Tabs` / `TabPanel` 已经写好且可访问性齐全，直接用，不要重写。
- 本条是本批最大的结构改动，务必拆成多个 commit：先路由与页面合并，再 Tab，再首页来源 Tab，每步跑一次 `pnpm --filter @hongtai/web build`。

### #90 制作页（P1，apps/web）

- **先读 `docs/交互信息架构规范.md` 全文。**
- 阶段化主按钮的状态机在 Issue 正文里已经列成表，照着做，不要自己发挥。
- 完成态**不得**出现任何「发布」入口，发布能力是 `planned`。
- 不做时间轴、逐帧剪辑、转场编辑器。看到「工具栏轴、预览轴」这类词不要理解成要做剪辑器。
- 不改变素材、计划、成片的生命周期语义，不新增并发写入方。

### #92 启动图标（P2，android/app/src/main/res）

- 仓库现在**完全没有** adaptive icon，用的是一张 1024×1024、无 alpha 通道的白底 PNG。要新建 `mipmap-anydpi-v26` 分层。
- `tests/android-plugin-boundary.test.ts:243-251` 现在要求 Android 图与 `apps/web/public/brand/hongtai-app-icon.png` 字节完全一致，做分层或抠图必然打破它，需要同步调整该测试的契约（改为同源校验而非字节相等），并在 commit message 里写明为什么改测试。
- 改完必须跑 `lintRelease` 与 `assembleRelease`，确认资源加载没被破坏。
- 真机桌面截图无法在无人值守下取得，如实标注待验证。

## 收尾

全部推进完成后：

1. 主线程亲自跑一次完整验证：`pnpm check`、`pnpm --filter @hongtai/web build`、相关 Gradle 单测与 `assembleRelease`。
2. 派一个只读子代理对整批 diff（`git diff origin/main...HEAD`）做防回归复查，重点看跨层越界、并发写入、生命周期终态、真实性、UTF-8 与 U+FFFD。
3. 更新 `docs/当前能力与发布状态.md` 的修复队列与能力矩阵；如有能力状态变化同步 `CHANGELOG.md`（版本号不动）。
4. **不推送、不建 PR。** 在最终报告里给出：每条 Issue 的完成状态、commit SHA 列表、验证命令的真实退出码、待真机 / 真网验证的清单、以及执行中新登记的 Issue 编号。
