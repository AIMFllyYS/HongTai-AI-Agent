# 2026-08-21 深色模式表面与小控件

## 目标

- 用户可感知的结果：打开深色或跟随系统后，页面底仍是近黑，次按钮、头像井、加号菜单圆标、观察模式卡、追问条、制作时长分段等小控件不再保持浅色薄荷/白底；切回浅色后这些控件仍是原来的淡绿底。

## 允许修改

- `apps/web/src/styles/tokens.css` 两套 dark 选择器
- `apps/web/src/styles/components.css` 与 `styles/pages/*.css` 中绕过 token 的浅色硬编码
- `android/app/src/main/res/values-night/colors.xml`
- `tests/web-dark-tokens.test.ts`、`tests/web-brand-splash.test.ts`
- `docs/交互信息架构规范.md`、`docs/项目架构解析.md`、`docs/文档索引.md`、`CHANGELOG.md`、本任务契约

## 明确不做

- 不改浅色 `:root` 数字，不重画未归档浅色 1:1，不给 Lucide 单独上色或 `invert`。
- 不用 `color-mix()`（WebView 基线 Chromium 89）。
- 不改制作预览/成片字幕烧录色，不把 `/playbook` 做成产品 Tab。
- 不改 Flow / Schema / Kotlin 业务，不推进 `versionName` / `versionCode`。
- 不声称真机通过。

## 架构归属

- 所属层：UI（`apps/web`）与 Android 启动帧颜色资源。
- 禁止跨越：Kotlin 不得决定深浅色业务规则；页面仍只消费 `AppRuntime` DTO。

## 权威状态与数据

- 外观权威：`hongtai.appearance.v1` 的 `colorScheme`（`system` / `light` / `dark`）。
- `system` 删除 `data-color-scheme`，由 `prefers-color-scheme` 生效；强制深浅色写到 `document.documentElement.dataset.colorScheme`。
- 无新业务 ID。

## 验收

- 定向测试：`tests/web-dark-tokens.test.ts`、`tests/web-brand-splash.test.ts`、`tests/web-home-vitality.test.ts`、`tests/web-appearance-preferences.test.ts`
- 构建 / lint：`pnpm check`、`pnpm --filter @hongtai/web build`
- 浏览器或真机证据：设置分别切浅色 / 深色，桌面与约 390px 抽查首页粘贴钮、加号 Sheet 圆标、观察模式卡、追问条、制作时长分段、设置头像。不声称真机通过。
- 用户实际会看到什么：深色里小控件是深薄荷井；浅色仍是 `#e6f7f1` 家族。

## 交付说明

- 改了什么：补全 dark token；硬编码浅色井改走表面 token；系统夜间启动底对齐 `#121413`。
- 刻意没有做什么：不另画深色设计稿；应用内强制深色而系统仍浅色时，Android 启动帧仍跟系统。
- 剩余风险：个别装饰性媒体渐变（森林/墨色占位、视频上的白字）保持设计原样；物理机 WebView 未验。
