# 2026-08-30 智能成片链路修复与删除确认统一

## 目标
- 用户可感知的结果：
  1. 智能成片「一键制作成片」不再必报「所需内容不完整 / 制作项目不存在或已损坏」；新项目从创建起可被管线正常读取。
  2. 打开「数字人出镜」后，composer 页直接出现上传卡片；先传一段数字人预处理视频，再点「一键制作成片」。
  3. 新建项目不再把旧项目的脚本/配音/报错混进新页面；失败兜底不串项目。
  4. 全部删除确认（项目、素材、成片）统一为底部上拉确认弹层，与观察记录一致。
  5. 「预估总时长」等贴线/重叠排版修复；AI 深度思考在脚本生成期真实流出。
  6. 浏览器真实端测（真实 MP4）+ 双宽度截图 + 子智能体可读性评审，最后出 v0.1.27 Release APK。

## 允许修改
- `packages/capacitor-runtime/src/standalone-production-record.ts`（parseProject 校验）及其定向测试
- `apps/web/src/features/production/`（workbench 页面状态、composer 表单、pipeline 面板、删除确认）及其测试
- `apps/web/src/components/`（复用 Sheet；必要时新增一个≥2 调用点的确认弹层组件）
- `apps/web` 相关 CSS（排版与间距）
- 版本与发布：`android/app/build.gradle.kts`、更新说明页、`output/apk-archive/`
- 活文档：`docs/当前能力与发布状态.md`、本任务契约、验收文档

## 明确不做
- 不改 core/ai 包的 Schema 与 Flow 契约（`analysisTaskId` 保持字符串类型，仅放宽 runtime 读取校验）
- 不新增云端后端、登录、同步；不新增系统权限
- 不改 Media3/Kotlin 渲染路径；浏览器端测不声称真机合成通过
- 不动归档画板；不做 #97 云数字人、#118 原子交换、#120 清单比对
- 旧 v3 存量项目行为不变

## 架构归属
- UI（apps/web）：composer 上传卡片、删除弹层、排版、状态隔离
- capacitor-runtime：parseProject 读取校验（不复制 Pipeline/状态机，只修单点校验规则）
- 依赖方向不变：UI 只消费 AppRuntime DTO；runtime 不导入 UI/Android API

## 权威状态与数据
- projectId：每个新项目一个权威记录（`project.json`）；composer 草稿项目与历史记录同一存储
- 并发：`#exclusive` 单项目串行不变；素材选择外部 Activity 仍走 `pendingRequirementOrder`/`consumeAssetRecovery` 恢复
- 失败：管线失败必须落盘 `project.issue` 或页面 issue，不得假成功；失败后选中项目必须是真实可读项目

## 验收
- 定向测试：runtime parseProject 空 `analysisTaskId` 用例；workbench composer 状态隔离用例；删除弹层与上传卡片 UI 断言
- 构建 / lint：`pnpm check`、`pnpm --filter @hongtai/web build`
- 浏览器或真机证据：Vite 浏览器态真实 MP4 走「拆解 → 智能成片 → 数字人上传 → 一键制作」到组装前（浏览器 render 诚实抛 `ERR_MEDIA_ENCODER_UNAVAILABLE`，不声称 Media3 通过）；桌面 + 约 390px 截图；截图交子智能体评审「是否重叠/清晰/看得懂」
- 用户实际会看到什么：composer 数字人开关下出现上传卡片；一键制作进入脚本流式生成（可见深度思考）；失败文案指向真实原因；删除弹层从底部上拉

- 改了什么：见各阶段 commit

- 剩余风险或新增 Issue：端测中发现的非本任务范围问题登记为独立 Issue
