# v0.1.12 舌诊与面诊质量优化任务契约

## 目标

- 用户可感知的结果：清晰图片能得到 3–6 条可见观察；轻微拍摄瑕疵仍继续分析；实时深度思考主要围绕图片证据、知识组合和干扰因素。

## 允许修改

- `packages/ai` 的诊察 Prompt、紧凑响应 Schema、知识库和 `DiagnosisFlow`。
- 诊察相关测试、版本唯一来源、应用内更新记录、当前能力状态和本阶段验收文档。

## 明确不做

- 不修改图标、富迪素材库、视频制作、Media3、TTS、公开报告 DTO 或历史报告结构。
- 不新增第二次思考整理调用、过滤流水线、Agent 循环、RAG、后端、数据库或 Android 业务规则。

## 架构归属

- 所属层：`packages/ai`；Web 只继续消费既有运行期 DTO。
- Prompt、Schema、知识边界与报告组装只保留在共享 AI Flow；Capacitor 和 Kotlin 不复制规则。

## 权威状态与数据

- `sessionId` 仍是一次观察会话的权威标识；完整 `diagnosis-report.v1` 校验后才原子保存。
- reasoning 只通过版本化运行期进度 DTO 展示，不持久化、不写日志、不加入后续对话。
- 初次视觉生成失败时最多保留现有一次纯文本格式修复；修复不重新发送私有图片。

## 验收

- 定向测试：Prompt、知识库、紧凑 Schema、Flow、多观察映射、流式板块、reasoning 与后续对话。
- 构建 / lint：`pnpm check`、Web build、Release 单测、lint、assemble 与签名后验。
- 浏览器或端侧证据：桌面和约 390px 页面检查；可用 API 35 模拟器执行无降级覆盖安装、冷启动和页面链路。
- 用户实际会看到什么：清晰图片 3–6 条观察、有限图片保留可见分析、0–3 条有条件的传统参考，以及聚焦证据的真实深度思考。

## 交付说明

- 改了什么：内部紧凑响应升级为 v2，Prompt 升级为 v3，最终公开报告继续使用 `diagnosis-report.v1`。
- 刻意没有做什么：不整理或改写供应商 reasoning，不扩大医疗结论边界。
- 剩余风险或新增 Issue：没有真实 Provider 或物理设备时，只能声明对应能力尚未完成真实端测。
