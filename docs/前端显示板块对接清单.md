# 应用界面层数据对接清单

> 适用对象：React 应用界面层开发与验收。页面只通过 `AppRuntime` 获取真实 DTO、事件和安全展示 URI；`workspace/` 是 CLI 开发期产物，不是移动端 UI 数据源。

## 数据入口与禁止边界

```text
页面 / 组件
    ↓ 仅调用
AppRuntime
    ↓
共享 Flow、仓储与 Android 原生端口
```

页面不得读取 Android 私有路径、`content://` 临时 URI、原始平台响应对象、Cookie、下载请求头或 API Key。供应商 reasoning 只能通过 `structured-generation-progress.v1.thinking` 在当前运行中展示，不能由页面直接解析 Provider 事件，也不能进入正式结果或本地历史。静态 fixture 只允许用于明确的开发/视觉回归入口，不能与真实任务列表混合，更不能作为成功结果。

## 页面、路由与服务映射

| 页面 / 路由 | 服务 | 真实内容 | 禁止内容 |
| --- | --- | --- | --- |
| 首页 `/` | `tasks.inspectInput`、`tasks.create`、`tasks.subscribeChanges`、`analysis.importVideo(onEvent?)` | 分享文案、支持链接、平台与实验性提示；系统选择的本地 MP4 自动进入正式拆解；任务历史和五板块进度自动更新 | 复制正则、假上传、假任务、固定轮询 |
| 任务 `/tasks/:taskId`（`/processing`、`/analysis` 为同一 `TaskPage` 别名） | `tasks.get`、`getDetail`、`listEvents`、`subscribe`、`subscribeChanges`、`tasks.delete`、`analysis.get`/`run`/`subscribe` | 处理中渲染七阶段；完成后同一页用 Tab 看媒体/文稿/拆解。互动量五格为真实非负整数或「未解析到」；本地占用来自 `byteLength` 合计或「未解析到」 | 三个互不通信的页面、第八阶段、假百分比、硬编码 42/1.2w/128 MB、运行中删除 |
| 设置 `/settings` | `profile.get`、`aiSettings.getPublic`、`deviceSettings.getAppInfo`；外观/通知/清缓存为本机偏好 | 资料入口、AI 入口、通知开关、深色模式、主题色说明、真实缓存估算、关于、隐私说明 | 硬编码 128 MB、假装检查更新、删除 IndexedDB/密钥 |
| 档案 `/settings/profile` | `profile.get`、`profile.update` | 本地档案与安全头像 URI | 登录、远程账号假象 |
| AI 设置 `/settings/ai` | `aiSettings.getPublic`、`save`、`replaceApiKey`、`probe`、`getProbeResults` | 公共配置、掩码状态、独立探测 | 完整 Key、原始 HTTP 错误 |
| 应用信息 `/settings/app-info` | `deviceSettings.getAppInfo` | 运行中 APK 的 `versionName` / `versionCode` 与更新记录 | 硬编码版本号 |
| 设计稿对照 `/playbook`、`/playbook/:sectionId` | 无。只展示 `apps/web/src/playbook` 的图标与板块标本 | 未归档画板的色系、字体、Lucide 图标、底栏、设置行、拆解与观察板块 | 真实任务列表、诊察结果、密钥、把对照标本写成用户数据 |
| 观察新建 `/observation/new` | `diagnosis.pickImage`、`captureImage`、`consumeImageRecovery`、`createSession`、`listSessions`、`subscribeReport` | 舌象或面部单模式、单张已导入图片、副标题日常参考、页底免责、确认后立刻进入会话进行中页、自动更新的观察历史 | 起始页生成进度卡、确诊口吻、概率数字、处方、健康评分、多模式混用、固定轮询 |
| 观察进行中 / 报告 `/observation/:sessionId` | `diagnosis.getSession`、`getReport`、`listMessages`、`runReport`、`subscribeReport`、`followUp` | pending/running 渲染未归档 S9b「AI 正在观察」（真图扫光、运行期深度思考、五模块状态）；成功后同一地址展示正式报告、需医院核实的不确定初步判断、页底追问输入和顶底免责。对话在 rise Overlay「AI 追问」中展示真实消息历史。取消返回起始页，不宣称已停止 AI | 确诊口吻、健康评分、体征 HUD 数字、概率数字、处方、伪聊天记录、未校验医疗内容、未接通的「有用」反馈 |
| 制作 `/create` | `production.list`、`create`、`importAssets`、`consumeAssetRecovery`、`removeAsset`、`generatePlan`、`render`、`removeOutput`、`delete`、`subscribe` | 两张入口卡（Agent 模式 / 爆款复刻）、项目、私有素材摘要、计划、真实渲染状态、成片 URI 和具名删除确认。爆款复刻只选来源并跳到 `/replica/:taskId`，不在本页复制向导 | 示例素材、假计划、假进度、只从页面隐藏的假删除、「AI 看懂素材」 |
| 导出微调 `/create/:projectId/edit` | `production.get`、`updatePlan`、`subscribe` | 卡片式改镜头与全局字幕模板/主文字/语速/BGM；cue 时间不由页面提交 | 把 `PRODUCTION_PLAN_VERSION_STALE` 当成本地合成重试、提交调用方编造的 cue 毫秒 |
| 复刻向导 `/replica/:taskId` | `replica.get`、`run`、`startProject`；绑定走 `production.importAssets` / `removeAsset`，计划走 `production.generatePlan` | 成功拆解转成的素材需求清单、逐项绑定、生成脚本和字幕后进入微调页 | 未拆解就开向导却假装已有清单、绑错文件却声称已核对画面 |
| 模板 `/templates` | `templates.list`、`createFromAnalysis`、`create`、`update`、`delete` | 正式拆解中的可复用结构和用户自定义模板 | 原视频副本、供应商响应、reasoning、云模板假象 |
| 兼容地址 `/assets` | 路由别名 | 迁移到 `/templates` | 继续展示已废弃的假素材页 |
| 发布（无路由） | `features.publish`（能力标记，不是服务对象） | 路由表没有 `/publish`；`PublishPage.tsx` 仅残留并由测试锁「尚未接入」 | 平台跳转、假发布成功、把残留页重新挂进底栏 |

`AppRuntime` 上还有一个不属于任何单页的服务：`recovery.recoverInterruptedWork()`。它只在 `main.tsx` 的组合根启动时调用一次，页面不得自行触发。

路由只携带业务 ID。刷新或重启后必须从仓储重载，不能以跳转前内存对象作为唯一数据源。初始列表读取与实时订阅并发时，页面按读取开始时的本地事件游标回放期间到达的窄事件，并拒绝更早请求的迟到结果；任务删除必须作为事件回放，不能只按时间戳合并。

## 单次结构化 AI 进度与自动更新

内容拆解、舌象观察和面部观察在正常路径各执行一次简单的结构化流式调用，不是 Agent。模型生成一份紧凑 JSON；应用逻辑层把稳定顶层字段投影为五个展示板块——内容拆解是五个字段一一对应，图片观察是八个字段按组合成五个板块。页面收到的是 `structured-generation-progress.v1` 累计快照，而不是 Provider 响应对象：

1. `thinking.status=streaming` 时自动展开“深度思考”，按纯文本追加当前运行的推理内容；完成后自动收起，用户可随时手动展开或折叠。文本必须由 React 转义，不得作为 HTML 注入。
2. 尚无已校验结果时显示五个板块名称，当前板块显示流光骨架，其余显示“等待生成”。
3. 顶层字段或字段组完整闭合并通过对应 Zod 与语义校验后，才把板块标为 `succeeded`；领域 presenter 只按白名单字段展示内容，不使用 `JSON.stringify` 兜底。
4. 完整文档校验失败时最多进行一次整体结构修复，页面显示“正在校正完整结构”；诊察修复不再次发送私有图片。
5. 生成失败时保留本次内存中的已完成板块，显示稳定 `TaskIssue`，后续板块显示“未开始”；这些内容和推理文本都不保存成正式半成品。
6. 五个板块全部完成后仍需完整 Schema 校验和原子保存，页面再重新读取正式 DTO；不能直接把内存投影拼成正式报告。
7. 流光和约 600ms 渐显只是业务状态反馈，不代表模型逐字符业务结果；`prefers-reduced-motion` 下禁用相关动画。

任务、拆解和报告终态先持久化再通知。首页、详情、拆解页和观察页通过窄订阅自动合并变更，健康状态下不显示手动刷新；读取或订阅失败时才提供“重新读取”。不使用固定间隔轮询、WebSocket、后台服务或全量历史重复请求。

## URL 采集与内容拆解

首页接受完整分享文案；UI 调用唯一预检入口 `inspectInput(rawText)`，展示第一个受支持链接和实验性提示。正式创建任务后再由共享 Pipeline 规范化输入。

本地视频入口调用 `analysis.importVideo()`，由 Android 系统选择器导入单个受控 MP4，再复用同一七阶段、ASR、证据和 `content-analysis.v1`。UI 不读取原始 content URI，不把本地视频显示为平台 URL，也不为本地来源复制另一套拆解组件。

处理页严格展示七个顶层阶段：`detect-platform`、`resolve-link`、`parse-content`、`select-media`、`download-media`、`obtain-transcript`、`save-artifacts`。阶段详情可以展示真实下载字节和转写分段，不能升格为第八阶段。

任务的可展示状态是 `queued`、`running`、`succeeded`、`degraded`、`failed`、`interrupted`。数据模型可兼容读取历史 `cancelled` 记录，但当前 standalone runtime 不支持成功取消运行中任务；UI 不得提供可用的“停止”承诺，直到取消路径真正实现并有回归覆盖。

内容拆解使用独立 `analysisStatus`，不改变七阶段。完全没有证据单元时拆解直接以 `TASK_ARTIFACT_MISSING` 失败，页面显示该问题与恢复动作，不展示空壳文档；证据存在但某个板块无内容时按空数组显示诚实空态。标题、作者、示例数据和 reasoning 都不能填补结果。

终态任务允许在详情页二次确认后删除；运行中的 taskId 拒绝删除。删除只清除该任务的私有媒体、文稿、拆解与事件，不级联删除已经独立保存的模板。

## 观察与图片导入

创建会话前，用户选择舌象或面部一种模式，再通过原生层导入一张图片到私有目录。成功导入后才允许创建会话；取消、读取失败、图片过大或质量不足必须结束忙碌状态并通过稳定错误码提示下一步。

报告页只按 `diagnosis-report.v1` 展示图片质量、可见观察、传统望诊参考（`wellnessReferences`，0–3 条）、日常建议、安全提示、局限和免责声明。传统望诊参考只在图片可用且存在直接可见观察时出现，固定标记为不确定参考与非诊断。不得使用智能诊疗、疾病概率、处方或综合健康评分等越界表达。

## 本地视频制作

制作页只能从已成功的 `content-analysis.v1` 创建项目。首页第一屏是 Agent 模式与爆款复刻两张入口卡；数字人口播是 Agent 流程内的 `mode: "avatar"`，不是第三张卡。Agent 真实顺序为：创建项目 → 用户主动导入素材 → 生成并验证制作计划 → 用户发起本地渲染 → 展示真实成功成片或稳定失败。爆款复刻选来源后跳到 `/replica/:taskId`，不在制作首页复制向导。旧的 `production-plan.v1` 只保留读取与渲染兼容；新计划写入 v3（兼容读取 v2）。

创建项目时页面还会提交 `mode`（素材剪辑或数字人口播）、可选的 `headlineText` 顶部主文字、`textPreset` 文字预设，以及数字人模式下的 `avatarScript` 口播稿。素材数量按模式区分：素材剪辑模式要求至少三份；数字人口播模式导入一份带原声的 MP4 即可。Agent 文案不得声称「看懂素材」；旁白参考画面可见内容，核对留给用户逐镜完成。

页面不得直接访问素材文件路径、Media3 进度对象或项目 JSON。渲染/导入期间需要显示真实忙碌状态；中断、失败或应用重启后必须让用户看到明确状态和安全的下一步，不能永久展示“制作中”。

删除素材、成片或整个项目必须先显示具名确认。素材删除使引用它的计划和成片失效；成片删除保留计划；项目删除清除自己的受控目录。任一原生删除失败都必须显示失败，不能只过滤 React 状态。发布没有接入，不从制作项目“顺手”扩展为发布流程。

## 模板管理

模板是从正式 `content-analysis.v1` 复制出的公式、步骤和变量槽，或由用户从空白结构创建的独立本地记录。页面允许编辑名称、摘要、公式、逐行步骤与变量，并在二次确认后删除。模板不保存视频、平台原始响应或供应商 reasoning；来源任务删除后，已经保存的模板继续存在。

## 问题展示与空态

所有页面通过同一 `TaskIssue.code/action` 映射提示和动作。`userMessage` 是显示文本，不是逻辑输入；错误码与动作表见[错误码与应用界面通知约定](错误码与前端通知约定.md)。

媒体、正文、文稿、分析结论或视频成片尚未真实获得时，显示空态或问题，不能用 fixture 伪装为成功。互动量未解析到时显示「未解析到」，不能用 42、1.2w、2.4 万之类假数据填格。成功产物不得被后续失败删除。
