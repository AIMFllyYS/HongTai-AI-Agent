# 前端显示板块对接清单（URL 抓取拆解产物）

> 适用对象：前端设计师 / 对接同学
> 目的：说明「抓取拆解 URL」任务每次统一产出的目录结构与内容种类，便于先做前端显示板块。
> 数据模型来源：`packages/core/src/models.ts`、`packages/node-runtime/src/storage/file-artifact-store.ts`、`packages/core/src/pipeline.ts`

---

## 1. 总览：每次任务都产出同一套目录

无论平台（抖音 / 小红书 / B站），无论内容类型（视频 / 图文），每次任务都在 `workspace/tasks/<taskId>/` 下生成统一骨架：

```
tasks/<taskId>/
├── task.json            # 任务记录：状态 / 平台 / 内容类型 / 问题 / 路径
├── task.log             # 进度日志：每行一条 JSON 事件（调试用）
├── metadata.json        # 解析后的结构化内容【前端主数据源】
├── raw/                 # 原始素材（调试用，不直接展示）
│   ├── response.json    # 平台原始返回（含互动数据、话题标签）
│   └── page.html        # 抓取的页面 HTML
├── media/               # 已下载的媒体
│   ├── video.mp4                         # 视频类主文件
│   ├── video-only.m4s / audio-only.m4s   # 分音视频流平台（抖音/B站常见）
│   ├── audio.wav                         # 开启语音识别时生成
│   ├── segments/segment-XXXX.wav         # 转写分段音频
│   └── images/image-NNN.jpg             # 图文类：1~N 张
├── content/content.txt  # 图文正文（仅图文类型）
└── transcript/          # 文稿区（仅视频类型）
    ├── transcript.txt   # 原始文稿
    ├── transcript.json  # 时间轴分段 + 状态
    └── draft.txt        # AI 整理稿（仅配置改写模型且成功时）
```

## 2. 前端显示板块拆解

### 板块 1：任务状态条（每次必有）

数据来源：`task.json`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `status` | `succeeded` / `degraded` / `failed` | `degraded` = 降级但仍可用，`failed` = 无可用产物 |
| `platform` | `xiaohongshu` / `douyin` / `bilibili` | 平台标识 |
| `contentType` | `video` / `image_text` | **决定下面走视频布局还是图文布局** |
| `currentStage` | string | 当前阶段，用于进度展示 |
| `speechStatus` | `transcribed` / `no_speech` / `failed` | 仅视频类型，语音转写状态 |
| `issues[]` | array | 问题清单，结构见第 4 节，需做提示/告警展示位 |

### 板块 2：内容信息卡（解析成功即有）

数据来源：`metadata.json`（`PlatformContent` 模型）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `title` | string? | 标题 |
| `description` | string? | 描述 / 正文摘要 |
| `author` | string? | 作者昵称 |
| `coverUrl` | string? | 封面图 URL |
| `platform` | string | 平台 |
| `contentType` | string | 内容类型 |
| `sourceUrl` | string | 用户原始链接 |
| `canonicalUrl` | string? | 平台规范链接 |
| `durationSeconds` | number? | 时长（秒） |
| `videos` / `audios` / `images` | array | 媒体源列表，结构见板块 3 |
| `subtitles` | array | 平台原生字幕（**当前恒为空 `[]`**，预留） |

### 板块 3：媒体展示区（每次必有，否则任务降级 / 失败）

- **视频类**：主文件 `media/video.mp4`；若平台分音视频流（抖音/B站常见），另含 `video-only.m4s` + `audio-only.m4s`；开启 ASR 时额外有 `audio.wav`。`metadata.videos[]` 每项含 `url / quality / codec / width / height / hasWatermark / headers`（下载所需请求头，前端播放一般只需 `url`）。
- **图文类**：`media/images/image-NNN.jpg`，**1~N 张，张数不固定**。前端需支持图片画廊 / 轮播，数量动态。

### 板块 4：文稿 / 字幕区（仅视频类型；图文类型走板块 5）

- `transcript/transcript.txt`：**原始文稿**，每次视频任务都有。来源可能是 ASR 转写，或降级使用平台描述（`description`）。
- `transcript/transcript.json`：时间轴分段，可做「字幕时间轴」或「文稿 + 高亮」。结构：
  ```json
  {
    "speechStatus": "transcribed | no_speech | failed",
    "source": "asr | description | none",
    "durationSeconds": 7,
    "segments": [
      { "index": 0, "startSeconds": 0, "endSeconds": 30, "text": "...", "status": "succeeded" }
    ]
  }
  ```
- `transcript/draft.txt`：**AI 整理稿**，条件生成（仅配置改写模型且成功时）。缺失属正常（如本例 `TEXT_REWRITE_FAILED`）。

### 板块 5：图文正文区（仅图文类型）

- `content/content.txt`：由 `title` + `description` 合并的纯文本正文（两段用空行分隔），无 Markdown 格式。

### 板块 6：原始数据 / 调试区（可折叠，不强展示）

- `raw/response.json`：平台原始返回。**含互动数据**——点赞 `likedCount`、收藏 `collectedCount`、评论 `commentCount`、分享 `shareCount`、话题 `tagList` 等（示例见第 5 节）。
- `raw/page.html`：抓取页 HTML。
- `task.log`：阶段进度日志。

---

## 3. 内容类型 → 板块组合（最重要）

| `contentType` | 走哪些板块 |
| --- | --- |
| `video`（视频） | 板块 1 + 2 + 3（视频） + 4（文稿/字幕） |
| `image_text`（图文） | 板块 1 + 2 + 3（图片画廊） + 5（正文） |

> 前端必须按 `contentType` 切换布局，两套分支互斥。

---

## 4. 问题提示位（issues）

`task.json` 的 `issues[]` 每项结构（`TaskIssue`）：

| 字段 | 说明 |
| --- | --- |
| `code` | 错误码（稳定，前端据此判断类型，不要依赖 `userMessage` 字符串） |
| `severity` | `warning` / `error` |
| `stage` | 出错阶段 |
| `userMessage` | 中文兜底文案，直接展示给用户 |
| `retryable` | 是否可重试 |
| `action` | 建议动作：`edit_input` / `retry` / `wait_and_retry` / `check_network` / `configure_ai` / `free_storage` / `view_partial_result` / `none` |

完整错误码表与 action 映射见 `docs/错误码与前端通知约定.md`。

## 6. 给前端的 3 个关键提醒

1. **互动数据 / 话题标签当前不在 `metadata.json`**：`metadata.json` 只提取标题/作者/封面/媒体源等；点赞、收藏、评论、话题在 `raw/response.json`。若前端要展示这些数据，需要扩展 adapter 写入 `metadata`，或前端直接读 `raw`（不推荐，raw 结构随平台变化）。
2. **`subtitles` 已预留但当前恒空**：模型里有 `SubtitleSource[]`，实际字幕走 ASR 生成的 `transcript/`。可预留「平台字幕」位，但当前主数据源是 `transcript/`。
3. **`draft.txt` 可能缺失**：整理稿依赖 AI 改写模型配置，缺失属正常降级，前端需对 `transcript/draft.txt` 不存在做空态处理。
