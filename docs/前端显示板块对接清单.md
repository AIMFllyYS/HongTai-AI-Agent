# 应用界面层数据对接清单

> 适用对象：应用界面层（React / Presentation）开发与验收。
>
> 本文替代“页面直接读取 CLI 目录”的旧假设。APK 页面只通过 `AppRuntime` 获取真实 DTO、事件和安全 URI；`workspace/tasks/` 是 CLI 开发期产物格式，不是移动端 UI 的数据源。

## 1. 数据入口与禁止边界

```text
页面 / 组件
    ↓ 仅调用
AppRuntime（profile / aiSettings / tasks / analysis / diagnosis / features）
    ↓
仓储与原生运行时
```

页面不得直接访问 SQLCipher 表、`workspace/`、Android 文件路径、`content://` 临时 URI、原始平台响应、Cookie、下载请求头或 API Key。媒体由运行时导入到应用私有目录后，返回可安全展示的 URI；URL 的查询参数和片段不得在 UI 或日志中显示。

静态 fixture 只允许用于视觉回归或未连接运行时时的明确开发模式，不能与真实任务列表混合，更不能在正式入口充当成功结果。

## 2. 页面、路由与服务映射

| 页面 / 动态路由 | 数据服务 | 真实内容 | 禁止内容 |
| --- | --- | --- | --- |
| 首页 `/` | `tasks.inspectInput`、`tasks.create` | 混合分享文案、提取到的链接、平台、实验性提示 | 假粘贴、固定进度、复制正则 |
| 处理页 `/tasks/:taskId/processing` | `tasks.get`、`tasks.listEvents`、`tasks.subscribe` | 七阶段事件、单调序号、停止/重试状态 | “AI 分镜”等第八阶段 |
| 详情页 `/tasks/:taskId` | `tasks.get` | 真实元数据、媒体、文稿、问题、空态 | 硬编码互动量/完播量/字幕 |
| 内容拆解 `/tasks/:taskId/analysis` | `analysis.get`、`analysis.run` | `content-analysis.v1` 与证据 | 自动运行或虚构结论 |
| 档案设置 `/settings/profile` | `profile.get`、`profile.update` | 本地显示名、头像、门店、行业、标签 | 登录、退出登录、假 PRO 身份 |
| AI 设置 `/settings/ai` | `aiSettings.getPublic`、`save`、`probe` | 公开模型配置、掩码状态、三项探测 | 完整 API Key、TTS 占位项 |
| 观察新建 `/observation/new` | `diagnosis.create` | 舌象或面部单模式、单张已导入图片 | 多模式混用、医疗诊断 |
| 观察报告 `/observation/:sessionId` | `diagnosis.getSession`、`getReport`、`listMessages`、`followUp` | 真实报告、快捷追问、流式回复、历史 | 健康评分、伪聊天记录 |
| 制作 / 素材 / 发布 | `features` | `planned` 说明和禁用控件 | 假上传、假生成、假发布 |

路由携带业务 ID，刷新或重启后必须从仓储重载，不能以路由跳转前的内存对象作为唯一数据源。

## 3. 首页：分享文案输入与预检

首页使用多行输入框而非仅 `type=url` 的单行框，以支持用户粘贴“说明文字 + 多个链接”的完整分享内容。

1. 输入变化或粘贴后调用共享逻辑 `inspectInput(rawText)`。
2. 显示真实提取的第一个受支持链接、识别的平台和 `experimental` 提示；其他链接被忽略时仅作输入信息。
3. `INPUT_EMPTY`、`INPUT_NO_SUPPORTED_URL` 等问题由统一问题展示层处理。
4. 点击开始后调用正式任务创建；正式流水线必须再次规范化输入，预检结果不能替代实际解析。
5. 创建成功后跳转 `/tasks/:taskId/processing`，不得导航至固定静态处理页。

原始粘贴文字不持久化。UI 可在尚未提交时保留本地编辑状态，但提交后的任务只保存安全标准化链接。

## 4. URL 采集处理页

### 4.1 顶层状态

任务状态只可能为：`queued`、`running`、`succeeded`、`degraded`、`failed`、`cancelled`、`interrupted`。状态徽标、停止和重试按钮必须直接读取任务 DTO。

| 状态 | UI 行为 |
| --- | --- |
| `queued` | 显示等待执行，不伪造下载百分比 |
| `running` | 显示实时阶段、事件序号和可用进度 |
| `succeeded` | 进入详情，展示真实产物 |
| `degraded` | 展示可用部分与 `TaskIssue` 提示 |
| `failed` | 显示统一错误与可用动作 |
| `cancelled` | 明示用户已停止，保留已保存产物 |
| `interrupted` | 明示已中断，允许用户创建新重试任务 |

### 4.2 七阶段状态条

处理页严格只展示以下七个顶层阶段：

1. 识别平台（`detect-platform`）
2. 解析链接（`resolve-link`）
3. 提取内容（`parse-content`）
4. 选择媒体（`select-media`）
5. 下载媒体（`download-media`）
6. 获取文稿（`obtain-transcript`）
7. 保存产物（`save-artifacts`）

每个阶段使用真实 `pending`、`running`、`succeeded`、`degraded`、`failed` 状态。事件按 `sequence` 排序，订阅断开后重连应从已持久化的事件恢复。阶段详情可以展示下载字节、转写分段等实际信息，但不得把内部子步骤升格为第八阶段。

“停止”只对 `queued`/`running` 显示。重试永远创建新任务并在任务谱系中显示“重试自：{旧任务 ID}”；不能修改旧任务页面的事件或产物。

## 5. 任务详情：按真实内容类型分支

| `contentType` | 必显板块 | 条件板块 |
| --- | --- | --- |
| `video` | 状态与问题、内容信息、真实视频/封面、文稿状态 | 字幕/时间轴、已导入音频 |
| `image_text` | 状态与问题、内容信息、动态图片画廊、正文 | 无视频/ASR 区 |
| `unknown` | 已解析元数据、问题与安全空态 | 不猜测视频或图文布局 |

内容信息卡只显示仓储已有字段：标题、描述、作者、平台、来源链接的安全展示、时长、真实封面和媒体。字段缺失应隐藏该字段或显示“暂无”，不能替换成样例数字、作者、封面或播放量。

媒体区只使用已落盘且可展示的私有 URI。无水印状态、分辨率、编码等仅在运行时确有对应字段时展示；不得根据平台名称或静态样例推断。图文图片数量可变，画廊必须支持 1 到 N 张。

文稿区按 `speechStatus` 展示：

- `transcribed`：显示真实文稿和可用时间轴；
- `no_speech`：显示“未检测到有效口播”的正常结果，不显示伪文稿；
- `failed`：显示问题和部分已保存文稿（若有）；
- 图文正文：显示真实解析文本，不进入 ASR 布局。

平台原始响应、请求头、signed URL、Cookie、Token 与 reasoning 都不在 UI 提供“调试展开”入口。

## 6. 内容拆解：独立于采集任务的状态

任务成功或降级且具有可用证据时，详情页显示“AI 自动拆解”操作。点击后先取得用户确认，再调用 `analysis.run(taskId)`；名称中的“自动”指由 AI 完成拆解，不代表后台自动开始。

拆解使用独立 `analysisStatus`：`not_started`、`running`、`succeeded`、`failed`。它不改变七阶段状态条，也不改写任务 `currentStage`。

`content-analysis.v1` 的展示按真实返回值组织为：概览、钩子、痛点、结构、论点、风格、模板、风险和证据。证据不足时显示诚实空态和原因；标题、作者、演示数据和模型 reasoning 不能填补空白。每项可追溯结论应链接到可显示的真实文稿 segment 或图文 paragraph，而非原始平台响应。

## 7. 本地档案与 AI 设置

### 7.1 本地档案

档案页读取并编辑：显示名、头像 URI、门店名、行业和经营标签。`localProfileId` 只作本地标识；可空 `remoteAccountId` 是未来映射预留，首版不能显示为“已登录”。头像通过系统选择后复制至私有目录，选择失败应保持旧头像和表单数据。

### 7.2 AI 设置

设置页只提供一个活动连接：Base URL、文本模型、视觉模型、ASR 模型、ASR transport 与 JSON Object / JSON Schema 高级开关。API Key 是写入/替换控件，已保存状态只能显示掩码或“已配置”和更新时间。

文本、视觉、ASR 各有独立测试按钮和结果位，显示最近探测状态、时间和稳定错误码。三个结果不得互相覆盖或相互推断。页面不显示完整 Key、请求头、供应商 reasoning、原始 HTTP 错误或 `.env` 内容。

## 8. 舌象 / 面部观察与追问

创建页先选择**舌象**或**面部**一种模式，再拍摄/选择一张图片。选择后由原生层复制到应用私有目录，成功后才允许创建会话。界面必须保持模式可见，不能把两种观察合并成一个报告。

报告页按 `diagnosis-report.v1` 真实字段展示：图片质量、可见观察、日常参考、建议、安全提示、局限与免责声明。以下文案和展示均禁止出现：智能诊疗、诊断结果、疾病概率、处方、整体健康评分、轻度气虚。

追问区要求：

- 使用报告提供的 `followUpQuestions` 生成快捷问题胶囊；
- 提供不遮挡正文的多行输入框和发送按钮；
- 显示真实流式回复、失败重试和持久化的会话历史；
- 不能预填对话、伪造正在输入状态或把供应商 reasoning 展示为回答。

## 9. 预留能力与统一问题展示

制作、素材、发布页面从 `features` 读取 `planned` 状态。保留的设计壳必须让主要操作禁用，并在操作附近说明“尚未接入”；不调用空接口、不创建假任务、不展示假进度。

所有页面使用同一 `TaskIssue.code/action` 展示层，将 `retry`、`configure_ai`、`free_storage`、`select_media` 和 `view_partial_result` 转换为一致控件。错误码与动作表见[错误码与前端通知约定](错误码与前端通知约定.md)。

## 10. 开发期 CLI 产物的映射说明

开发期 `workspace/tasks/<taskId>/` 的 `task.json`、`metadata.json`、`media/`、`content/` 和 `transcript/` 是 Node 运行时实现的产物。迁移到 APK 时，它们由 SQLCipher 记录和应用私有文件实现相同业务含义，而不是让 React 直接依赖同一目录结构。

保留以下语义：成功产物不被后续失败删除；视频和图文布局互斥；`raw/` 只供脱敏排障；无口播不伪造文稿；不把平台互动数据或下载临时地址写入正式展示模型。
