# 应用界面层数据对接清单

> 适用对象：React 应用界面层开发与验收。页面只通过 `AppRuntime` 获取真实 DTO、事件和安全展示 URI；`workspace/` 是 CLI 开发期产物，不是移动端 UI 数据源。

## 数据入口与禁止边界

```text
页面 / 组件
    ↓ 仅调用
AppRuntime
    ↓
共享 Flow、仓储与 Android 原生端口
```

页面不得读取 Android 私有路径、`content://` 临时 URI、原始平台响应、Cookie、下载请求头、API Key 或供应商 reasoning。静态 fixture 只允许用于明确的开发/视觉回归入口，不能与真实任务列表混合，更不能作为成功结果。

## 页面、路由与服务映射

| 页面 / 路由 | 服务 | 真实内容 | 禁止内容 |
| --- | --- | --- | --- |
| 首页 `/` | `tasks.inspectInput`、`tasks.create`、`tasks.subscribeChanges`、`analysis.importVideo(onEvent?)` | 分享文案、支持链接、平台与实验性提示；系统选择的本地 MP4 自动进入正式拆解；任务历史和五板块进度自动更新 | 复制正则、假上传、假任务、固定轮询 |
| 处理页 `/tasks/:taskId/processing` | `tasks.get`、`listEvents`、`subscribe` | 七阶段事件、单调序号、真实问题 | 第八阶段、假百分比 |
| 详情 `/tasks/:taskId` | `tasks.get`、`tasks.delete`、`tasks.subscribeChanges`、`analysis.subscribe` | 元数据、媒体、文稿、问题、空态、拆解模块状态和终态任务删除确认 | 硬编码互动量、字幕或封面；运行中删除 |
| 内容拆解 `/tasks/:taskId/analysis` | `analysis.get`、`analysis.run`、`analysis.subscribe` | `content-analysis.v1`、真实证据和已校验五板块进度 | 公网任务未经确认自动运行、无证据运行、虚构结论、半截 JSON |
| 档案 `/settings/profile` | `profile.get`、`profile.update` | 本地档案与安全头像 URI | 登录、远程账号假象 |
| AI 设置 `/settings/ai` | `aiSettings.getPublic`、`save`、`probe` | 公共配置、掩码状态、独立探测 | 完整 Key、原始 HTTP 错误 |
| 观察新建 `/observation/new` | `diagnosis.create`、`listSessions`、`subscribeReport` | 舌象或面部单模式、单张已导入图片、五板块进度和自动更新的观察历史 | 医疗诊断、多模式混用、固定轮询 |
| 观察报告 `/observation/:sessionId` | `diagnosis.getSession`、`getReport`、`listMessages`、`runReport`、`subscribeReport`、`followUp` | 正式报告、已校验五板块进度、追问和真实历史 | 健康评分、伪聊天记录、未校验医疗内容 |
| 制作 `/create` | `production.list`、`create`、`importAssets`、`removeAsset`、`generatePlan`、`render`、`removeOutput`、`delete` | 项目、私有素材摘要、计划、真实渲染状态、成片 URI 和具名删除确认 | 示例素材、假计划、假进度、只从页面隐藏的假删除 |
| 模板 `/templates` | `templates.list`、`createFromAnalysis`、`create`、`update`、`delete` | 正式拆解中的可复用结构和用户自定义模板 | 原视频副本、供应商响应、reasoning、云模板假象 |
| 兼容地址 `/assets` | 路由别名 | 迁移到 `/templates` | 继续展示已废弃的假素材页 |
| 发布 `/publish` | `features.publish` | `planned` 说明 | 平台跳转、假发布成功 |

路由只携带业务 ID。刷新或重启后必须从仓储重载，不能以跳转前内存对象作为唯一数据源。初始列表读取与实时订阅并发时，页面按读取开始时的本地事件游标回放期间到达的窄事件，并拒绝更早请求的迟到结果；任务删除必须作为事件回放，不能只按时间戳合并。

## 模块化 AI 进度与自动更新

内容拆解、舌象观察和面部观察都由应用逻辑层固定顺序执行五个简单 AI 模块，不是 Agent。页面收到的是 `structured-generation-progress.v1` 累计快照，而不是 Provider `content_delta`：

1. 尚无已校验结果时显示五个模块名称，当前模块显示流光骨架，其余显示“等待生成”。
2. 当前模块进入唯一一次修复时显示“正在校正本板块结构”。
3. 只有 `status=succeeded` 且存在已校验 `result` 时，领域 presenter 才按白名单字段展示内容；不使用 `JSON.stringify` 兜底。
4. 模块失败时保留本次内存中的已完成模块，显示稳定 `TaskIssue`，后续模块显示“未开始”；这些内容不保存成正式半成品。
5. 五个模块全部完成后仍需完整 Schema 校验和原子保存，页面再重新读取正式 DTO；不能直接把内存模块拼成正式报告。
6. 流光和约 600ms 渐显只是业务状态反馈，不代表模型逐字符流；`prefers-reduced-motion` 下禁用相关动画。

任务、拆解和报告终态先持久化再通知。首页、详情、拆解页和观察页通过窄订阅自动合并变更，健康状态下不显示手动刷新；读取或订阅失败时才提供“重新读取”。不使用固定间隔轮询、WebSocket、后台服务或全量历史重复请求。

## URL 采集与内容拆解

首页接受完整分享文案；UI 调用唯一预检入口 `inspectInput(rawText)`，展示第一个受支持链接和实验性提示。正式创建任务后再由共享 Pipeline 规范化输入。

本地视频入口调用 `analysis.importVideo()`，由 Android 系统选择器导入单个受控 MP4，再复用同一七阶段、ASR、证据和 `content-analysis.v1`。UI 不读取原始 content URI，不把本地视频显示为平台 URL，也不为本地来源复制另一套拆解组件。

处理页严格展示七个顶层阶段：`detect-platform`、`resolve-link`、`parse-content`、`select-media`、`download-media`、`obtain-transcript`、`save-artifacts`。阶段详情可以展示真实下载字节和转写分段，不能升格为第八阶段。

任务的可展示状态是 `queued`、`running`、`succeeded`、`degraded`、`failed`、`interrupted`。数据模型可兼容读取历史 `cancelled` 记录，但当前 standalone runtime 不支持成功取消运行中任务；UI 不得提供可用的“停止”承诺，直到取消路径真正实现并有回归覆盖。

内容拆解使用独立 `analysisStatus`，不改变七阶段。证据不足时显示诚实空态，标题、作者、示例数据和 reasoning 不能填补结果。

终态任务允许在详情页二次确认后删除；运行中的 taskId 拒绝删除。删除只清除该任务的私有媒体、文稿、拆解与事件，不级联删除已经独立保存的模板。

## 观察与图片导入

创建会话前，用户选择舌象或面部一种模式，再通过原生层导入一张图片到私有目录。成功导入后才允许创建会话；取消、读取失败、图片过大或质量不足必须结束忙碌状态并通过稳定错误码提示下一步。

报告页只按 `diagnosis-report.v1` 展示图片质量、可见观察、日常参考、建议、安全提示、局限和免责声明。不得使用智能诊疗、疾病概率、处方或综合健康评分等越界表达。

## 本地视频制作

制作页只能从已成功的 `content-analysis.v1` 创建项目。真实顺序为：创建项目 → 用户主动导入至少三份素材 → 生成并验证 `production-plan.v1` → 用户发起本地渲染 → 展示真实成功成片或稳定失败。

页面不得直接访问素材文件路径、Media3 进度对象或项目 JSON。渲染/导入期间需要显示真实忙碌状态；中断、失败或应用重启后必须让用户看到明确状态和安全的下一步，不能永久展示“制作中”。

删除素材、成片或整个项目必须先显示具名确认。素材删除使引用它的计划和成片失效；成片删除保留计划；项目删除清除自己的受控目录。任一原生删除失败都必须显示失败，不能只过滤 React 状态。发布没有接入，不从制作项目“顺手”扩展为发布流程。

## 模板管理

模板是从正式 `content-analysis.v1` 复制出的公式、步骤和变量槽，或由用户从空白结构创建的独立本地记录。页面允许编辑名称、摘要、公式、逐行步骤与变量，并在二次确认后删除。模板不保存视频、平台原始响应或供应商 reasoning；来源任务删除后，已经保存的模板继续存在。

## 问题展示与空态

所有页面通过同一 `TaskIssue.code/action` 映射提示和动作。`userMessage` 是显示文本，不是逻辑输入；错误码与动作表见[错误码与应用界面通知约定](错误码与前端通知约定.md)。

媒体、正文、文稿、分析结论、互动数据或视频成片尚未真实获得时，显示空态或问题，不能用 fixture 伪装为成功。成功产物不得被后续失败删除。
