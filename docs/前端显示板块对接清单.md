# 应用界面层数据对接清单

> 适用对象：React 应用界面层开发与验收。页面只通过 `AppRuntime` 获取真实 DTO、事件和安全展示 URI；`workspace/` 是 CLI 开发期产物，不是移动端 UI 数据源。

## 数据入口与禁止边界

```text
页面 / 组件
    ↓ 仅调用
AppRuntime
    ↓
共享 Flow、仓储与 Android 原生端口
```

页面不得读取 Android 私有路径、`content://` 临时 URI、原始平台响应、Cookie、下载请求头、API Key 或供应商 reasoning。静态 fixture 只允许用于明确的开发/视觉回归入口，不能与真实任务列表混合，更不能作为成功结果。

## 页面、路由与服务映射

| 页面 / 路由 | 服务 | 真实内容 | 禁止内容 |
| --- | --- | --- | --- |
| 首页 `/` | `tasks.inspectInput`、`tasks.create` | 分享文案、支持链接、平台与实验性提示 | 固定进度、复制正则、假任务 |
| 处理页 `/tasks/:taskId/processing` | `tasks.get`、`listEvents`、`subscribe` | 七阶段事件、单调序号、真实问题 | 第八阶段、假百分比 |
| 详情 `/tasks/:taskId` | `tasks.get` | 元数据、媒体、文稿、问题和空态 | 硬编码互动量、字幕或封面 |
| 内容拆解 `/tasks/:taskId/analysis` | `analysis.get`、`analysis.run` | `content-analysis.v1` 和真实证据 | 自动运行、虚构结论 |
| 档案 `/settings/profile` | `profile.get`、`profile.update` | 本地档案与安全头像 URI | 登录、远程账号假象 |
| AI 设置 `/settings/ai` | `aiSettings.getPublic`、`save`、`probe` | 公共配置、掩码状态、独立探测 | 完整 Key、原始 HTTP 错误 |
| 观察新建 `/observation/new` | `diagnosis.create` | 舌象或面部单模式、单张已导入图片 | 医疗诊断、多模式混用 |
| 观察报告 `/observation/:sessionId` | `diagnosis.getSession`、`getReport`、`listMessages`、`followUp` | 正式报告、追问、真实历史 | 健康评分、伪聊天记录 |
| 制作 `/create` | `production.list`、`create`、`importAssets`、`generatePlan`、`render` | 项目、私有素材摘要、计划、真实渲染状态和成片 URI | 示例素材、假计划、假进度 |
| 素材 `/assets` | `features.assets` | `planned` 说明 | 假搜索、假素材库 |
| 发布 `/publish` | `features.publish` | `planned` 说明 | 平台跳转、假发布成功 |

路由只携带业务 ID。刷新或重启后必须从仓储重载，不能以跳转前内存对象作为唯一数据源。

## URL 采集与内容拆解

首页接受完整分享文案；UI 调用唯一预检入口 `inspectInput(rawText)`，展示第一个受支持链接和实验性提示。正式创建任务后再由共享 Pipeline 规范化输入。

处理页严格展示七个顶层阶段：`detect-platform`、`resolve-link`、`parse-content`、`select-media`、`download-media`、`obtain-transcript`、`save-artifacts`。阶段详情可以展示真实下载字节和转写分段，不能升格为第八阶段。

任务的可展示状态是 `queued`、`running`、`succeeded`、`degraded`、`failed`、`interrupted`。数据模型可兼容读取历史 `cancelled` 记录，但当前 standalone runtime 不支持成功取消运行中任务；UI 不得提供可用的“停止”承诺，直到取消路径真正实现并有回归覆盖。

内容拆解使用独立 `analysisStatus`，不改变七阶段。证据不足时显示诚实空态，标题、作者、示例数据和 reasoning 不能填补结果。

## 观察与图片导入

创建会话前，用户选择舌象或面部一种模式，再通过原生层导入一张图片到私有目录。成功导入后才允许创建会话；取消、读取失败、图片过大或质量不足必须结束忙碌状态并通过稳定错误码提示下一步。

报告页只按 `diagnosis-report.v1` 展示图片质量、可见观察、日常参考、建议、安全提示、局限和免责声明。不得使用智能诊疗、疾病概率、处方或综合健康评分等越界表达。

## 本地视频制作

制作页只能从已成功的 `content-analysis.v1` 创建项目。真实顺序为：创建项目 → 用户主动导入至少三份素材 → 生成并验证 `production-plan.v1` → 用户发起本地渲染 → 展示真实成功成片或稳定失败。

页面不得直接访问素材文件路径、Media3 进度对象或项目 JSON。渲染/导入期间需要显示真实忙碌状态；中断、失败或应用重启后必须让用户看到明确状态和安全的下一步，不能永久展示“制作中”。

素材库与发布没有接入，不从制作项目“顺手”扩展为全局素材库或发布流程。

## 问题展示与空态

所有页面通过同一 `TaskIssue.code/action` 映射提示和动作。`userMessage` 是显示文本，不是逻辑输入；错误码与动作表见[错误码与应用界面通知约定](错误码与前端通知约定.md)。

媒体、正文、文稿、分析结论、互动数据或视频成片尚未真实获得时，显示空态或问题，不能用 fixture 伪装为成功。成功产物不得被后续失败删除。
