## 一句话结论

完整功能源码已经统一进入仓库根目录。AI 采用“一次视觉生成、最多一次纯文本格式修复、五个已校验展示板块、运行期真实深度思考”；舌象与面部观察共用分层 Prompt 和独立 Markdown 知识库。清晰图片应形成 3–6 条可见观察，轻微瑕疵图片继续分析可辨部分，五脏六腑、湿气、胃寒和心火等内容只作为有组合依据且不确定的传统观察参考。APK 启动图标已改为带透明前景的 adaptive icon；底部导航为 5 项，富迪素材库从制作页页头打开，页面内原有 SVG 不变。视频制作规划会同时接收爆款原文与正式拆解，并以“仅供参考、不得作为新口播”的前缀约束原创输出；新计划支持顶部主文字预设和底部逐镜头字幕，Android Media3 只执行通过校验的计划。项目只使用根项目目录和 Release APK 交付路径，版本唯一来源是 `android/app/build.gradle.kts`；构建成功后按版本号分别归档，不覆盖旧 APK。当前源码与下载页推荐均为 `v0.1.16`/`versionCode=24`，公网文件已回验。2026-08-18 已在浏览器 Vite 开发态用真实公开 B 站链接跑通采集，并用成功拆解生成 `production-plan.v2`；这不是 APK、真机 Media3 或全部模型能力验收。已公开分发不等于全部门禁通过：物理设备完整端测仍未完成，相关能力不得表述为已通过真机验证。

AI 运行反馈是两条简单 AI Flow，不是 Agent、工具调用循环或动态编排器。诊察与内容拆解在正常路径各发出一次结构化流式请求；同一响应中的五个顶层字段或字段组完整闭合后，先通过对应 Zod 与业务语义校验，再发送 `structured-generation-progress.v1` 安全投影。完整文档无效时最多进行一次格式修复，诊察修复为纯文本且不再次发送私有图片。板块进度和推理文本都不持久化；WebView 或进程退出后不恢复半成品，用户重试会重新生成完整文档，只有完整 `diagnosis-report.v1` / `content-analysis.v1` 校验并原子保存后才成立。

任务列表、任务详情、内容拆解与观察报告在健康状态下通过按 ID 或窄变更事件自动更新。权威记录先落盘再通知页面；初始异步列表读取会回放读取期间到达的 upsert、delete 或报告终态，并拒绝更早请求的迟到结果，因此不需要固定轮询或手动刷新。只有读取或订阅失败时保留“重新读取”恢复动作。

  [#108](https://github.com/AIMFllyYS/HongTai-AI-Agent/issues/108) 给 `ProductionService` 补上 `updatePlan`：按镜头改素材、时长、口播与标题，按全局改字幕模板、语速、主文字和背景音乐。字幕时间轴一律由文案重建，**不接受调用方传入的 cue 时间**，因此微调后的时间来源诚实地降为 `script_estimate`；这条路径也让模板降级第一次真实可达——选 `karaoke_glow` 会得到 `classic_line` 并在 `degradedFromTemplateId` 留下原选择。并发保护用调用方回传的 `expectedUpdatedAt` 做乐观版本校验，覆盖进程内串行化看不见的**顺序**场景：界面隔着上一次微调或应用重启再提交会被拒绝。`updatedAt` 现在保证严格递增（时钟不走时取上一次加 1 毫秒），否则同一毫秒内的两次写入会共用 token、让旧界面通过两次校验。这条校验是 read-then-write，**不能**让两个真正并发的运行时实例变安全——写入前会再比对一次以缩小窗口，但关闭窗口需要文件层的原子交换；`render` 用开始时的快照做最终写入，属于同一个 TOCTOU，一并登记为 [#118](https://github.com/AIMFllyYS/HongTai-AI-Agent/issues/118)。校验全部通过后才写盘，失败不推进版本也不改盘上计划。微调会作废已渲染成片（按 `removeOutput` 的既有语义回到 `ready` 并删除 `output.mp4`）：`project.json` 先写、成片删除成功后才写派生的 `plan.json` 并广播状态，删除失败则回滚且不广播——否则界面会先收到一个 `ready`、以为微调已经生效。数字人模式不接受改口播与改时长，因为字幕是原声说出的词、单个视频按镜头时长顺序切片，改任一项都会让字幕盖在说着别的话的片段上。

  端侧验收发现一个阻断缺陷并已修：TypeScript 用容差判断整毫秒，Kotlin 用位精确的 `% 1.0 == 0.0`，于是 `8.005` 秒（IEEE-754 下是 8004.999999999999 毫秒）能通过校验落盘、却让渲染永久失败，且错误被兜底成可重试的合成失败。`ProductionPlanParser.secondsToMs` 改为四舍五入加同样的容差——原先的位精确判断连 `8.1` 秒都会拒绝，截断取整还会丢 1 毫秒。同时给 `ERR_INVALID_ARGUMENT` 建了映射，渲染器拒绝计划不再伪装成可重试的合成失败。其余修复：用户输入错误统一报 `PRODUCTION_PLAN_EDIT_INVALID` + `edit_input` 并按字段给准确提示（此前语速、音量、主文字越界都会被报成「字幕生成不出来」，模板与素材错误还会被报成 AI 输出问题、把用户引去重跑 AI）；微调与生成计划受同一条禁止照搬来源原文的约束；选了背景音乐时音量必须大于 0，取消音乐时不接受同时设置音量；只含零宽字符的口播按空内容拒绝，不会烧进一条看不见的字幕；私有文件删除失败映射为 `STORAGE_WRITE_FAILED`，不再向界面抛出无码的原生异常。

  已知未修：表情符号密集的口播按码位切句、Zod 按 UTF-16 计长，两者不一致时会被拒绝并给出「字幕生成不出来」的笼统提示。方向是 fail-closed 的，不会写坏项目，但提示不准确。

  顺带补齐两处 TypeScript 与 Kotlin 的校验落差：镜头时长必须精确到毫秒且毫秒总和必须精确等于目标时长（原先允许 0.01 秒浮点松弛），镜头画面不得引用音频素材。当前只有 TypeScript 单测与 JVM 单测证据，**没有真机渲染验证**。

  [#109](https://github.com/AIMFllyYS/HongTai-AI-Agent/issues/109) 把 `updatePlan` 接到界面：`/create/:projectId/edit` 是卡片式逐镜微调页，全局面板管字幕模板、主文字、语速与背景音乐，每个镜头一张卡片管时长、标题、口播，并用真实的第一条 cue 做模板预览。这条路径让 [#107](https://github.com/AIMFllyYS/HongTai-AI-Agent/issues/107) 遗留的两处「实现了但用户碰不到」第一次真实可达：模板选择会传给规划器，选 `karaoke_glow` 会得到 `classic_line`、界面在两处说明降级原因，`degradedFromTemplateId` 也第一次在用户产出的计划里非空。

  时长按契约必须精确加总，所以改一个镜头会把毫秒差按比例补回其他镜头。请求值与吸收差值的镜头都对齐 100 毫秒步长，因此只要目标时长也在步长上，界面上逐镜显示的秒数之和就仍等于总时长；滑杆本身按毫秒定位，以便如实显示旧计划里 6.667 秒这类不在网格上的时长。可调范围按「其余镜头还能吸收多少」收窄，界面不提供服务端必然拒绝的值。字幕出入点不由界面提交，只在保存后按文案和模板重算；卡片里的切分预览调用与 `updatePlan` **同一个** `buildShotCueTimeline`，因此显示的是「保存后会烧进画面的切分」而不是上次保存的结果——改时长或文案后预览立即跟着变，短于 0.6 秒的字幕也在保存前就按镜头提示「观众来不及看完」。数字人模式锁住口播与时长并说明原因。主文字、镜头标题、口播文案都是必填项，空值会在提交前被拦下并指名是哪一项，界面不让用户走到一次必然被服务端拒绝的保存。其中主文字尤其容易出错：`updatePlan` 把空值读成「保持原值」，所以界面直接拦住清空并说明留空不会删掉它，而不是提交一个会被静默忽略、保存后又被还原的空串。

  并发按 [#108](https://github.com/AIMFllyYS/HongTai-AI-Agent/issues/108) 的令牌语义处理：草稿有未保存改动时，订阅到的更新**不**替换版本令牌，而是停下保存并说明「盘上的计划已经比这一页新，现在保存会被拒绝」，同时给一个明确的「用最新计划，放弃这一页的改动」。版本过期（`PRODUCTION_PLAN_VERSION_STALE`）走同一条冲突提示，草稿原样保留、不整页重载，也**不**复用制作页把 `retry` 映射成本地合成的路径。字段级错误（`PRODUCTION_PLAN_EDIT_INVALID`）在页内展示服务端给的那一句，例如「第 1 个镜头的口播内容不能为空」，不被通用标题盖住。

  诚实性靠三条硬约束，不靠提示词自觉：每个分镜必须至少引用一条真实证据 id，引用不存在的 id 会被拒绝并只修一次（仍失败报 `AI_FORMAT_REPAIR_FAILED`）；说不出画面时必须交空清单加 `emptyReason`，给了分镜就不能同时声明证据不足；脚本草稿与制作计划受**同一条**原创约束——为此把「连续 12 字照搬」抽成共享的 `sharesVerbatimRun`，把证据 id 校验抽成共享的 `assertEvidenceRefs`，拆解流程改为调用同一份实现，避免两处规则各自漂移。分镜数与时长上限也改由 `packages/core` 的生产边界常量同时供给计划 Schema 和蓝图，因此蓝图描述的视频一定能被计划表达；建议时长合计必须落在 15 到 60 秒，否则用户按清单拍完也用不上。没有证据单元时直接按 `TASK_ARTIFACT_MISSING` 失败，不白花一次模型调用。`karaoke_glow` 在这一层必然降级：蓝图阶段还没有任何录音，逐字时间无从谈起，降级来源记在 `degradedFromTemplateId`。
