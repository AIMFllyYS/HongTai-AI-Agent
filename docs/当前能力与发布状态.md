# 当前能力与发布状态

> 最后校对：2026-08-15。本文是能力和发布成熟度的当前来源；日期验收文档仅保存当时证据。

## 一句话结论

完整功能源码已经统一进入仓库根目录。AI 采用“一次视觉生成、最多一次纯文本格式修复、五个已校验展示板块、运行期真实深度思考”；舌象与面部观察共用分层 Prompt 和独立 Markdown 知识库。清晰图片应形成 3–6 条可见观察，轻微瑕疵图片继续分析可辨部分，五脏六腑、湿气、胃寒和心火等内容只作为有组合依据且不确定的传统观察参考。APK 启动图标已切换为独立的宏泰AI机器人图，底部导航可以离线打开富迪素材宣传图，页面内原有 SVG 不变。视频制作规划会同时接收爆款原文与正式拆解，并以“仅供参考、不得作为新口播”的前缀约束原创输出；新计划支持顶部主文字预设和底部逐镜头字幕，Android Media3 只执行通过校验的计划。项目只使用根项目目录和 Release APK 交付路径，版本唯一来源是 `android/app/build.gradle.kts`；构建成功后按版本号分别归档，不覆盖旧 APK。当前签名候选为 `v0.1.12`/`versionCode=20`，已完成主机构建、API 35 模拟器普通覆盖升级、冷启动和页面端测；仓库下载页当前推荐 v0.1.11/code19，但本阶段未重新执行公网文件回验。没有真实 Provider、物理设备完整端测、公开上传和公网哈希回验前，v0.1.12 只能称为 Release 候选，不能称为正式发布。

## 运行时能力矩阵

以下能力来自 `packages/capacitor-runtime/src/standalone-app-runtime.ts` 的 `FeatureCapabilityRegistry`。`available` 表示运行时已接入，不等同于所有设备、所有网络或正式分发均已验收。

| 能力 | 状态 | 用户可做的事 | 重要边界 |
| --- | --- | --- | --- |
| 本地档案 | available | 编辑显示名、门店信息与私有头像 | 无登录、无云同步 |
| AI 设置 | available | 选择小米 MiMo/阶跃星辰并只填写 API Key，或使用高级 OpenAI 兼容配置；分别探测文本、视觉、ASR、视频配音 | Key 只进入 Android Keystore；页面不读取原始响应或音频 |
| URL 采集 | available | 处理公开单条作品并显示七阶段真实事件；终态任务可明确删除 | 不处理 Cookie、登录、批量采集或绕过风控；运行中任务不可删除 |
| 内容拆解 | available | 基于真实转写或图文证据运行 `content-analysis.v1`；带清晰口播的本地 MP4 复用同一七阶段、语音识别与正式拆解 | 公网任务仍由用户确认后拆解；本地视频选择后自动拆解。没有可用口播时明确提示更换视频，不再继续进入文字拆解；当前不分析静音视频画面，也不伪造证据 |
| 图片观察 | available | 选择舌象或面部单张图片、生成观察报告并追问；清晰图片可形成 3–6 条可见观察，轻微受限图片仍分析可辨部分，并可查看 0–3 条基于独立知识库的传统观察参考 | 先描述可见证据，再按组合条件给不确定参考；不是疾病诊断、器官功能判断或处方，没有组合依据时不强迫生成传统方向 |
| AI 运行反馈 | available | 在内容拆解、面部观察、舌象观察期间展开查看实时“深度思考”，并依次看到五个固定展示板块；诊察思考被要求聚焦图片证据、知识组合与拍摄干扰 | 深度思考只存在于当前运行内存，不保存、不写日志、不进入追问；页面不读取供应商响应对象、不展示半截 JSON，正式报告仍以完整 Schema 校验和原子保存为准 |
| 本地视频制作 | available | 基于成功拆解导入图片/视频素材；制作时可填写顶部主文字或交由 AI 生成，并选择经典顶部白字、白色卡片或青绿强调三种预设；“素材剪辑 + TTS”使用 AI 连接中的云端旁白和底部字幕，旧连接未配云端 TTS 才回退系统语音；“数字人口播”导入带原声 MP4 并按用户口播稿生成字幕；可删除素材、成片或整个项目 | 爆款原文与拆解只在规划请求内作为受限参考，不持久化原文；较长连续重复会触发一次修复。后台返回可终止遗留 `planning/rendering`，但不后台续跑；删除素材会使旧计划与成片失效，规划或渲染期间拒绝删除；云端 TTS、编码器和 OEM 媒体实现仍需真机覆盖 |
| 模板管理 | available | 从成功拆解复制结构，或新建、编辑、删除本地模板 | 模板不复制原视频、供应商响应或 reasoning；不做云模板市场 |
| 发布 | planned | 显示明确的未接入状态 | 不唤起平台、不伪造发布成功 |

AI 运行反馈是两条简单 AI Flow，不是 Agent、工具调用循环或动态编排器。诊察与内容拆解在正常路径各发出一次结构化流式请求；同一响应中的五个顶层字段或字段组完整闭合后，先通过对应 Zod 与业务语义校验，再发送 `structured-generation-progress.v1` 安全投影。完整文档无效时最多进行一次格式修复，诊察修复为纯文本且不再次发送私有图片。板块进度和推理文本都不持久化；WebView 或进程退出后不恢复半成品，用户重试会重新生成完整文档，只有完整 `diagnosis-report.v1` / `content-analysis.v1` 校验并原子保存后才成立。

任务列表、任务详情、内容拆解与观察报告在健康状态下通过按 ID 或窄变更事件自动更新。权威记录先落盘再通知页面；初始异步列表读取会回放读取期间到达的 upsert、delete 或报告终态，并拒绝更早请求的迟到结果，因此不需要固定轮询或手动刷新。只有读取或订阅失败时保留“重新读取”恢复动作。

## 最小验证基线

每次变更按影响范围选择验证，详情见[任务执行模板](任务执行模板.md)：

- TypeScript：`pnpm check` 与定向测试；
- Web：`pnpm --filter @hongtai/web build`，视觉改动补桌面与约 390px 截图；
- Android：相关 Gradle 单测、lint、构建；外部媒体、网络和 Media3 改动补真机证据；
- Release：签名、递增版本号、APK SHA-256 和不带降级参数的升级测试。

不要把“构建成功”“模拟器通过”或“某一个 AI 探测成功”表述为正式 release、物理真机或全部模型能力均已验证。
