# 错误码与前端通知约定

## 1. 通信契约

任务结果、任务记录和失败进度事件统一使用：

```ts
interface TaskIssue {
  code: ErrorCode;
  severity: "warning" | "error";
  stage: TaskStage;
  userMessage: string;
  retryable: boolean;
  action: IssueAction;
  platform?: SupportedPlatform;
  details?: Record<string, string | number | boolean>;
}
```

`code`、`severity`和`action`是稳定业务字段。`userMessage`是默认中文兜底文案，前端不得通过字符串判断错误类型。

## 2. 错误码分类

| 分类 | 错误码 |
| --- | --- |
| 输入 | `INPUT_EMPTY`、`INPUT_NO_SUPPORTED_URL`、`INPUT_URL_INVALID`、`INPUT_PLATFORM_UNSUPPORTED` |
| 链接 | `LINK_NETWORK_FAILED`、`LINK_TIMEOUT`、`LINK_REDIRECT_LIMIT`、`LINK_REDIRECT_INVALID`、`LINK_HTTP_ERROR`、`LINK_EXPIRED` |
| 内容 | `CONTENT_NOT_FOUND`、`CONTENT_REMOVED`、`CONTENT_PRIVATE_OR_LOGIN_REQUIRED`、`CONTENT_PARSE_FAILED`、`CONTENT_SCHEMA_CHANGED`、`CONTENT_TYPE_UNSUPPORTED` |
| 平台API | `PLATFORM_API_RATE_LIMITED`、`PLATFORM_API_UNAVAILABLE`、`PLATFORM_API_RESPONSE_INVALID`、`PLATFORM_RISK_CONTROLLED` |
| 媒体 | `MEDIA_SOURCE_NOT_FOUND`、`MEDIA_DOWNLOAD_FAILED`、`MEDIA_DOWNLOAD_TIMEOUT`、`MEDIA_DURATION_EXCEEDED`、`MEDIA_PROBE_FAILED`、`MEDIA_MERGE_FAILED` |
| AI | `AI_NOT_CONFIGURED`、`AI_AUTH_INVALID`、`AI_PERMISSION_DENIED`、`AI_QUOTA_EXHAUSTED`、`AI_RATE_LIMITED`、`AI_NETWORK_FAILED`、`AI_TIMEOUT`、`AI_SERVER_ERROR`、`AI_EMPTY_RESPONSE`、`AI_STRUCTURED_OUTPUT_INVALID`、`AI_FORMAT_REPAIR_FAILED`、`AI_VISION_UNAVAILABLE`、`AI_CONTEXT_SUMMARY_FAILED`、`AI_SESSION_NOT_FOUND`、`ASR_PARTIAL_FAILURE`、`TEXT_REWRITE_FAILED` |
| 图片 | `IMAGE_INVALID`、`IMAGE_TOO_LARGE` |
| 任务产物 | `TASK_ARTIFACT_MISSING` |
| 存储 | `STORAGE_WRITE_FAILED`、`STORAGE_SPACE_INSUFFICIENT`、`STORAGE_PERMISSION_DENIED` |
| 内部 | `INTERNAL_UNKNOWN_ERROR` |

## 3. 建议动作

| action | 前端行为 |
| --- | --- |
| `edit_input` | 返回输入区并允许重新粘贴 |
| `retry` | 显示重新执行按钮 |
| `wait_and_retry` | 提示稍后重试，避免立即连续请求 |
| `check_network` | 提示检查网络并保留当前任务 |
| `configure_ai` | 跳转AI配置页 |
| `free_storage` | 引导释放空间或重新授权存储 |
| `view_partial_result` | 打开已经保存的视频、图片或文稿 |
| `none` | 只显示信息，不提供专用按钮 |

## 4. 状态与通知

- `severity=error`：阻断当前链路，显示错误弹窗；
- `severity=warning`：已有部分产物，显示非阻断提示；
- 多链接被忽略只是输入检查信息，不生成warning，也不改变任务状态；
- 实验性平台提示是入口能力说明，不生成warning，也不改变任务状态；
- 同一任务可以同时包含具体原因和汇总问题，例如`AI_QUOTA_EXHAUSTED`与`ASR_PARTIAL_FAILURE`；
- React页面统一通过一个错误展示层映射按钮，不在各页面重复维护错误判断。

### 无口播不是错误

`speechStatus=no_speech`表示ASR成功完成但没有检测到有效口播。它不生成`TaskIssue`，不使任务降级，前端应显示普通结果说明。只有响应缺少预期字段时才返回`AI_EMPTY_RESPONSE`；存在失败分段且没有文字时返回`speechStatus=failed`，不能误判为无口播。

## 5. 重试和安全

- 网络错误、HTTP 429和5xx最多尝试3次，间隔为0秒、1秒、3秒；
- 401、403、内容删除、私密内容、输入错误和结构变化不自动重试；
- 验证码或平台风控返回`PLATFORM_RISK_CONTROLLED`，本次GraphQL结果不自动重试，提示用户稍后再试；
- 429明确表示余额或额度不足时返回`AI_QUOTA_EXHAUSTED`，不自动重试；
- 日志只保留经过清理的状态码、阶段、平台和错误类型；
- 禁止记录API Key、Authorization、Cookie、Token、签名参数、完整查询参数和base64图片或音频；
- 供应商独立reasoning只作为开发调试产物显示和保存，不属于正式业务结果，也不得进入后续对话上下文。
