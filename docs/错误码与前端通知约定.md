# 错误码与应用界面通知约定

> 本文中的“界面”指应用界面层（Presentation / UI），不是传统 Web 前端；问题来源于本地应用逻辑层与平台运行时。
>
> 本文是[架构与工程规范](架构与工程规范.md)的配套稳定契约。页面只能读取代码和动作，不能通过中文文案、HTTP 文本或原生异常文本判断业务状态。

## 1. 统一问题契约

任务、设置、存储、媒体导入和 AI Flow 都通过同一个可展示的问题结构向 UI 暴露。对 URL 采集任务，`stage` 必须是七个 `TaskStage` 之一；对档案、加密存储或设置等非任务问题，`stage` 可以省略。

```ts
interface TaskIssue {
  code: ErrorCode;
  severity: "warning" | "error";
  stage?: TaskStage;
  userMessage: string;
  retryable: boolean;
  action: IssueAction;
  platform?: SupportedPlatform;
  details?: Record<string, string | number | boolean>;
  diagnostic?: NativeLinkDiagnosticV1;
}
```

`code`、`severity`、`retryable` 和 `action` 是稳定业务字段；`userMessage` 仅为默认中文兜底。`details` 只能包含脱敏的诊断信息，禁止放入 API Key、Authorization、Cookie、Token、签名 URL、完整查询参数、原始供应商错误正文或 base64 媒体。

`interrupted` 是 URL 采集可见的非成功终态，不能仅依靠一条错误弹窗替代状态记录。其他领域沿用其既有 `failed` 终态并附加 `TASK_INTERRUPTED`。应用只恢复“状态可解释性”，不自动续跑、自动重放或自动新建任务。

### 原生链接诊断 `native-link-diagnostic.v1`

Android 页面抓取失败可以附带一个版本化安全诊断，但它不是业务状态权威来源。页面仍只按 `TaskIssue.code/action` 决定按钮，诊断仅用于展示“失败发生在哪里”。

| 字段 | v1 允许值与边界 |
| --- | --- |
| `schemaVersion` | 固定为 `native-link-diagnostic.v1` |
| `operation` | 固定为 `fetch-text` |
| `phase` | `request`、`connect`、`redirect`、`response`、`decode` |
| `hostname` | 可选，仅规范化 DNS 主机名；IP、URL、query、fragment 和 user-info 均不得进入 |
| `errorClass` | `dns`、`tls`、`connection`、`timeout`、`redirect_limit`、`redirect_invalid`、`response_too_large`、`response_invalid_encoding`、`response_io`、`invalid_request` |
| `elapsedMs` | `0..600000` 的整数 |
| `networkType` | 可选，仅 `wifi`、`cellular`、`ethernet`、`vpn`、`offline`、`other`、`unknown`；不得附带 SSID、IP 或运营商信息 |
| `attempt` | `1..3` 的整数 |
| `redirectCount` | `0..5` 的整数 |

业务层当前不读取 Android 网络状态，也不采集 `networkType`；该可选字段只保留版本化白名单，不构成业务层主动申请权限的理由。最终合并 Manifest 会由 Media3 依赖带入普通安装时权限 `ACCESS_NETWORK_STATE` 和 `WAKE_LOCK`，用于播放器网络/唤醒能力；它们不是运行时危险权限，也不授权相机、相册、网络标识或用户媒体访问。DTO 严禁出现完整 URL、query、Cookie、Authorization、请求体、响应正文、Throwable message/stack、SSID、IP、运营商信息或用户媒体。Capacitor Runtime 必须从拒绝对象的 `data` 中重建上述白名单对象，不能把原生对象整体透传或持久化；UI 格式化时再次按固定枚举读取，不能插值未知字段。

原生技术码到业务码的映射如下。技术码只放在安全的 `details.nativeCode`，业务动作仍由 `TaskIssue` 决定：

| 原生技术码 | 业务码 | `retryable` | `action` |
| --- | --- | --- | --- |
| `ERR_LINK_DNS_FAILED`、`ERR_LINK_TLS_FAILED`、`ERR_LINK_CONNECTION_FAILED`、`ERR_LINK_RESPONSE_FAILED` | `LINK_NETWORK_FAILED` | `true` | `check_network` |
| `ERR_LINK_TIMEOUT` | `LINK_TIMEOUT` | `true` | `check_network` |
| `ERR_LINK_REDIRECT_LIMIT` | `LINK_REDIRECT_LIMIT` | `false` | `edit_input` |
| `ERR_LINK_REDIRECT_INVALID` | `LINK_REDIRECT_INVALID` | `false` | `edit_input` |
| `ERR_LINK_RESPONSE_TOO_LARGE`、`ERR_LINK_RESPONSE_INVALID` | `LINK_HTTP_ERROR` | `false` | `retry` |
| `ERR_LINK_REQUEST_INVALID` | `LINK_HTTP_ERROR` | `false` | `edit_input` |

`CONTENT_SCHEMA_CHANGED`、`MEDIA_SOURCE_NOT_FOUND`、`CONTENT_PRIVATE_OR_LOGIN_REQUIRED`、`PLATFORM_RISK_CONTROLLED` 等既有平台业务语义不得被上述网络映射覆盖。

### 原生照片选择与恢复

照片选择、相机返回和私有化导入是短生命周期的 Android I/O。原生层只在取得系统授予的持久读取权限后记录可恢复的 picker URI；导入成功或失败进入终态后释放该授权，若写入 importing 状态失败也必须立即释放。若外部 Activity 的结果丢失，拍照 staging 文件必须在写入恢复失败终态前清理。页面只消费下表中的业务码与 `select_media` 动作，不读取原生 URI、异常文本或私有路径。

当前拍照由外部相机应用执行，应用只通过 `FileProvider` 临时授予一个输出 URI；选图由 Photo Picker 或 `ACTION_OPEN_DOCUMENT` 授予一个用户选定 URI。因此本应用不声明 `CAMERA`、`READ_MEDIA_IMAGES`、`READ_EXTERNAL_STORAGE` 或 `MANAGE_EXTERNAL_STORAGE`，也不应为了让系统设置页出现“权限”入口而增加它们。未来若使用应用内 CameraX，必须另行声明并运行时请求 `CAMERA`，且把拒绝结果映射为稳定业务问题。

| 原生技术码 | 业务码 | `retryable` | `action` |
| --- | --- | --- | --- |
| `ERR_MEDIA_SELECTION_CANCELLED` | `MEDIA_SELECTION_CANCELLED` | `false` | `select_media` |
| `ERR_MEDIA_SOURCE_MISSING` | `MEDIA_SOURCE_NOT_FOUND` | `false` | `select_media` |
| `ERR_PHOTO_CAPTURE_LOST`、`ERR_PHOTO_RECOVERY_FAILED` | `TASK_INTERRUPTED` | `false` | `select_media` |
| `ERR_VIDEO_RECOVERY_FAILED`、`ERR_ASSET_RECOVERY_FAILED` | `TASK_INTERRUPTED` | `false` | `select_media` |
| `ERR_MEDIA_READ_FAILED` | `MEDIA_READ_FAILED` | `false` | `select_media` |
| `ERR_IMAGE_TOO_LARGE` | `IMAGE_TOO_LARGE` | `false` | `select_media` |
| `ERR_IMAGE_INVALID` | `IMAGE_INVALID` | `false` | `select_media` |
| `ERR_PRIVATE_FILE_IMPORT_FAILED` | `MEDIA_IMPORT_FAILED` | `false` | `select_media` |

## 2. 稳定错误码分类

| 分类 | 错误码 |
| --- | --- |
| 输入 | `INPUT_EMPTY`、`INPUT_TOO_LONG`、`INPUT_NO_SUPPORTED_URL`、`INPUT_URL_INVALID`、`INPUT_PLATFORM_UNSUPPORTED` |
| 链接 | `LINK_NETWORK_FAILED`、`LINK_TIMEOUT`、`LINK_REDIRECT_LIMIT`、`LINK_REDIRECT_INVALID`、`LINK_HTTP_ERROR`、`LINK_EXPIRED` |
| 内容 | `CONTENT_NOT_FOUND`、`CONTENT_REMOVED`、`CONTENT_PRIVATE_OR_LOGIN_REQUIRED`、`CONTENT_PARSE_FAILED`、`CONTENT_SCHEMA_CHANGED`、`CONTENT_TYPE_UNSUPPORTED` |
| 平台 API | `PLATFORM_API_RATE_LIMITED`、`PLATFORM_API_UNAVAILABLE`、`PLATFORM_API_RESPONSE_INVALID`、`PLATFORM_RISK_CONTROLLED` |
| 媒体与导入 | `MEDIA_SOURCE_NOT_FOUND`、`MEDIA_SOURCE_INVALID`、`MEDIA_SELECTION_CANCELLED`、`MEDIA_DOWNLOAD_FAILED`、`MEDIA_DOWNLOAD_TIMEOUT`、`MEDIA_DURATION_EXCEEDED`、`MEDIA_PROBE_FAILED`、`MEDIA_MERGE_FAILED`、`MEDIA_IMPORT_FAILED`、`MEDIA_READ_FAILED` |
| 视频制作与导出 | `MEDIA_RENDER_TIMEOUT`、`MEDIA_EXPORT_FAILED`、`OUTPUT_FINALIZATION_FAILED` |
| 旁白合成 | `TTS_UNAVAILABLE`、`TTS_SYNTHESIS_FAILED` |
| AI 连接与调用 | `AI_NOT_CONFIGURED`、`AI_SETTINGS_INVALID`、`AI_SECRET_STORE_FAILED`、`AI_CAPABILITY_PROBE_FAILED`、`AI_AUTH_INVALID`、`AI_PERMISSION_DENIED`、`AI_QUOTA_EXHAUSTED`、`AI_RATE_LIMITED`、`AI_NETWORK_FAILED`、`AI_TIMEOUT`、`AI_SERVER_ERROR`、`AI_EMPTY_RESPONSE`、`AI_STRUCTURED_OUTPUT_INVALID`、`AI_FORMAT_REPAIR_FAILED`、`AI_VISION_UNAVAILABLE`、`AI_CONTEXT_SUMMARY_FAILED`、`AI_SESSION_NOT_FOUND`、`ASR_PARTIAL_FAILURE`、`TEXT_REWRITE_FAILED` |
| 图片观察 | `IMAGE_INVALID`、`IMAGE_TOO_LARGE`、`IMAGE_QUALITY_INSUFFICIENT`、`DIAGNOSIS_REPORT_INVALID`、`DIAGNOSIS_FOLLOW_UP_FAILED` |
| 本地档案与任务 | `PROFILE_SAVE_FAILED`、`TASK_ARTIFACT_MISSING`、`TASK_INTERRUPTED`、`TASK_CANCEL_FAILED` |
| 本地存储 | `STORAGE_WRITE_FAILED`、`STORAGE_SPACE_INSUFFICIENT`、`STORAGE_PERMISSION_DENIED` |
| 内部 | `APP_RUNTIME_UNAVAILABLE`、`INTERNAL_UNKNOWN_ERROR` |
| 预留未启用 | `DATABASE_MIGRATION_FAILED`、`DATABASE_KEY_UNAVAILABLE`、`DATABASE_OPEN_FAILED` |

本表与 `packages/core/src/models.ts` 的 `ErrorCode` 联合类型一一对应。新增代码必须在实现前写入本表，说明其 `retryable` 语义和展示 `action`；不得将供应商或 Android 原始错误码直接暴露为业务代码。

### 新增分类的语义

| 错误码 | 触发时机 | `retryable` | `action` |
| --- | --- | --- | --- |
| `MEDIA_SOURCE_INVALID` | 制作素材或媒体源不符合可执行条件（编码、时长、方向等） | `false` | `select_media` |
| `MEDIA_RENDER_TIMEOUT` | Media3 渲染超过本次允许时长后被取消 | `true` | `retry` |
| `MEDIA_EXPORT_FAILED` | Media3 导出阶段失败 | `true` | `retry` |
| `OUTPUT_FINALIZATION_FAILED` | 成片写入临时文件成功但最终替换失败 | `true` | `retry` |
| `TTS_UNAVAILABLE` | 系统或云端旁白合成能力不可用 | `false` | `configure_ai` |
| `TTS_SYNTHESIS_FAILED` | 旁白合成过程失败 | `true` | `retry` |
| `TASK_CANCEL_FAILED` | 用户请求取消，但首版不提供安全的中止路径 | `false` | `none` |

`DATABASE_*` 三个代码保留在类型中但当前不会被抛出：首版不引入任务数据库。页面不得展示这三个代码，也不得为它们编写文案分支。

## 3. 建议动作与唯一展示层

| action | 应用界面层行为 |
| --- | --- |
| `edit_input` | 聚焦分享文案输入区，保留用户尚未提交的输入 |
| `retry` | 仅重新发起当前安全操作；URL 任务需由用户明确新建，旧任务不覆盖 |
| `wait_and_retry` | 提示稍后操作，避免连续请求 |
| `check_network` | 提示检查网络，并保留当前任务/会话 |
| `configure_ai` | 导航到 AI 设置页；不在弹窗中索取或回显完整 Key |
| `free_storage` | 引导用户释放空间或重新授权；不自动清理数据 |
| `select_media` | 打开系统媒体/文件选择流程，重新导入到应用私有目录 |
| `view_partial_result` | 打开已经安全保存的任务详情、媒体、图片或文稿 |
| `none` | 只显示信息，不提供专用按钮 |

应用只保留一个问题展示层负责把 `TaskIssue.code/action` 映射为用户可见的提示与后续动作。页面、Kotlin 插件和平台适配器都不得各自维护同一套中文分支。

当前实现是 `apps/web/src/components/IssueNotice.tsx`：它按 `action` 分支、按 `code` 取标题，统一转成顶部通知后返回 `null`。尚未实现的部分：内联提示形态、`edit_input` 自动聚焦分享输入区、`view_partial_result` 的 `partialResult` 传入（目前没有页面传这个参数）。这三项属于已声明未兑现的契约，补齐工作登记为 [Issue #56](https://github.com/AIMFllyYS/HongTai-AI-Agent/issues/56)；补齐前不要在别处另写分支绕开该组件。

## 4. 状态、通知与空态

- `severity=error`：当前操作不可继续；展示阻断弹窗或明确错误页，但保留已落盘的部分结果。
- `severity=warning`：任务可继续或已有部分产物；展示非阻断提示和可用结果。
- `queued`、`running`、`succeeded`、`degraded`、`failed`、`interrupted` 是首版任务状态，不通过 `severity` 推导。
- 内容拆解只使用独立 `analysisStatus`（`not_started`、`running`、`succeeded`、`failed`），不得伪装为 URL 采集第八阶段。
- 多链接被忽略只是输入检查信息，不生成 warning；实验性平台提示也是入口能力说明，不改变任务状态。
- 未实际获得的互动量、字幕、文稿、分析结论或媒体必须显示空态，不能以模拟数据降级为“成功”。

### 无口播不是错误

`speechStatus=no_speech` 表示 ASR 成功完成但没有检测到有效口播。它不生成 `TaskIssue`，不使任务降级，UI 应显示普通结果说明。存在失败分段且没有文字时为 `speechStatus=failed`，不得误判为无口播。

### 平台描述可以作为明示来源的降级文稿

ASR 失败或未配置 AI 时，允许把平台简介/描述写入 `transcript.txt` 作为降级文稿，但必须同时满足三条，缺一条即为伪造：

1. `transcript.json` 的 `source` 必须记为 `description`，不得记为 `asr`，也不得省略。
2. 必须附带一条 warning 级 `TaskIssue`（当前是 `AI_EMPTY_RESPONSE`，`action=view_partial_result`），使降级对用户可见。
3. 展示这份文稿的界面必须标注它来自平台描述，不得呈现为语音逐字稿。

被禁止的是「冒充」：不标注来源、把描述记为 `source: "asr"`、或在 UI 上让用户以为读到的是真实语音转写。当前实现见 `packages/core/src/pipeline.ts` 的 `obtain-transcript` 阶段。

### 中断不是可自动恢复

首版不承诺后台续跑。冷启动会检查全部持久化状态；一次真实的 inactive→active 返回若发现仍依赖原 WebView 的执行，会先受控重载，再执行同一检查。系统相机/Photo Picker 等外部 Activity 返回只派发页面刷新事件，不销毁仍有效的原生回调。

| 状态所有者 | 遗留未终态 | 恢复终态与动作 |
| --- | --- | --- |
| URL 采集任务 | `running` | `interrupted` + `TASK_INTERRUPTED(action=edit_input)` |
| 内容拆解 | `running` 或父任务 `analysisStatus=running` | 拆解与父任务均为 `failed` + `TASK_INTERRUPTED(action=retry)` |
| 图片观察报告 | `running` | `failed` + `TASK_INTERRUPTED(action=retry)` |
| 视频制作项目 | `planning` / `rendering` | `failed` + `TASK_INTERRUPTED(action=retry)` |

恢复必须幂等并保留已落盘媒体、正文、文稿、正式分析、观察图片、制作素材或计划。应用不自动重跑、不自动新建任务、不删除旧产物；用户从对应入口明确发起新的安全操作。

## 5. 重试、存储与安全

- 网络错误、HTTP 429 和 5xx 最多尝试 3 次，间隔为 0 秒、1 秒、3 秒；其中平台风控、内容删除、私密内容、输入错误和结构变化不自动重试。
- 429 明确表示 AI 余额或额度不足时使用 `AI_QUOTA_EXHAUSTED`，不自动重试；验证码或平台风控使用 `PLATFORM_RISK_CONTROLLED`，不自动重试。
- 私有文件写入失败不能触发“清空并重建”。保留已有产物、停止本次写入并提示用户处理。
- 导入失败不能把临时 `content://` URI 当作已保存素材；成功导入后才向 UI 返回应用私有目录的安全展示 URI。
- 日志只保留脱敏状态、阶段、平台、稳定代码和必要计数。供应商独立 reasoning 仅可进入私有调试材料，不属于正式结果，也不得进入后续对话上下文或 UI。

## 6. AI 与观察功能的边界

- 文本、视觉、ASR 的真实调用彼此独立；一个成功不表示其余能力可用。首版只在用户实际使用或明确点击测试时验证。
- `AI_NOT_CONFIGURED` / `AI_SETTINGS_INVALID` / `AI_SECRET_STORE_FAILED` 的默认动作是 `configure_ai`。
- 图片不符合质量条件时使用 `IMAGE_QUALITY_INSUFFICIENT`，页面引导重新选择或拍摄，而非生成医学结论。
- 图片观察报告及追问仅提供日常健康参考；不得通过错误或成功文案声称医疗诊断、疾病概率、处方或综合健康评分。
