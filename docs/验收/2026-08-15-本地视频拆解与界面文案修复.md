# 本地视频拆解与界面文案修复验收

## 目标

- 用户上传一段带清晰口播的本地 MP4 后，系统完成语音识别并进入内容拆解。
- 语音识别失败时，页面保留真正可操作的原因，不再被“部分语音未识别”这一汇总提示覆盖。
- 视频没有可用口播时停止后续文字拆解，并直接提示用户更换人声清晰的视频。
- 首页、任务页、报告页、应用启动页与顶部通知使用普通用户能理解的产品语言，不展示内部错误码、Schema 名称、私有目录或运行时术语。

## 允许修改

- `packages/capacitor-runtime` 中本地视频导入到内容拆解的组合逻辑及定向测试。
- `apps/web` 中错误通知、拆解进度和高频页面文案。
- 与上述行为直接对应的 Web 测试和当前能力说明。

## 明确不做

- 不改变共享七阶段 Pipeline、AI Prompt、Schema、平台解析或 Android I/O。
- 不新增云端后端、模型供应商、权限或存储方案。
- 不把本地视频能力描述为画面理解：当前能力依赖视频中的真实口播文字，静音或只有画面的素材不能拆解。
- 不构建或发布 APK，不调整 Android 版本号和公开下载页。

## 架构归属

- `capacitor-runtime` 继续只组合既有本地媒体导入、共享采集 Flow 和内容拆解 Flow。
- Web 页面只消费 `AppRuntime` 的版本化 DTO；内部 `TaskIssue.code` 继续作为稳定分支依据，但不直接展示给普通用户。
- 没有在 Kotlin、页面或 Capacitor 层复制 Pipeline、Prompt、Schema 或业务状态机。

## 权威状态与数据

- `taskId` 仍是本地视频采集与后续拆解的唯一关联标识。
- 采集任务终态和 `issues` 由共享 Pipeline 持久化；内容拆解只有在存在真实文字证据后启动。
- 多个分段失败时，从末尾回查真正可操作的语音识别错误；跳过只用于汇总的 `ASR_PARTIAL_FAILURE`。
- `speechStatus=no_speech` 时不创建文字拆解结果，返回“没有听清口播内容”的可恢复提示。

## 根因

1. 本地视频采集会先记录各分段的真实语音识别错误，最后再追加 `ASR_PARTIAL_FAILURE` 汇总项。组合服务过去固定取 `issues` 的最后一项，导致 API Key、模型权限、网络或限流等真正原因被覆盖，页面只能反复显示泛化错误。
2. 共享采集允许“视频成功保存但没有口播”的任务以成功终态结束；组合服务过去仍继续调用依赖文字证据的内容拆解，随后以“缺少任务产物”失败，用户无法知道应更换视频。
3. 页面把错误码、ASR、Schema、私有目录、运行时和状态机术语当成正文，通知也同时显示内部代码，信息虽然便于工程排查，却没有回答用户“发生了什么、该怎么做”。

## 验收

- 定向测试：本地视频组合服务、错误通知、拆解进度及受影响页面共 50 项通过。
- Web 构建：`pnpm --filter @hongtai/web build` 通过；仅有既有的大包体积提示。
- 全量检查：类型检查和 ESLint 通过；全量测试除仓库既有的“源码候选 0.1.7 与公开下载页 0.1.5 不一致”版本血缘检查外，其余执行到的测试通过。该发布状态不在本任务内修改。
- 视觉检查：用真实首页与顶部通知组件在 1440×1000 和 390×844 视口检查；上传说明、按钮和通知均可读，无横向溢出。截图保存在 `output/playwright/`。
- 编码检查：改动保持 UTF-8，不含 U+FFFD。

## 用户实际会看到什么

- 上传区明确写明“带有清晰人声的 MP4”，并说明视频只保存在本机。
- 失败通知显示产品化标题、可理解原因和下一步按钮，例如“视频内容没有识别成功 / 检查 AI 设置”，不再显示 `AI_AUTH_INVALID` 等内部代码。
- 无口播视频直接提示更换人声清晰的视频，不再先显示上传成功、随后又以缺少产物报错。

## 剩余边界

- 当前主机没有连接 Android 设备，也没有在本次任务中使用用户真实 API Key，因此尚未获得“真实手机 + 真实供应商 + 私有 WAV”端到端成功证据。
- 当前实现是“视频音轨转写后拆解”，不是对画面、镜头或静音视频的视觉理解。若产品目标包含画面拆解，应作为独立能力设计并补充相应证据模型。
