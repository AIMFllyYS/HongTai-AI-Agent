# 任务执行模板

> 每个实现、修复、重构或发布任务在开始前填写本模板。审查和纯分析任务保留只读范围即可。

所有命令都在仓库根目录执行，不创建 worktree。APK 验证和交付只使用 Release。

## 任务契约

```md
## 目标
- 用户可感知的结果：

## 允许修改
- 目录 / 模块 / 文件：

## 明确不做
- 不修改的能力、依赖、数据或外部系统：

## 架构归属
- 所属层：UI / core / ai / platforms / capacitor-runtime / Android I/O
- 依赖方向与禁止跨越的边界：

## 权威状态与数据
- 关键 ID：taskId / sessionId / projectId / 其他
- 并发、失败、重试、进程中断后必须保持的事实：

## 验收
- 定向测试：
- 构建 / lint：
- 浏览器或真机证据：
- 用户实际会看到什么：

## 交付说明
- 改了什么：
- 刻意没有做什么：
- 剩余风险或新增 Issue：
```

## 文件拆分与复用检查

在新增文件、组件或 helper 前回答：

1. 现有组件、DTO、Schema、错误码、存储 helper 或 Flow 是否已经覆盖需求？
2. 新文件是否只有一个明确职责，能否独立测试？
3. 当前文件是否已混入三类以上无关职责，应该按责任拆分吗？
4. 抽象是否至少有两个真实调用点？若没有，是否应保持局部实现？
5. 是否只是为了缩短文件而创造无意义的 wrapper、barrel 或层级？若是，不拆。

默认在文件约 300 行且阅读/测试已经困难时评估拆分；这不是机械上限。优先按领域职责拆分，而不是按“组件、hooks、utils”随意切碎。

## 验证选择表

| 改动类型 | 最低验证 | 额外要求 |
| --- | --- | --- |
| 文档 | 内部链接、UTF-8、`git diff --check` | 历史记录不得被改写成当前事实 |
| core / ai / platforms | 定向测试、`pnpm check` | 不导入运行时/平台 API；保持 Schema 与 DTO 单一来源 |
| Capacitor Runtime | 定向测试、`pnpm check` | 不复制 Flow、Pipeline 或状态机；检查同一 ID 并发写入 |
| Web UI | 定向测试、`pnpm check`、Web build | 视觉改动检查桌面和约 390px；只消费 `AppRuntime` DTO |
| Android 原生 | 相关 Gradle 测试、lint、构建 | 相册/相机、网络、外部 Activity、Media3 改动要有真机证据或明确标记未验证 |
| 安全 / 依赖 | 受影响测试、依赖审计 | 不泄露敏感信息；说明攻击面与回归样例 |
| 发布 | 所有受影响验证 | 检查 release 签名、递增 versionCode、APK SHA-256 和正常升级路径 |

## Git 交付

1. 查看 `git status --short --branch`，识别并保留无关改动。
2. 只暂存本任务路径，禁止默认 `git add .`。
3. 执行 `git diff --cached --check` 和本任务验证。
4. 每个完成阶段创建本地 commit；除非用户明确授权，不推送。
