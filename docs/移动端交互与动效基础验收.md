# 移动端交互与动效基础验收

> 当前口径见 [动效规范](动效规范.md)。本文只证明 2026-08-05 当时做过基础动效验收，不是今天的 Sheet / 骨架 / 底栏点击规则。
>
> 分支：`feat/frontend-static-visual-system-migration`
>
> 验收日期：2026-08-05
>
> 预览地址：`http://127.0.0.1:4173/`

## 1. 本阶段实现

- 使用 `motion@12.43.0` 统一 React 页面进入/退出和一级导航按压反馈；
- 现有 `history.pushState` route 保持不变，页面切换增加 260ms 内的淡入和不超过 16px 的水平位移；
- AI、拆解、制作、素材、设置五个一级页面支持触摸/手写笔左右滑动切换；
- 按钮、图标按钮、交互卡片、Tabs 和底部导航使用共享 press token；
- 使用原生 Web Audio 播放极短、低音量点击音，使用 `navigator.vibrate` 提供短触觉；浏览器策略或 WebView 不支持时静默跳过；
- 页面纵向滚动保持浏览器原生行为，滚动条轨道隐藏；滚动离开顶部时只提升 header 背景和阴影；
- `prefers-reduced-motion: reduce` 下关闭位移、回弹、平滑滚动和音触反馈；
- 所有交互均停留在前端静态 route 和视觉边界，不触发真实 CLI、API、任务状态或数据刷新。

## 2. 浏览器证据

执行：


`mobile_motion_audit.py` 实测输出：

```text

scroll-state=scrolled; top-state=top
audio-support=1; vibration-support=1
reduced-motion-transform=none

```

静态 route audit：

- 11 个 route 全部渲染；
- 11 个 route 均为唯一 `h1`；
- 0 个 page error；
- 本地 Noto Sans SC、品牌 logo 和 fixture media 均可读取；
- AI `/vitality/scan` 与 `/vitality/result` 继续使用 `#FBFDFA`、`#26A69A`、`#004D40` 绿色主题；
- 首页滚动到底部后，最后内容与 fixed bottom nav 保持 32px 间距；
- `prefers-reduced-motion` 下页面过渡的 computed transform 为 `none`；
- 当前 Chromium 报告支持 Web Audio 和振动接口；这不等同于所有 Android 设备都实际发声或振动，真机需要后续单独验证。

## 4. 视觉与交互差异

已还原/新增：

- 页面之间不再瞬间硬切，进入和退出保持统一短过渡；
- bottom nav 点击有一致的 scale press，AI 仍使用医疗十字图标；
- 可点击历史卡片增加键盘 Enter/Space 与触摸按压反馈；
- 滚动时 header 有轻量抬升，不会隐藏标题或侵入内容；
- 横向 chip/template 等已有滚动区域仍能滚动，但不显示系统滚动条。

明确保留：

- 没有实现下拉刷新数据，因为当前 `VisualDataAdapter` 没有刷新契约；
- 没有为分析详情、制作发布等内部业务 route 猜测左右滑动语义，滑动只作用于五项一级导航；
- 没有引入在线音效、Google Fonts、图标 CDN 或新的业务状态；
- Motion 引入后构建 JS gzip 约 121KB，后续若 APK 包体或首屏预算收紧，再评估 `LazyMotion` 或 CSS-only 页面过渡，不在本阶段扩大架构。

## 6. 后续真机建议

1. 在目标 Android WebView 版本和真实设备上验证音量、AudioContext 首次解锁、振动权限和系统省电策略；
2. 由真实数据 adapter/API 定义刷新成功、失败和取消状态后，再单独设计下拉刷新；
3. 如果真机测得 Motion 包体影响首屏，再以截图和构建预算为证据评估按路由懒加载，不能为了体积直接删除页面过渡。
