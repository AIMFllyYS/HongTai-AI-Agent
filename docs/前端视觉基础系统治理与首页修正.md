## 1. 目标与边界

本阶段不是单独修正 AI 页面，而是先把 `apps/web` 的低层视觉能力整理为可复用、可替换、可验证的前端基础，再修正首页和 AI 主题。

允许修改：

- `apps/web` 的 CSS token、视觉组件、页面组合和静态展示 adapter；
- 前端边界测试、浏览器截图审计脚本和本迁移文档；
- 与视觉系统直接相关的 route 壳层 props 和 view model 展示字段。

禁止修改：

- `apps/cli`、`packages/core`、`packages/platforms`、`packages/ai`、`packages/node-runtime` 的业务逻辑；
- API、DTO、数据库、鉴权、价格、积分、配额、爬虫、agent 和任务状态机；
- 真实 CLI/API 接入、真实 URL 解析、真实任务订阅和真实健康诊疗规则；
- Stitch 远程设计资产的创建、修改、上传、应用或删除。

## 4. 业界实践落地规则

- Atlassian 的 foundations → components → patterns 对应本项目的 tokens → shared components → page composition。
- Adobe Spectrum 的 global → semantic alias → component-specific token 对应本项目的基础值 → 语义 token → 组件局部变量。
- Material 3 的 color roles 对应 `canvas`、`surface`、`text`、`action`、`focus`、`status` 等用途型 token，AI 主题不再直接覆盖棕色值。
- CSS 使用 `@layer reset, base, shell, components, pages, themes, responsive` 固定级联顺序。
- React 页面只接收 view model 和行为回调；静态 fixture 通过 adapter 提供，不把 mock 对象直接写在页面或共享组件中。
- Tabs 具备完整 `tablist`、`tab`、`tabpanel` 关联和键盘行为。
- 继续使用现有 Playwright/Chromium 审计，不为了引入“业界工具”而新增 Storybook、Tailwind 或 CSS-in-JS。
- 页面组合继续遵守“壳拥有页面标题、页面只组合内容”的规则；同一标题不在 header 和 content 中重复渲染。
- 资产行使用显式缩略图轨道和 `min-width: 0`，避免 `aspect-ratio` 的首选比例把媒体撑出网格轨道。
- 品牌 logo 作为共享视觉基础组件复用；页面语义明确的 `folder_special`、`movie_edit` 和返回箭头仍保留为局部 header action。

## 4.1 本轮资产重叠与品牌 logo 证据

用户截图对应 route：`/assets`，浏览器复现尺寸为 `536×900`。修复前真实 DOM 几何为：资产行第一列 `57.6px`，媒体因 `16 / 9 + min-height` 被撑到 `85.3px`，媒体右边界 `110.0px`，文本起点 `94.3px`，实际侵入 `15.7px`。根因是 CSS Grid 轨道宽度与媒体组件的自动比例/最小高度约束不一致，不是 fixture 数据重叠。

本轮按截图和布局规范将资产媒体轨道固定为 `8rem`，媒体设置 `width: 100%`、`min-width: 0`、`min-height: 0` 和 `16 / 9`；修复后同一尺寸下媒体为 `128×72px`，文本从媒体右侧 `12px` 后开始，浏览器审计确认所有资产行无重叠。

设计 logo 证据来自本地 Stitch HTML：`stitch_ai/_1/code.html`、`_6/code.html`、`_7/code.html`、`_9/code.html` 的 AI 导航项均引用同一张独立图片资源。用户随后提供的 `Pulse Flow` 本地品牌图是当前采用的权威素材；它已转为完整品牌图 `pulse-flow.svg`、透明页面标记 `pulse-flow-mark.svg` 和带框应用图标 `pulse-flow-icon.svg`，并由 `components/BrandLogo.tsx` 按语境统一供 AppShell 品牌 header、AI 导航和未来 APK 资源使用。素材下载只读取本地 HTML 中已有的远程图片 URL；当前会话未加载名为 `stitch` 的 MCP server，`list_mcp_resources(server="stitch")` 返回 unknown server，因此没有执行任何远程设计资产写操作，也不把远程项目状态当作已验证事实。

本轮还移除了素材库、制作、发布、个人中心中与 AppShell 重复的页面标题，把上传动作放回素材库 header slot，降低“header + 页面标题 + 内容卡”造成的拼接感；不改变 route、view model、adapter 或业务状态。

## 4.2 本轮字体、品牌资源与国内离线边界

本轮采用本地打包的 `Noto Sans SC` 可变字体，运行时文件为 `apps/web/public/fonts/NotoSansSC-VF.woff2`，授权文本随 `NotoSansSC-OFL.txt` 一起保存。它替代了原先只写在 CSS font stack 中、但没有实际加载的 Plus Jakarta Sans、Be Vietnam Pro 和 Inter；正文提升到 `1rem`，caption 提升到 `0.8125rem`，页面原有低于 `0.75rem` 的小字统一归入 `--text-meta`。Noto 官方资料将 `Noto Sans SC` 列为简体中文变体，并说明 Noto 字体可随原生应用打包，但仍需遵守 OFL 条款：

- https://notofonts.github.io/noto-docs/website/use/
- https://github.com/googlefonts/noto-cjk/blob/main/Sans/LICENSE

用户提供的 `C:\Users\AIMFl\Downloads\stitch_ai (2)\screen.png` 是 `Pulse Flow` 1024×1024 品牌图。本轮通过 VTracer 将它转为路径型 SVG，未使用 `<image>` 嵌套栅格图：

- `apps/web/public/brand/pulse-flow.svg`：完整字标资源；
- `apps/web/public/brand/pulse-flow-mark.svg`：透明背景的页面品牌标记，供 AppShell 和 AI 导航使用；
- `apps/web/public/brand/pulse-flow-icon.svg`：带圆角底板和阴影的应用图标，供未来 APK launcher icon 使用；
- `BrandLogo` 保持现有组件 API，默认使用 mark 变体；`icon` 变体只用于应用图标语境，避免把带框资源误放入页面 header/nav。

图标库审查结果：`apps/web/src/components/Icon.tsx` 已经是项目内联 SVG path registry，不在运行时加载 Google Material Symbols，因此不需要为了国内可用性再下载 Google 图标字体。静态媒体则原先直接引用 `lh3.googleusercontent.com`，其中两条 URL 已返回 400；本轮按本地 Stitch HTML 中的正确资源重新下载为 `apps/web/public/media/*.jpg`，fixture 只保留 `/media/...` 路径，后续 WebView/APK 可直接将它们作为静态包资源。
