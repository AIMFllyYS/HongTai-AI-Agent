# 全项目审查报告

> 审查日期：2026-08-16。审查基线：`main` 分支 HEAD `47b7b2d`，Android `versionName=0.1.12` / `versionCode=20`。
> 本文只报告可复现、可定位的问题，不包含修复实现。文档漂移类问题已在同批次修复，代码逻辑类问题只登记不改。

## 一、结论

项目的分层纪律整体是成立的：`core`、`ai`、`platforms` 三个共享包没有任何 Node、Capacitor 或 Android 的导入越界；APK 的依赖图里不存在 CLI、`node-runtime` 或 sharp；Android 清单只声明 `INTERNET`，没有相册、相机或存储权限，也没有放宽 TLS 校验或打印密钥的地方；页面的正式入口只走 `AppRuntime`，fixture 从来没有冒充过真实结果。这几条是这个项目最容易出事、而实际做得最扎实的部分。

问题集中在三类。第一类是**真实性与密钥边界的局部漏口**——采集管线把未脱敏的平台原始响应直接落盘，其中可能包含带签名参数的 CDN 地址。第二类是**跨层职责回流**——一段改写 Prompt 落在了 Capacitor 组合层，一批中文进度文案和 TTS Prompt 落在了 Kotlin，视频计划的业务规则在 Kotlin 里被重新实现了一遍。第三类是**生命周期终态缺口**——视频选择器和素材选择器在进程重建后会静默丢弃结果，采集管线跳过的阶段不发终态事件，页面因此会在一个已经结束的任务上长期显示"等待中"。

另有一个当时会让 `pnpm check` 失败的版本一致性问题，已在本次修复。

## 二、审查方法与覆盖范围

六个子智能体并行审查六个面，每个面都要求给出文件路径与行号，并明确区分"已核实"与"推测"。推测类结论已剔除。

## 三、严重度定义

- **阻断**：违反不可协商的硬规则（真实性、密钥、跨层导入），或导致统一检查失败。
- **重要**：违反明确写入 `AGENTS.md` 或架构文档的规则，或存在会导致用户可见错误状态的缺陷。
- **一般**：违反约定、存在竞态或资源风险，但当前触发路径窄或影响可控。
- **轻微**：死代码、命名不一致、无调用点的导出。

### 重要

#### M1　视频与素材选择器在进程重建后静默丢弃

`android/app/src/main/java/com/hongtai/aiagent/bridge/FileMediaPlugin.kt` 第 132–133 行 `onVideoPicked` 的处理是 `if (call == null) return`；`ProductionRuntimePlugin.kt` 第 56–57 行的 `onAssetsPicked` 同样。进程重建后 Capacitor 交回的是一个悬空调用，结果被直接丢掉，页面没有任何终态。

## 四、已核实合规的部分

这些是审查中重点验证、结论为通过的项，记录下来避免后续重复怀疑。

- **分层导入**：`core`、`platforms`、`ai` 三个包的每一条导入要么是相对路径要么是 `@hongtai/core`，没有 `node:*`、`fs`、`path`、`@capacitor/*`。三个包的 `tsconfig` 带 `DOM` lib，但只用到 `URL`、`crypto.getRandomValues` 这类同构 API。
- **APK 依赖边界**：`apps/web` 与 `capacitor-runtime` 对 `@hongtai/node-runtime`、`@hongtai/cli`、`@hongtai/ai/node`、`sharp` 的导入数为零；`vite.config.ts` 无别名，`capacitor.config.ts` 只打包 `apps/web/dist`。有 `tests/apk-runtime-boundary.test.ts` 守卫。
- **Android 权限**：清单只声明 `INTERNET`（合并后另有 Media3 带入的 `ACCESS_NETWORK_STATE`、`WAKE_LOCK`）。没有 `CAMERA`、`READ_MEDIA_IMAGES`、`READ_EXTERNAL_STORAGE`、`MANAGE_EXTERNAL_STORAGE`。相册走 Photo Picker，相机走外部 Intent + FileProvider 单次授权。
- **TLS 与网络**：无自定义 `TrustManager`、无 `HostnameVerifier`、无 `usesCleartextTraffic`、无网络安全配置例外。所有客户端在 `requireHttpsUrl` 之后转型为 `HttpsURLConnection`。`NativeNetworkPolicy` 还额外拒绝了回环与内网地址。
- **密钥不落地**：Kotlin 侧没有任何打印密钥、请求头、Cookie 或带 token URL 的日志；Capacitor `loggingBehavior` 为 `none`；失败分类器剥离 IP 与异常文本。AI 层的运行记录 `rawResponse` 与 `reasoning` 一律写空字符串，Node 侧的对应文件也是空占位。
- **原子写入**（Android 侧）：下载、导入、PCM、remux、成片输出统一走临时文件 + `fsync` + `renameTo`，失败只删临时文件；替换路径会先把旧文件挪开，失败时尝试恢复。
- **真实性**：七阶段进度来自 `TaskEventRecord.progress`，成片进度来自 `ProductionEvent`，都不是定时器伪造。板块骨架明确标注等待/运行中，只有 `succeeded` 后才渲染结果。发布页是禁用的"尚未接入"。`main.tsx` 从不传 `visualData`，fixture 页面在生产路由上不可达。
- **医疗边界的结构性防护**：`diagnosis-report.v1` 没有健康评分、处方或概率字段；组装期强制 `certainty: "uncertain"`、`notADiagnosis: true`，追加"单张图片不能据此诊断"，覆盖固定免责声明；不可用图片不能携带观察与建议。
- **发布链路**：`scripts/build-android-release.ps1` 从 Gradle 读取版本号而不是硬编码；只有 `:app:assembleRelease`，没有任何 `assembleDebug`；归档同版本不同字节会拒绝覆盖并报错。签名身份强制在仓库外，别名不得为 `androiddebugkey`。
- **编码**：全部审查范围内未发现 U+FFFD 或错误编码的中文。
