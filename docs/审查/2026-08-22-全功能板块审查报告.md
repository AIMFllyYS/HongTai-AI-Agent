# 全功能板块审查报告

> 审查日期：2026-08-22。审查基线：分支 `feat/hongtai-mobile-ui-redesign`，HEAD `b9a1a78`（制作链路代码清洗之后），Android `versionName=0.1.22` / `versionCode=30`。
> 本文只报告可复现、可定位的问题，不包含修复实现。功能缺口若代码已诚实标明（如 `script_estimate`、#122 真网未复验），不当成「实现撒谎」。
> 同日另有一份只谈文件职责的 [架构与代码清洗审查](2026-08-22-架构与代码清洗审查.md)；本报告覆盖全部用户路径。

## 一、结论

分层纪律在清洗之后仍然成立：`core` / `ai` / `platforms` 不导入 Node、Capacitor 或 Android API；APK 路径不持有 `FetchAiTransport`、不依赖 `node-runtime` 或 sharp；Keystore 只写不回读；页面正式入口只走 `AppRuntime`；制作计划权威在 TypeScript，Kotlin Parser 只做数值/枚举防御。2026-08-16 的阻断项（原始响应落盘、改写 Prompt 在组合层、Kotlin TTS 中文稿）在代码里已经落地。

当前真正会让用户走偏的，不再是「整层画错」，而是各板块自己的终态、错误码和诚实文案：

1. **采集**：B 站解析与 `-352`/`412` 映射正确，但 APK 下载失败几乎一律变成「媒体下载失败」（原生码无 `ERR_` 前缀，组合层不映射）；抖音/小红书风控页容易被标成「页面结构变化」；分享链上的 `xsec_token` 仍进 `request.json`。
2. **拆解**：无证据会拒绝，但公网 ASR 失败时平台描述会变成「转写证据」；板块允许空 `evidenceRefs`。
3. **观察**：主报告结构守卫已明显强于 8 月 16 日；追问已有 Zod，但流式 `content_delta` 会先把越界句送到屏幕。
4. **制作**：清洗后分层干净，浏览器 `MEDIA_ENCODER_UNAVAILABLE` 诚实；项目卡不展示 grounding / `script_estimate`，用户主要停在那一屏。
5. **设置/恢复**：Key 边界成立；`FileMediaPlugin.handleOnResume` 仍会把还活着的选图/选视频当成进程死亡。

本轮**没有阻断级**跨层越界或密钥回读。发布成熟度边界（真机、Agent 真网 `generatePlan`、B 站 APK 真网下载）仍以 [当前能力与发布状态](../当前能力与发布状态.md) 为准，不在此当新的架构违规。

## 第一部分：按功能板块

### A. 公开链接采集（抖音 / 小红书 / 快手）

数据流已核实：

```text
分享文案 → inspectInput（不发网）
  → TaskService.create / start
  → IngestPipeline 七阶段
      detect-platform → resolve-link → parse-content
      → persistableSuccessRaw 落盘（仅 host/path + 计数）
      → select-media → download-media → obtain-transcript → save-artifacts
```

**已修复（相对 8 月 16 日 B1）：** `pipeline.ts` 成功路径写 `persistableSuccessRawFromContent`，不再把 `{ item }` / `{ note }` 或带签名 query 的 CDN 写入 `rawResponse`；全程不写 `rawPage`。测试锁住 JSON 不含 Cookie / Authorization / `signature`。

#### 重要

**A1　抖音 / 小红书风控页被标成「结构变化」**

`packages/platforms/src/shared.ts` 的 `contentStateError`：登录/私密走 `CONTENT_PRIVATE_OR_LOGIN_REQUIRED`，其余一律 `CONTENT_SCHEMA_CHANGED`。正则不含验证码 / `__ac` / 风控。抖音桌面页只有风控脚本时会再拉移动分享页，两边都没有 `_ROUTER_DATA` 仍走该函数。错误码文档要求风控用 `PLATFORM_RISK_CONTROLLED` + `wait_and_retry`。快手 GraphQL 已按该码映射。

最小方向：识别 `__ac` / captcha / 验证码后抛 `PLATFORM_RISK_CONTROLLED`；加「桌面 + 分享页皆为风控」测试。不要为过关去带 Cookie。

**A2　分享链签名 query 仍进 `request.json`**

`standalone-task-service.ts` 创建任务时把 `inspection.value.normalizedUrl`（`URL.toString()`，含 search）写入 `task.json.sourceUrl` 和 `request.json`。管线之后 `task.json.sourceUrl` 会变成 `safeUrlForDisplay`，**`request.json` 一直带着完整 URL**，`start` 再拿它当输入。小红书/抖音分享常见 `xsec_token`。架构 §6.1：签名 URL 与完整敏感查询参数不得进入正式 JSON。

最小方向：落盘只用去敏 URL；若解析必须带 token，写明「无 token 的重跑可能失败」，不要把 token 当产物。

#### 一般

- **无水印是 URL 改写启发式**（抖音 `/playwm/`→`/play/` 后标 `hasWatermark: false`；小红书 H.264 一律 false）。阶段文案可能写「无水印」。应标未知，除非平台字段明确。
- **快手 `resolve` 仍 `fetchPage` 读 HTML**，`parse` 只用 GraphQL。B 站短链已改为只跟 Location。可同样优先 `followRedirectLocation`。
- **`inspectInput` 不带 `supportLevel`**，界面用 `platform === "kuaishou"` 硬编码「实验性」。规范要求实验性提示来自预检结果。
- **跳过阶段记为 `succeeded` +「已跳过」**（`pipeline.ts` `stagesAfter`）。UI 缺事件时用 `degraded` +「已跳过」，两套语义。测试把「跳过 = succeeded」锁住了。
- **下载进度 `detail.destination` 是 `task://...` 私有逻辑路径**，原样进事件。应只留字节数。

快手 `supportLevel=experimental`、无 Cookie、401/403 映射为需要登录、进度来自真实回调：未发现假进度或打码绕过风控。

### B. B 站采集

**解析与文档一致（已核实）：** `parse()` 只打公开 `view` / 可选 `nav`（WBI）/ `playurl`，不读整页 HTML；含 BV 时 `resolve` 零 HTTP；短链 `followRedirectLocation`。WBI 用公开 nav 口令，无 Cookie。HTTP `412` → `PLATFORM_API_RATE_LIMITED`；API `-352` → `PLATFORM_RISK_CONTROLLED`。签名 CDN 不落盘。

#### 重要

**B1　APK 下载失败几乎不可分支（#122 的可观测性）**

`NativeDownloadClient.httpFailure` 抛出的 code 是 `MEDIA_DOWNLOAD_FAILED` / `CONTENT_PRIVATE_OR_LOGIN_REQUIRED` / `MEDIA_DOWNLOAD_TIMEOUT`，**没有** `ERR_` 前缀。`issueFromAppError` 只从 `ERR_*` 抽 `nativeCode`。`NativeIngestPorts.#download` 不像 `#fetch` 那样映射 `ERR_LINK_*`。结果：MIME 拒绝、CDN 403、超时、remux 失败，用户都可能只看到阶段 `download-media` +「媒体下载失败」。

`DownloadMediaTypePolicy` 已接受音频槽 `video/mp4`（#122 源码侧）。浏览器 Vite **不按槽位校验 MIME** 且用 FFmpeg remux，2026-08-18 浏览器跑通不能当 APK 通过。活文档已写 #122 仍 open。

最小方向：下载/remux 原生码统一 `ERR_*`，组合层映射为可区分 `TaskError`；再用**当前签名 APK** 跑公开短稿后才能关 #122。不要把 JVM MIME 单测写成真网通过。

**B2　选流忽略 codec，APK remux 只收 AVC/HEVC + AAC**

`selectBest` 按像素×码率，不看 `avc1`/`mp4a`。`qn=64` 主要约束 durl。APK `remuxVideoNow` 只 copy 白名单轨。可能解析成功、下载成功、merge 失败，且失败算在 `download-media` 里。

最小方向：选流限制为 remux 可处理的轨，或降低分优先普通 AAC；merge 映射 `MEDIA_MERGE_FAILED`。

#### 一般

- 无 `backupUrl`，主 CDN 403 即死。
- 原生把下载 HTTP 403 标成「需要登录」，CDN 缺 Referer/签名过期不是登录。
- 短链若返回 200 HTML 而非 3xx，原生仍可能把最多 2MB body 读进内存，适配器只用 URL。

### C. 七阶段任务与处理页

**已符合：** 只有七个 `TaskStage`；`analysisStatus` 不是第八阶段。无视频源会补 `download-media` / `obtain-transcript` 终态（8 月 16 日 M2 已修）。本地视频 `sourceKind=local_video`、拆解 `platform=local_upload`；`no_speech` 不写伪文稿。同一 `taskId` ingest single-flight。冷启动 `running → interrupted`，产物保留。互动五格拒绝 `1.2w` 等假数。

#### 重要

**C1　进程中断后当前阶段事件仍是 `running`**

`recoverInterruptedWork` 只改 `task.json` 的顶层 `interrupted`，不给当前阶段追加终态、也不给后续阶段补「已跳过」。处理页有事件就原样采用。任务已终态，该行仍显示「进行中」。这与「不得永久显示进行中」同类。

最小方向：恢复时给当前阶段写 `failed`/`degraded` + `TASK_INTERRUPTED`；呈现层对「任务已终态且阶段仍 running/pending」不要渲染进行中。

**C2　任务 `failed` 时 `save-artifacts` 仍报 `succeeded`**

`pipeline.ts` 在视频失败路径仍 `report("save-artifacts", "succeeded", "完成：…")`。图文无产物时该阶段会 `failed`，视频失败路径没对齐。

最小方向：`save-artifacts` 状态跟任务终态走，失败文案不要写「完成」。

#### 一般

- 本地导入从选文件起就挂拆解五板块骨架（`TaskHomePage` `videoImporting`），此时真实工作是复制/ASR。应等 `analysis.run` 开始再挂五板块。
- 「任务在后台运行，可以放心离开此页」与「不承诺后台续跑」冲突。可改为「可离开本页；系统回收应用后需重新提交」。
- `writeTask` 每次把 `analysisStatus` 写成 `not_started`。当前 resume 不 recover 活 WebView，现网未触发；若以后把 recover 接到前台，会覆盖已成功的拆解状态。

### D. 内容拆解

**已符合：** 一次结构化流 + 最多一次整文修复，不是 Agent。无证据单元 → `TASK_ARTIFACT_MISSING`。本地 `no_speech` 不进文字拆解。五板块只在顶层字段闭合且 Zod 通过后发出。thinking 不进 `analysis.json`。页面不 `JSON.parse` 半截供应商 JSON。Prompt/Schema 只在 `packages/ai`。公网须用户确认后 `analysis.run`；本地采集成功后自动跑同一 Flow。文稿改写 Prompt 已单源（8 月 16 日 B2 已修）。

#### 重要

**D1　公网 ASR 失败时，平台描述会变成拆解证据**

`pipeline.ts`：`speechStatus !== "no_speech" && !transcript && description` 时把描述当作文稿，`transcriptSource = "description"`，并 warning。任务详情投影在 segments 为空时把整份文稿收成 `source: "transcript"`。`analysisInput` 只看证据条数 > 0，不区分 asr / description。本地通常无平台描述且被 `no_speech` 拦住；公网用户一点确认就会用简介当「真实转写」。

最小方向：仅 `transcript.source === "asr"`（或等价）才拆解；description 降级走 `TASK_ARTIFACT_MISSING` / `view_partial_result`。与本地「无口播不进文字拆解」对齐。

**D2　有结论、无引用可通过校验**

`contentEvidenceRefsSchema` 是可空数组；`assertEvidenceRefs` 只拒不存在的 ID。overview / 文风模板甚至没有 `evidenceRefs`。测试还允许空结构、空步骤。五个板块都能「校验通过并渐显」，hook/观点可以零引用。

最小方向：hook 与每条痛点/结构/观点/风险要求至少一条真实 ID，或空数组时强制「证据不足」语义并降级文档，不要当完整成功 `content-analysis.v1`。

**D3　拆解 `maxOutputTokens: 4096` 对小米 completion tokens 偏紧**

小米把思考计入 `max_completion_tokens`。五字段 JSON 容易截断 → 一次修复仍失败 → `AI_FORMAT_REPAIR_FAILED`。测试只锁数值 4096。

最小方向：拆解单独提高上限，或按 dialect 区分；加截断夹具。不要改成多轮 Agent。

**D4　服务层失败写盘仍可能被空 catch 吞掉**

Flow 侧已记录 `failedRunWriteIssues`。`StandaloneAnalysisService.#run` 二次 `#write(failed)` 仍 `.catch(() => undefined)`。磁盘可能停在 `running`，只能等进程恢复。

最小方向：写盘失败映射 `STORAGE_WRITE_FAILED`，带上 Flow 的写失败记录。

#### 一般

- 首页公网主按钮文案「开始拆解」，实际只启动采集。
- `sharesVerbatimRun` 未进入拆解落盘（只用于制作/复刻）。
- CLI 会打印 `[思考]`；APK 无此路径。

### E. 舌象 / 面部观察

**已符合（相对 8 月 16 日明显加强）：** 起始页标题「AI 智能诊断」+ 副标题「仅供日常参考」；报告顶底固定免责；底栏仍是「观察」。Schema 无评分/处方/概率字段；组装强制 `certainty: "uncertain"`、`notADiagnosis: true`。`diagnosis-medical-boundary.ts` 拦住「确诊为 / 诊断为 / 概率+数字 / 处方 / 健康评分」；08-16 举例的「可能确诊为糖尿病，患病概率80%」现有测试钉死失败。单张图、舌 XOR 面、私有导入、HEIF→JPEG、导入不在主线程。知识库生成与测试统一 LF。修复调用纯文本、不重发私图。进行中页无 BPM/SpO2/假评分。追问 **已有** `diagnosisFollowUpReplySchema` 与 `maxOutputTokens`；失败不落库；页面不展示 reasoning。

#### 重要

**E1　追问流式先于医疗 Zod**

`followUp` 把 `content_delta` 直接拼到气泡。越界句会先上屏，Zod 失败后再清空。`tests/diagnosis-flow.test.ts` 把「会发 delta」写成预期。规范允许自由文本例外，但例外仍不得把未校验的确诊/处方送到屏幕。

最小方向：累计文本命中 `diagnosisTextHasStructuralOverreach` 即停止转发 delta 并以失败收尾；落库仍只接受 Schema。

**E2　摘要 / 安全 / 追问建议 / 观察描述未挂结构扫描**

字段级扫描目前主要在 `wellnessReferences.statement` 和 `advice`。`summary`、`safetyGuidance.recommendedAction`、`followUp`、`observations[].description` 没有同一套 `rejectDiagnosisStructuralOverreach`。越界句只要不写在 statement/advice 就能进正式报告正文。

最小方向：上述可见字符串同样 `superRefine`；压缩摘要 Schema 一并挂上。不要为此维护病名词典。

#### 一般

- `listMessages` 读盘只做形状校验，被改过的 `messages.json` 会原样上屏。读取时应对 assistant 内容再 `safeParse`。
- 结构扫描不是疾病词典：「湿气重」只要不含「确诊为/概率/处方」就能过。这是有意设计，不是 08-16 那种完全没过滤。

### G. AI 连接、探测、传输

**已符合：** `FetchAiTransport` 仅 `@hongtai/ai/node`；APK 用无钥 `CapacitorAiTransport`。小米 `reasoning_content` / 阶跃 `reasoning` 投影为运行期 `thinking`，正式 run 的 `reasoning`/`rawResponse` 为空串。文本/视觉/ASR/TTS 四项独立探测，一项成功不推断其余。采集取消仍是 `TASK_CANCEL_FAILED`（首版无 AbortSignal）。HTTP 失败不把供应商正文放进 `userMessage`。

#### 重要

**G1　流开始之后的超时 / 原生失败不是 `TaskError`**

`requestWithRetry` 只包住 `transport.request()`。SSE 读到一半遇到 `AbortError` 或 Capacitor `ERR_AI_TIMEOUT`（`NativeAiTransportError`）会冒成内部错误。拆解/观察页面按码判断可重试时，超时会变成 `INTERNAL_UNKNOWN_ERROR`。

同时：`requestWithRetry` 把非 `TaskError` 一律当成可重试网络错误，`ERR_AI_NOT_CONFIGURED` 可能被打成 3 次「无法连接AI服务」。

最小方向：流消费层把 `AbortError` / `NativeAiTransportError` 映射为稳定 `TaskError`；`requestWithRetry` 识别 `ERR_AI_*`。

**G2　原生 AI SSE 无字节上限**

`NativeAiRequestClient` JSON 模式有 2MB 上限；`streamUtf8` 无上限，8KB 一块进 WebView。page fetch / 下载都有上限。恶意或失控端点可打爆 JS 堆。

最小方向：流模式累计字节封顶并失败。

#### 一般

- 聊天 SSE 循环结束后不冲刷尾包（ASR 路径会补 `\n\n`）。最后一个 `data:` 无空行会被丢，表现为空响应或假修复。
- HTTP 200 + SSE `{ error: ... }` 被忽略，最后变成 `AI_EMPTY_RESPONSE`。
- `AiGenerateRequest` 无 abort 与文档一致；文档把「取消」说得像全局，实际只有采集 `TaskService.cancel`。
