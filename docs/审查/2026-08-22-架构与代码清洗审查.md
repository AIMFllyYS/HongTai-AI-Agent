# 2026-08-22 架构与代码清洗审查

> 对照活文档：2026-08-21 校对的 `AGENTS.md`、[架构与工程规范](../架构与工程规范.md)、[项目架构解析](../项目架构解析.md)、[AI应用能力层架构](../AI应用能力层架构.md)。

> 源码基线：工作区当时的制作链路（`production-plan.v3` + Media3）。

## 一句话结论

分层意图是成立的。共享包没有 Node/Capacitor/Android 导入越界；页面不直接读 `@hongtai/ai`；规划权威在 TypeScript；Kotlin Parser 只做执行前数值/枚举防御；TTS Prompt 已上收到 `packages/ai`。

视频合成「很难改」的主因不是分层画错，而是**制作组合层和制作页把过多职责堆在同一文件里**。清洗先把这条链路按文档已经写好的职责切开。成片对不对、真机过不过，不在本文件当待办。

```text
用户操作
  → apps/web 制作页 / 微调页 / 复刻向导
  → AppRuntime.production | replica
  → StandaloneProductionService
       ├─ ProductionPlanningFlow | createAvatarCaptionPlan
       ├─ withSubtitleTimeline → 校验后的 production-plan.v3
       └─ ProductionRuntimePlugin
            ├─ ProductionPlanParser（防御解析，保留）
            └─ ProductionRenderer → Media3 720×1280 H.264/AAC
```

## 仍成立、不要再当缺陷修的部分

- `packages/core` / `ai` / `platforms` 的导入仍只有相对路径或 `@hongtai/core`。
- `apps/web` 页面不 import `@hongtai/ai`；正式入口仍是 `AppRuntime`。
- 2026-08-16 的 M3（Kotlin 重写数字人业务规则）已收敛：`validateProductionPlan` 持有 avatar 单视频、禁 BGM、绑定顺序。Parser 不再写这些规则。
- TTS 中文 instruction 在 `packages/ai/src/prompts/cloud-tts.ts`，插件只转发。
- 素材选择器进程重建已有 `AssetOperationStateStore` + `consumeAssetOperation`。
- Vitality 死页面、`ProductionPlanStore` 已不存在。
- `TaskRepository` 仍导出，是因为合约测试锁 `appendEvent`，注释已说明。不要删。
- Parser 里的 `720×1280@30`、`15–60s`、`1–12` 镜、`zh-CN`、旁白/字幕长度是规范允许的防御副本。改数字必须 TypeScript `production-bounds.ts` 与 Kotlin 一起改。不要删二次校验。
- v1/v2 计划只读兼容必须保留。
- Web 字幕预览与 Kotlin 烧录是两套渲染器，几何由测试对齐，不是重复业务规则。

## 清洗项

### C1 组合层制作服务职责过载（高）

`packages/capacitor-runtime/src/standalone-production-service.ts` 当时约 894 行，同时做：落盘解析、原生错误码映射、素材导入/恢复/删除、insight、规划、微调、渲染、中断恢复、DTO 投影。同文件测试约 1257 行。

诊断链路已经按职责拆开（service / repository / image-recovery / subscription）。制作链路应对齐该模式，且不建空 barrel。

最小方向：

| 文件 | 职责 |
| --- | --- |
| `standalone-production-record.ts` | 持久化形状、解析、规划用素材投影 |
| `standalone-production-native-errors.ts` | `ERR_*` → `TaskError` |
| `standalone-production-assets.ts` | 导入合并、pending 清单项、选择模式 |
| `standalone-production-service.ts` | 仍实现 `ProductionService` 门面 |

禁止把 Zod Schema、Prompt 或 `validateProductionPlan` 搬进组合层。

### C2 制作工作台放错层（高）

`apps/web/src/pages/CreatePage.tsx` 当时约 473 行，内嵌完整工作台状态机。阶段文案模型 `production-workbench-model.ts` 放在 `pages/`，而 composer / plan-view / 微调模型已在 `features/production/`。

最小方向：模型和工作台页面迁到 `features/production/`；`CreatePage.tsx` 只做路由壳（无 runtime 时的 planned 占位 + 挂载工作台）。源码契约测试改为同时读壳和工作台。

### C3 规划前置条件三处手写（中）

「能不能开规划」出现在：

1. `StandaloneProductionService.#generatePlan`（`TASK_ARTIFACT_MISSING` + `select_media`）
2. `ProductionPlanningFlow.validateInput`（`AI_STRUCTURED_OUTPUT_INVALID`）
3. 制作页 `productionPlanBlockedReason`（界面文案）

且 Flow 按「全部素材个数」卡 montage 下限，服务和界面按「visual 角色」卡，规则已经漂移。

最小方向：纯谓词进 `packages/core`（界面不能 import `@hongtai/ai`）。组合层继续包成 `select_media`；Flow 继续包成模型错误；界面继续把 reason 映射成中文。权威可执行计划仍是 `validateProductionPlan`。

### C4 渲染器夹带遗留静态字幕（中）

`ProductionRenderer.kt` 当时约 376 行：TTS 调度、Composition 编译、Transformer 导出/软件回退、成片校验，外加 v1/v2 的 `headlineOverlays` / `captionOverlays`。v3 字幕已在 `ProductionOverlays.kt`。

最小方向：遗留静态文字 overlay 搬出 Renderer。Parser、watchdog、failure classifier 不动。

### C5 两处真相同源，本轮只记录（低）

1. 导出模式是 `native.render({ mode })` 的插件参数，来自 `project.mode`，不在 plan JSON 里。本轮不加 schema 字段；在调用处写明来源。
2. 导出边界数字 Kotlin 手写、TS 在 `production-bounds.ts`。本轮不引入代码生成。
