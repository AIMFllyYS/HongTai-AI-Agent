# 宏泰 AI：架构与工程规范（全局唯一基线）

> 状态：已冻结。除非在评审中显式修订，本文件优先于 README、页面原型、历史说明和口头约定。
>
> 编码：所有源代码、文档、资源清单和 JSON 一律使用 UTF-8（无 BOM 亦可），不得引入 Unicode 替换字符（U+FFFD）或以错误编码重写中文。

## 1. 术语与项目边界

本项目不是传统意义上的“Web 前端 + 远程后端”系统，也不以云端网页套壳作为 Android 应用的运行基础。为避免歧义，后续工程沟通使用以下术语：

| 非正式说法 | 本项目中的专业术语 | 职责 |
| --- | --- | --- |
| 前端 | **应用界面层（Presentation / UI）** | React 页面、交互、可访问状态和纯展示逻辑 |
| 后端 | **本地应用逻辑层（Application / Domain）** | 任务编排、业务规则、Schema、错误、仓储契约和 AI Flow |
| 原生端 / Kotlin | **平台运行时与原生能力层（Platform Runtime）** | Capacitor 桥接、Android 系统能力、私有存储、媒体、网络和前台任务 |

最终交付物是本地优先的 Android APK。它可以请求内容平台和用户配置的 OpenAI 兼容服务，但这些外部服务不是本项目拥有或运行的“后端”。首版不实现注册、登录、云同步、远程任务队列或远程账号体系。

## 2. 目标架构

```text
React 应用界面层（apps/web）
        │ 仅调用公开 AppRuntime；不持有密钥、不读原始文件
        ▼
共享 TypeScript 应用逻辑层（packages/core、packages/ai、packages/platforms）
        │ 契约、状态机、平台解析、Prompt、Zod Schema、错误和业务 Flow
        ▼
Capacitor 运行时适配层（packages/capacitor-runtime）
        │ 版本化 DTO、订阅、URI 和可取消命令
        ▼
Kotlin / Android 原生能力层（android）
        │ Keystore、SQLCipher、网络、下载、文件、Photo Picker、Media3、前台任务
        ▼
Android 私有存储、系统媒体能力与外部网络
```

开发期 CLI 复用同一套共享 TypeScript 应用逻辑，但通过 `packages/node-runtime` 提供 Node 文件、网络、媒体和开发期产物实现：

```text
apps/cli → 共享 TypeScript 应用逻辑 → packages/node-runtime
```

CLI 是诊断与回归入口，不是 APK 的服务端，也不能成为 APK 中的隐式依赖。

### 2.1 分层硬规则

1. `packages/core`、`packages/ai` 和 `packages/platforms` 不得导入 Node、浏览器、Capacitor 或 Android API。
2. `packages/platforms` 只负责识别、规范化链接和解析公开平台内容；不得写文件、调用 UI、拼接 Prompt 或持有 API Key。
3. `packages/ai` 保留 Prompt、Zod Schema、一次格式修复、reasoning 隔离和业务 Flow；不得自行读取 Android URI、使用 Keystore 或直接依赖 `fetch` 全局实现。
4. `packages/capacitor-runtime` 只适配共享契约与原生桥，不复制平台解析、Prompt、Schema 或中文页面文案。
5. Kotlin 插件只完成系统能力：安全设置、网络/流、私有文件与 Photo Picker、媒体处理、前台任务。它不得包含平台规则、Prompt、Schema 或页面业务判断。
6. UI 只通过 `AppRuntime` 读取或修改业务状态；不得直接读取 `workspace/`、SQL 表、raw 文件、Keystore 或原生插件的未约束返回值。

### 2.2 目录职责

```text
apps/web                    应用界面层；Capacitor 打包的本地页面资源
apps/cli                    开发期无界面入口与终端日志
packages/core               运行时无关模型、任务编排、仓储与设备能力契约
packages/platforms          内容平台适配器（快手必须标记 experimental）
packages/ai                 OpenAI 兼容协议逻辑、Flow、Prompt、Zod Schema
packages/node-runtime       CLI 的 Node 设备能力和文件产物实现
packages/capacitor-runtime  APK 的 AppRuntime 组合与 Capacitor 适配器
android                     Capacitor Android 工程、Kotlin 插件、SQLCipher 与测试
tests                       固定样本、契约、迁移、状态恢复和界面控制器测试
workspace                   仅开发期本地产物与调试数据；默认不进入 Git
docs                        规范、运行说明和验收报告
```

不为“制作、素材、发布”等尚未实现的能力创建空数据库、空服务或伪实现；页面只可通过能力声明显示“尚未接入”。

## 3. 真实能力与预留能力

所有入口必须读取 `FeatureCapabilityRegistry`（由 `AppRuntime.features` 暴露），其状态只允许为 `available` 或 `planned`。`planned` 不是降级、不是测试成功，也不允许触发假上传、假生成、假发布或假进度。

| 能力 | 首轮状态 | 真实边界 |
| --- | --- | --- |
| 本地档案 | `available` | 读取/更新本地档案与头像 URI，不做登录或云同步 |
| AI 设置 | `available` | 单一 OpenAI 兼容连接；公开配置与写入式 API Key 分离 |
| URL 采集 | `available` | 从混合分享文本提取受支持链接，解析、下载、文稿与产物保存 |
| 任务历史与详情 | `available` | 读取真实仓储记录、事件、媒体和安全投影 |
| 内容拆解 | `available` | 仅用户确认后按已有任务 ID 运行 `content-analysis.v1` |
| 舌象/面部观察 | `available` | 单模式图片观察、`diagnosis-report.v1`、追问与真实历史；仅日常健康参考 |
| 制作 | `planned` | 保留界面壳，禁用动作并显示“尚未接入” |
| 素材 | `planned` | 保留界面壳，禁用动作并显示“尚未接入” |
| 发布 | `planned` | 保留界面壳，禁用动作并显示“尚未接入” |

平台能力同样必须显式声明：抖音、小红书、B 站属于稳定集合；快手仅限匿名公开单条链接并标记 `experimental`。实验性提示是入口说明，不能伪装成任务 warning 或以中文文案反推任务状态。

## 4. `AppRuntime`：界面层唯一公共入口

页面只能依赖组合接口，而不能依赖 Node、Kotlin、数据库或具体 AI 供应商。接口命名可在实现中细化，但下列职责和数据边界固定：

```ts
interface AppRuntime {
  profile: ProfileService;
  aiSettings: AiSettingsService;
  tasks: TaskService;
  analysis: AnalysisService;
  diagnosis: DiagnosisService;
  features: FeatureCapabilityRegistry;
}
```

| 服务 | 必须提供的能力 | 界面层不得获得的内容 |
| --- | --- | --- |
| `profile` | 读取、更新本地档案和头像 | SQLCipher 密钥、数据库路径 |
| `aiSettings` | 读取公开配置、保存配置、写入/替换 Key、分别探测文本/视觉/ASR | 完整 API Key、Authorization、供应商 reasoning |
| `tasks` | 输入预检、创建、列表、详情、读取/订阅进度、停止、重试 | signed URL、Cookie、原始请求头、raw 平台响应 |
| `analysis` | 按任务 ID 启动/读取 `content-analysis.v1` | 与证据无关的推理过程 |
| `diagnosis` | 创建单模式会话、读取报告、流式追问和历史 | 原始密钥、未脱敏调试信息 |
| `features` | 查询入口是否 `available` / `planned` | 不适用 |

`AppRuntime` 返回的是版本化 DTO、稳定错误码、私有媒体 URI 的安全展示地址或受控流，不是数据库行、文件路径或原生对象。Android URI 由原生层复制到应用私有目录后再转换为可安全展示的 URI；页面不得假设 `file://`、`content://` 或 desktop 路径可直接使用。

## 5. 任务模型与不可变语义

### 5.1 七个顶层阶段永不扩容

URL 采集任务的顶层 `TaskStage` 永远只有七个，UI 必须用真实事件映射以下名称，不能添加“智能分镜分析”等第八阶段：

1. `detect-platform`：识别平台；
2. `resolve-link`：处理分享文本、短链和跳转；
3. `parse-content`：提取原始内容；
4. `select-media`：选择可用媒体源；
5. `download-media`：下载视频、图片及必要素材；
6. `obtain-transcript`：平台字幕优先，否则执行 ASR；
7. `save-artifacts`：写入统一产物、任务记录和安全投影。

阶段状态只允许为 `pending`、`running`、`succeeded`、`degraded`、`failed`。内部子步骤只能写进 `detail` 或进度事件，不能增加顶层阶段。

### 5.2 任务状态、内容拆解和重试

- 任务状态为 `queued`、`running`、`succeeded`、`degraded`、`failed`、`cancelled`、`interrupted`。
- `cancelled` 是用户主动停止后的终态；`interrupted` 表示进程异常、强制停止或启动恢复检查发现任务没有活跃原生执行器后的终态。二者都不能伪装为成功或失败。
- `analysisStatus` 独立记录 `not_started`、`running`、`succeeded`、`failed`。内容拆解不属于 URL 采集七阶段，也不得通过改写 `currentStage` 展示。
- `retry` 必须创建新任务，并写入 `retryOfTaskId`；旧任务、旧事件和旧产物只读保留，禁止覆盖。
- 每个进度事件必须带按同一任务单调递增的 `sequence`、时间戳、阶段、状态与安全 `detail`。事件先持久化再通知订阅者；重启后订阅应能恢复历史顺序。
- `speechStatus=no_speech` 是 ASR 正常完成且未检测到有效口播，不是错误、不是降级，也不能用平台描述伪造文稿。

### 5.3 输入、产物和真实数据

`inspectInput(rawText)` 是分享文本、粘贴与系统分享入口共同使用的唯一输入预检：它提取第一个受支持链接、识别平台、标注其他链接被忽略并给出实验性提示。正式执行时流水线必须再次规范化，UI 不得复制正则。

任务详情只显示实际仓储中存在的标题、作者、媒体、图片、正文、文稿、问题与分析。不存在的互动量、完播量、字幕、时长、缩略图或分析结论必须显示空态，不得用固定数字、演示文案或静态 mock 填充。平台 raw 响应只用于排障，永远不是页面主数据源。

## 6. AI 连接与业务安全边界

首版只允许一个活动的 OpenAI 兼容连接，包含 Base URL、文本模型、视觉模型、ASR 模型、ASR transport 和 JSON Object / JSON Schema 高级开关。连接不是供应商绑定：页面不得预置某一家厂商或模型。

1. API Key 是**只写**敏感值：保存/替换后 React 只能获知“已配置”与掩码/更新时间，绝不读取完整值。
2. Node 继续使用现有 Fetch/Undici 路径；Android 的 `AiTransport` 由 Kotlin 读取原生 URI、附加 Keystore 中的凭据、处理 SSE 和媒体上传。
3. Prompt、Zod Schema、结构化 JSON 校验、一次格式修复和 reasoning 隔离始终留在 TypeScript；原生端不复制这些逻辑。
4. 文本、视觉、ASR 必须用不含个人数据的小夹具分别探测并分别保存成功/失败状态。文本成功不能推断视觉或 ASR 可用。
5. 内容拆解只从真实转写 segment 或图文 paragraph 生成证据；标题、作者和虚构指标不得作为模型证据。证据不足时返回诚实空结果。
6. 舌象/面部功能是图片质量和可见观察的日常健康参考，不输出疾病诊断、处方、综合健康评分或“轻度气虚”等越界结论。报告必须包含局限与安全提示。

## 7. 本地数据、加密与迁移

### 7.1 数据放置规则

| 数据类别 | 保存位置 | 规则 |
| --- | --- | --- |
| 结构化记录、状态、事件、报告索引 | SQLCipher 数据库 | 由 Android Keystore 保护的数据库密钥打开 |
| 视频、图片、音频、正文、文稿、正式 JSON | 应用私有文件目录 | 不暴露给其他 App；按任务/会话 ID 组织 |
| API Key | Android Keystore 保护的安全设置存储 | 不返回 React、不写入日志或 SQL 明文列 |
| reasoning、原始供应商响应、排障材料 | 私有调试目录（最小化、脱敏） | 非正式产品结果、不得进入会话上下文或 UI |

用户通过 Photo Picker 或文件选择的媒体，必须先复制到应用私有目录；原始临时 URI 不能作为长期持久化引用。迁移、Keystore 或解密失败时必须中止并给出稳定错误，**绝不自动清库、重建空库或覆盖原数据**。

### 7.2 SQLite v1 固定表

首次迁移仅允许建立下列八张表，表外需求须在新迁移中明确提出：

```text
schema_migrations
profiles
ai_connections
tasks
task_events
content_analyses
diagnosis_sessions
diagnosis_messages
```

`schema_migrations` 记录应用过的不可变版本；所有迁移必须在事务中执行，并在失败时保留可诊断现场。`tasks` 保存 `analysisStatus` 与可空 `retryOfTaskId`；`task_events` 保存单调 `sequence`。不为 `planned` 的制作、素材、发布建立空表。

本地档案字段固定为：`localProfileId`、可空 `remoteAccountId`、显示名、头像 URI、门店名、行业、经营标签、创建时间和更新时间。首版只使用 `localProfileId`，为未来迁移保留 `remoteAccountId`，但不提供账号登录、注册或同步。

## 8. Android 原生运行时

`android/` 与 `packages/capacitor-runtime/` 使用同一 Capacitor 主版本（当前基线为 v8，Android API 24+）。Kotlin 插件保持五类明确职责：

| 插件职责 | 允许做的事 | 禁止做的事 |
| --- | --- | --- |
| 安全设置 | Keystore 读写、SQLCipher 密钥准备、公开设置状态 | 返回完整 Key、页面文案 |
| 网络与下载 | 原生 HTTP、SSE、流式下载、取消、进度 | 平台页面解析、Prompt |
| 文件与媒体选择 | Photo Picker、文件导入、私有目录、受控 URI | 直接将临时系统 URI 当永久产物 |
| Media3 / MediaCodec | 媒体探测、音视频合并、抽取/分段 PCM WAV、转码 | 内容业务决策、AI Schema 校验 |
| 前台任务 | 前台服务、持续通知、取消、启动恢复检查 | 自动续跑已中断任务、伪造进度 |

长时间下载、媒体处理和转写必须在退后台后保持可见的前台任务通知。系统强制停止、崩溃或启动恢复发现无执行器时，将原 `queued`/`running` 任务标为 `interrupted`；用户可显式重试，但应用不得后台自动恢复执行。

## 9. UI 数据边界与交互规范

1. UI 显示的是 `AppRuntime` 的真实 DTO 和订阅事件；开发期静态样本只可用于独立视觉测试，不能与运行时数据混用。
2. 首页使用多行分享文案输入，实时调用 `inspectInput()` 显示真实链接、平台和实验性提示；执行后进入携带任务 ID 的动态路由。
3. 处理页逐项显示真实七阶段事件、顺序号和当前状态；详情页依据真实 `contentType` 在视频、图文布局间切换。
4. 采集成功后才显示“AI 自动拆解”操作；它必须由用户确认后调用 `analysis.run(taskId)`，并使用独立 `analysisStatus`。
5. 舌象/面部每次会话只能选择一种模式和一张已导入的本地图片。报告页面按图片质量、可见观察、日常参考、建议、安全提示、局限、免责声明展示；追问使用 `followUpQuestions` 快捷胶囊、可多行输入的固定编辑器、真实流式回复与历史。
6. 不得使用“智能诊疗”“诊断结果”“整体健康评分”“轻度气虚”等医疗越界或无依据文案。
7. 制作、素材、发布入口读取能力注册表。`planned` 入口可以保留设计壳，但所有动作禁用并明确说明“尚未接入”。
8. 错误弹窗、重试、配置 AI、释放空间和查看部分结果必须由一个 `TaskIssue.code/action` 展示层映射；页面不通过中文字符串、HTTP 文本或原生异常文本判断分支。

## 10. 平台、媒体与隐私规则

- 适配器仅处理公开单条作品，不处理 Cookie、自动登录、批量采集或绕过平台风控。
- 不做逐帧内容修复型去水印；“无水印”仅表示获得真实可用的无水印媒体源。无该源时保留可用媒体并标记事实。
- 已成功写入的产物不得因后续失败删除；重试不得覆盖旧任务。
- `metadata` 和 UI 可见 URL 必须移除查询参数和片段；Cookie、Token、Authorization、签名 URL、下载请求头、base64 媒体与完整 API Key 禁止写入 SQL、进度、日志、正式 JSON、截图和 UI。
- 原始分享文本不持久化；只保留执行所需的安全标准化链接。

## 11. 错误、质量与测试

`TaskIssue.code`、`severity`、`action` 是稳定协议，`userMessage` 只作默认中文展示。完整错误与 UI 映射见[错误码与前端通知约定](错误码与前端通知约定.md)。新增错误必须先添加稳定代码、可重试语义与展示动作，再实现页面，禁止以异常字符串驱动 UI。

每个实现阶段遵守“先失败测试、后最小实现、再重构”的顺序。提交前至少执行与改动相称的检查：

- TypeScript 严格类型检查、ESLint 与固定测试：`pnpm check`；
- Web 生产构建：`pnpm --filter @hongtai/web build`；
- 迁移、仓储、状态恢复、动态路由、错误映射、AI Flow 的定向测试；
- Kotlin 单元与 instrumentation 测试；
- `git diff --check`、暂存区 `git diff --cached --check`、UTF-8 替换字符扫描与敏感信息扫描。

真实 AI 验收必须分别验证文本、视觉、ASR 三种能力；不得由任一成功推断另两项。开发期 CLI 回归可读取受 Git 忽略的本地 `.env`，但 `.env` 绝不复制进 APK、Git、日志或 ADB 参数。APK 通过设置页写入自身安全存储后再进行单独探测。

## 12. 提交、迁移与真机验收

1. 每个已完成阶段只暂存其对应路径，禁止 `git add .`。
2. 提交前检查差异和编码，验证后才本地提交；不自动推送。
3. 提交信息按阶段使用：
   - `docs(architecture): lock local APK integration contract`
   - `feat(core): add local application runtime contracts`
   - `feat(android): add encrypted local runtime foundation`
   - `feat(settings): connect profile and AI configuration`
   - `feat(android): implement native ingest runtime`
   - `feat(tasks): connect ingest and content analysis UI`
   - `feat(diagnosis): connect observation reports and follow-up chat`
   - `refactor(web): enforce real and planned capability boundaries`
   - `test(android): verify real APK integration`
4. 真机验收必须连接实际物理设备，并记录 APK SHA-256、设备型号、Android/API 版本、安装结果和每项证据。没有设备时只能报告“构建/模拟器已验证”，不得宣称真机通过。
5. 最终验收至少覆盖：平台真实任务（抖音、小红书视频/图文、B 站；快手可接受明确的实验性风控结果）、视频/图文手动拆解、舌象/面部报告与各一次追问、退后台继续、通知进度、停止、中断后的手动重试，以及重启后的档案/设置/任务恢复。

## 13. 禁止事项

- 把 UI 层和本地应用逻辑层称作传统远程前后端，或借此引入无授权云端服务；
- 将 Node、Python、桌面 FFmpeg 或浏览器自动化伪装为 APK 原生能力；
- 用 mock、硬编码进度、假账号、假指标、假上传、假生成或假发布伪造可用能力；
- 自动清除加密库、自动重跑中断任务、覆盖旧任务或无证据宣称平台/真机能力可用；
- 在页面、日志、Git、测试快照或诊断报告泄露密钥、Cookie、Token、签名 URL、base64 媒体或供应商 reasoning；
- 以中文文案、异常文本或 DOM 文本作为业务状态机；
- 为尚未实现的功能堆叠空表、空插件或平行架构。
