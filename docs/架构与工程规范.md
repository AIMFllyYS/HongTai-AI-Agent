# 宏泰 AI：架构与工程规范（全局唯一基线）

> 状态：首版独立 APK 的架构基线。当前能力、发布成熟度和修复队列以[当前能力与发布状态](当前能力与发布状态.md)为准；本文件定义不随单次验收变化的边界。
>
> 编码：所有源代码、文档、资源清单和 JSON 一律使用 UTF-8。不得引入 Unicode 替换字符（U+FFFD）或以错误编码重写中文。

## 1. 术语与项目边界

本项目不是传统的“Web 前端 + 远程后端”。为消除歧义，工程沟通统一使用下列术语：

| 非正式说法 | 本项目术语 | 职责 |
| --- | --- | --- |
| 前端 | **应用界面层（Presentation / UI）** | React 页面、交互、展示状态和可访问性 |
| 后端 | **本地应用逻辑层（Application / Domain）** | 任务编排、平台解析、AI Flow、Schema、错误和业务规则 |
| Kotlin / Android | **平台运行时与原生能力层（Platform Runtime）** | Android 私有文件、Keystore、网络、Photo Picker 和必要媒体 I/O |

交付物是独立运行的 Android APK。它可以访问公开内容平台和用户配置的 OpenAI 兼容服务，但本项目不拥有远程 Web 后端。首版不做账号、登录、云同步、远程任务队列、多端同步或多供应商档案。

## 2. 首版目标与反膨胀原则

首版必须让甲方安装 APK 后完成下列真实路径：

1. 保存一个 OpenAI 兼容连接；
2. 粘贴公开作品分享文本，看到真实七阶段进度和真实成功/失败结果；
3. 查看真实媒体、正文、文稿和问题，并由用户确认后运行真实内容拆解；
4. 选择一张舌象或面部图片，获得真实观察报告并追问一次；
5. 从一份正式内容拆解出发，选择本机素材、生成制作计划并在手机本地合成竖屏 MP4；素材库和发布仍明确显示“尚未接入”。

稳定的含义是**路径少、数据来源唯一、输入输出明确**，不是提前堆叠更多框架。新表、新状态、新插件、新依赖或新抽象只能在一个真实用户路径已经证明需要它时加入。

## 3. 最小独立 APK 架构

```text
React 应用界面层（apps/web）
        │ 只读取安全 DTO，发起用户事件
        ▼
ThinAppRuntime（packages/capacitor-runtime）
        │ 只组合既有 Flow 与 Android I/O 端口；不复制业务规则
        ▼
共享 TypeScript 本地应用逻辑层
packages/core + packages/platforms + packages/ai
        │
        ▼
Android 具名 I/O 端口
SecureSettings · LocalFiles · NativeHttp · MediaTools
        │
        ▼
Android Keystore、应用私有目录、Photo Picker、网络与必要媒体能力
```

`IngestPipeline` 是 APK 中唯一的采集任务执行器。`ContentAnalysisFlow`、`DiagnosisFlow` 和 `ProductionPlanningFlow` 分别是内容拆解、图片观察和视频制作计划的唯一 AI 业务 Flow。经共享 TypeScript 验证的 `production-plan.v1` 才能交给 `MediaTools`/Media3 执行本地渲染。平台解析、七阶段、Prompt、Zod Schema、一次格式修复、reasoning 隔离和医疗安全规则只能存在于共享 TypeScript 本地应用逻辑层；Capacitor 和 Kotlin 不复制平台解析、Prompt、Schema 或七阶段，也不复制制作计划规则。

开发期 CLI 继续通过 `packages/node-runtime` 调用同一套共享逻辑：

```text
apps/cli → 共享 TypeScript 本地应用逻辑层 → packages/node-runtime
```

CLI 只用于开发回归，不能成为 APK 的服务端或隐式运行依赖。若 UI 需要机器可读输出，增加版本化 DTO/JSON 适配，不能解析中文终端文案。

## 4. 分层硬规则

1. `packages/core`、`packages/ai` 和 `packages/platforms` 不得导入 Node、浏览器、Capacitor 或 Android API。
2. `packages/platforms` 只识别、规范化和解析公开链接；不得写文件、调用 UI、持有 API Key、拼 Prompt 或绕过平台风控。
3. `packages/ai` 只保留 AI 协议、Prompt、Schema、Flow 与安全规则；不得读取 Android URI、访问 Keystore 或处理页面文案。
4. `packages/capacitor-runtime` 只能把共享端口映射为 Android I/O；不得新增另一套 Pipeline、任务状态机、平台解析或 AI Flow。
5. Kotlin 只负责系统 I/O：Key 保存、私有文件、用户选择媒体、HTTP/下载、必要媒体工具。它不得包含业务规则、Prompt、Schema、平台解析或 UI 决策。
6. UI 只能通过 `AppRuntime` 消费版本化 DTO；不得直接读原生插件、文件路径、Key、请求头、Cookie、原始平台响应或数据库行。

## 5. 平台端口：只保留四个具名能力

| 端口 | 允许做的事 | 禁止做的事 |
| --- | --- | --- |
| `SecureSettings` | 将 API Key 写入/替换到 Keystore 保护槽位，返回“是否已配置” | 返回完整 Key、在日志中输出 Key、解释业务状态 |
| `LocalFiles` | 写入应用私有目录、原子更新 JSON、导入 Photo Picker 图片、生成展示 URI | 解析平台内容、持久化 Cookie 或把临时 URI 当长期产物 |
| `NativeHttp` | 发起受控 HTTP、流式下载、必要 AI 请求与进度回调 | 平台页面解析、Prompt、Schema、错误文案判断 |
| `MediaTools` | 仅在共享 Flow 请求时探测媒体、抽取音频，或按已验证的 `production-plan.v1` 执行本地合成 | 自行决定任务流程、生成制作计划、伪造进度 |

首版不实现 SQLCipher 任务数据库、分析数据库、诊断数据库、数据库迁移或数据库恢复。首版不实现通用任务执行器、第二份七阶段 Runner、后台续跑、前台服务通知、自动重试或自动恢复。若进程结束，启动时把未终态快照标记为 `interrupted`；用户重新开始新任务。

## 6. 本地数据与安全

### 6.1 保存位置

| 数据 | 位置 | 规则 |
| --- | --- | --- |
| 显示名、门店信息、Base URL、模型名、公开设置状态 | Android 私有偏好 | 不保存完整 API Key |
| API Key | Android Keystore 保护的安全槽位 | 只写；React 只能得到已配置状态和更新时间 |
| 任务快照 | `tasks/<taskId>/task.json` | 原子写入；只保存安全 DTO |
| 任务事件 | `tasks/<taskId>/events.jsonl` | 先写入、再通知 UI；顺序号单调递增 |
| 媒体、正文、文稿、正式分析 JSON | `tasks/<taskId>/` | 应用私有目录，不暴露内部路径 |
| 观察报告与追问 | `observations/<sessionId>/` | 图片先导入私有目录，再调用共享 Flow |
| 制作项目、用户素材、计划与成片 | `productions/<projectId>/` | 素材由系统选择器导入；计划和成片原子保存，不进入素材库或自动发布 |
| 任务发现 | `tasks/<taskId>/` 子目录 | 当前实现通过私有任务目录枚举读取；不得凭空依赖不存在的 `tasks/index.json`，未来新增索引必须可由目录重建 |

文件更新使用临时文件后替换。写入失败不删除已有成功产物，也不伪造完成记录。Cookie、Authorization、签名 URL、下载请求头、完整 API Key、base64 媒体、供应商 reasoning 和原始响应不得进入正式 JSON、UI、日志、Git 或测试快照。

### 6.2 任务语义

URL 采集顶层阶段只有七个，名称与既有 `TaskStage` 一致：

1. `detect-platform`；
2. `resolve-link`；
3. `parse-content`；
4. `select-media`；
5. `download-media`；
6. `obtain-transcript`；
7. `save-artifacts`。

阶段状态只能是 `pending`、`running`、`succeeded`、`degraded`、`failed`。内容拆解使用独立 `analysisStatus`，永不成为第八阶段。`speechStatus=no_speech` 表示 ASR 正常完成但无有效口播，不是失败或降级。

首版任务状态使用 `queued`、`running`、`succeeded`、`degraded`、`failed`、`interrupted`。持久化模型可兼容读取历史 `cancelled` 状态，但当前 standalone runtime 不提供成功取消运行中任务的用户能力；UI 不得承诺“停止”可用。当前不承诺后台续跑或自动重试；用户重新执行时创建新任务，旧任务和产物不覆盖。进程中断后的恢复语义必须以当前状态文档和对应 Issue 的实现/验收为准，不得仅靠页面文案假定已经恢复。

`inspectInput(rawText)` 是分享文本、粘贴和系统分享的唯一输入预检。UI 只展示它给出的链接、平台、忽略链接和实验性提示，不复制正则或平台判断。

## 7. AppRuntime：应用界面层唯一入口

页面只依赖组合接口：

```ts
interface AppRuntime {
  profile: ProfileService;
  aiSettings: AiSettingsService;
  tasks: TaskService;
  analysis: AnalysisService;
  diagnosis: DiagnosisService;
  production: ProductionService;
  features: FeatureCapabilityRegistry;
}
```

| 服务 | 页面可做的事 | 页面永远得不到的内容 |
| --- | --- | --- |
| `profile` | 读取/更新本地档案、导入头像 | 内部路径、Key、原生对象 |
| `aiSettings` | 读取公开配置、保存公开配置、写入 Key、按将使用的能力测试连接 | 完整 Key、Authorization、reasoning |
| `tasks` | 预检、创建、列表、详情、订阅真实进度 | Cookie、签名 URL、原始请求头、raw 平台响应 |
| `analysis` | 用户确认后运行/读取 `content-analysis.v1` | 无关推理过程 |
| `diagnosis` | 创建单模式会话、读取报告、追问和历史 | 原始图片路径、密钥、调试材料 |
| `production` | 基于正式拆解创建项目、导入素材、生成 `production-plan.v1`、订阅真实合成进度和读取成片 | 任意文件路径、模型原始响应、伪造进度 |
| `features` | 查询 `available` / `planned` | 不适用 |

返回值必须是版本化 DTO。私有 URI 只通过受控展示 URI 交给页面；页面不得假定 `file://` 或 `content://` 可直接显示。

## 8. UI 真实数据规范

1. 首页是多行分享文案输入，实时调用 `inspectInput()`；创建任务后进入带任务 ID 的处理页。
2. 处理页逐项渲染真实的七阶段事件、顺序号和状态；不得伪造百分比、时长或成功结果。
3. 详情页依据真实 `contentType` 渲染视频或图文；不存在的媒体、正文、文稿、互动指标或结论显示空态。
4. 采集成功后才显示“AI 自动拆解”；用户确认后调用 `analysis.run(taskId)`，展示真实证据与结果。
5. 观察会话一次只选择舌象或面部、一张私有图片。报告展示图片质量、可见观察、日常参考、建议、安全提示、局限、免责声明和真实追问历史。
6. 不使用“智能诊疗”“诊断结果”“整体健康评分”“轻度气虚”等无依据或越界文案。
7. 制作页只接受已成功的 `content-analysis.v1`，至少三份用户主动选择的图片或视频，以及 15–60 秒目标时长；计划和渲染失败均保留真实错误，不伪造视频。项目状态按 `projectId` 保持单一权威来源，进程中断不能永久显示“渲染中”。
8. 制作成片固定为竖屏 720×1280、30fps、H.264/AAC MP4；旁白使用 Android 系统 TTS，字幕和画面合成使用 Media3。素材库和发布仍通过统一能力组件显示“尚未接入”。
9. 页面由稳定 `TaskIssue.code` 和 `action` 映射提示与下一步，不能根据中文异常文本、HTTP 文本或 DOM 文案做逻辑分支。

## 9. AI、平台与媒体边界

- 首版仅一个 OpenAI 兼容连接，支持 Base URL、文本/视觉/ASR 模型、ASR transport 与必要 JSON 开关；不绑定某个供应商。
- `.env` 只用于开发机 CLI 回归，不能进入 APK、Git、日志、截图或 ADB 参数。APK 必须通过设置页写入自身安全槽位。
- 文本、视觉、ASR 的真实调用彼此独立；只在用户实际使用该功能前或用户显式点击测试时验证，不能用一种成功推断其他能力成功。
- 内容拆解只使用真实转写 segment 或图文 paragraph 作为证据。证据不足时返回诚实空结果。
- 制作计划只引用当前项目已导入的素材 ID，镜头顺序连续且总时长必须精确等于目标时长；TypeScript 验证通过后 Kotlin 才可执行。
- 系统 TTS 优先选择已安装的同语言离线 Voice；首次合成失败时只重试一次，不引入第二套云端 TTS。H.264 输出以旋转后的显示尺寸 720×1280 验收。
- 舌象/面部功能是日常观察参考，不输出疾病诊断、处方、概率或综合健康评分。
- 只处理公开单条作品；不处理 Cookie、登录、批量采集或绕过风控。快手始终标记为 `experimental`。
- 不实现逐帧去水印。无可用无水印媒体源时，只保留真实可用结果与事实提示。

## 10. 测试、提交与交付

1. 每个新增行为先写失败测试、确认失败、写最小实现、再确认通过。
2. 每个纵向阶段只暂存其对应路径，禁止 `git add .`；执行 `git diff --cached --check`、定向测试和 UTF-8 扫描后本地提交，不自动推送。
3. 本次交付分为：最小运行时收敛、真实任务与内容拆解、设置与观察、本地视频制作、APK 构建验收。不要把素材库或发布改造混入其中。
4. **完整 APK 交付前**至少运行：TypeScript 类型检查、定向测试、Web build、Android 单元测试、debug APK 构建、`git diff --check`、UTF-8/敏感信息扫描；单层变更按[任务执行模板](任务执行模板.md)选择受影响范围的验证。
5. 真机未连接时只能报告“已构建”，不能声称已真机验证。真机可用后记录设备、API 版本、APK SHA-256、安装结果和实际链路证据。正式 release 还必须验证团队签名、递增 `versionCode` 和不带降级参数的正常升级路径。

## 11. 禁止事项

- 将应用界面层和本地应用逻辑层误称为传统远程前后端，并以此引入无授权云端服务；
- 在 Capacitor/Kotlin 复制 `IngestPipeline`、平台解析、Prompt、Schema 或第二个状态机；
- 用 mock、硬编码进度、假指标、假上传、假生成、假发布或假诊断冒充可用能力；
- 为未来可能性预建数据库、迁移、后台服务、恢复系统或泛化框架；
- 把 Node、桌面 FFmpeg、浏览器自动化伪装成 APK 原生能力；
- 自动删除已有产物、自动重跑中断任务，或无证据宣称平台、AI、APK 或真机能力可用；
- 在任何页面、日志、Git、测试快照或报告泄露密钥、Cookie、Token、签名 URL、base64 媒体或供应商 reasoning。
