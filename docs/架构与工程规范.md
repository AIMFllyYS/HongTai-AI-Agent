# 宏泰 AI 智能体：架构与工程规范

## 1. 文档目的

本文档固定项目从无界面核心、CLI 验证到 Android APK 的工程结构和职责边界，防止早期代码与最终手机端架构发生冲突。

这是一份工程基线，不代表所有功能已经确定。各平台解析、下载、本地ASR和视频处理方案仍需逐项验证后实现。

## 2. 当前目标

第一阶段只跑通以下闭环：

```text
输入抖音/小红书/B站链接，或快手匿名公开链接（实验性）
        ↓
识别平台并解析链接
        ↓
保存平台原始结果和标准化信息
        ↓
选择可用视频源并下载
        ↓
优先获取平台已有字幕
        ↓ 没有字幕
对本地视频进行语音转写
        ↓
保存视频、文稿、字幕、元数据和任务日志
```

第一阶段明确不做：

- React/Capacitor 页面；
- 用户、门店、权限和云端账号系统；
- 云端任务队列和分布式服务；
- 自动发布到内容平台；
- 复杂逐帧画面去水印；
- 大规模爬取、批量账号采集；
- 为未知未来需求提前建设抽象层。

## 3. 真实项目形态

本项目不是传统“Web前端 + 云端后端”。它最终是一个本地优先的 Android APK，由三部分构成：

```text
React/TypeScript 手机页面
            ↓
纯 TypeScript 应用核心和平台适配器
            ↓
Capacitor 能力接口
            ↓
Kotlin 本地下载、文件、媒体、后台任务和端侧ASR
```

CLI 是开发阶段的无界面入口：

```text
终端 CLI
    ↓
同一套 TypeScript 应用核心和平台适配器
    ↓
Node 本地下载、文件、FFmpeg和ASR适配器
```

CLI 不进入最终手机页面，也不会限制 APK。它的作用是让核心能力在 GUI 开发前可以独立运行、观察和调试。

## 4. 总体架构原则

### 4.1 核心与运行环境分离

`packages/core` 和 `packages/platforms` 必须可以在不具备 Node.js 的环境中加载。

以下能力不得直接出现在共享核心中：

- `fs`、`path`、`child_process`；
- 本机 FFmpeg 命令；
- Python脚本；
- Playwright/Chromium桌面进程；
- Capacitor API；
- Android/Kotlin API。

共享核心只依赖契约。CLI 由 `node-runtime` 实现契约，APK 后续由 Capacitor/Kotlin 实现相同契约。

### 4.2 平台实现彼此隔离

每个平台都是独立适配器：

```text
PlatformAdapter
├── DouyinAdapter
├── XiaohongshuAdapter
├── BilibiliAdapter
└── KuaishouAdapter（experimental）
```

新增或修复一个平台，不应修改其他平台的解析代码。平台差异必须在标准化之前消化，主流程只处理统一结构。

每个适配器显式声明`supportLevel`。`stable`表示已经进入稳定平台集合；`experimental`表示链路可用但仍受平台风控或协议波动影响。入口可以显示能力提示，但不能把实验性标签写成任务warning或由中文文案反推状态。

### 4.3 原始结果始终保留

解析到什么就保留什么。任务不能因为作者、标题、封面等非关键字段缺失而整体失败。

每次任务至少保存：

- 原始链接；
- 解析后的标准链接；
- 平台原始响应、页面状态或安全投影；
- 标准化结果；
- 每个阶段的状态；
- 可理解的失败原因。

### 4.4 最小降级，不建设复杂验证系统

只实现有现实价值的有限降级：

```text
公开页面/API
    ↓失败
用户提供的登录态
    ↓失败
可选浏览器辅助
    ↓失败
保存已获得信息并明确报告停止阶段
```

每次降级都必须在任务日志和结果中可见，不能静默切换。

## 5. 目录职责

```text
HongTai-AI-Agent/
├── apps/cli                 当前无界面入口
├── packages/core            纯TypeScript业务核心与契约
├── packages/platforms       三个稳定平台适配器与快手实验性适配器
├── packages/node-runtime    CLI专用设备能力
├── android                  后续Capacitor Android工程
├── tests                    固定样本、流程测试和少量冒烟测试
├── workspace                本地任务、缓存、Cookie和模型
├── scripts                  本地辅助脚本
└── docs                     架构、调研和运行说明
```

### 5.1 `apps/cli`

只负责：

- 读取命令和参数；
- 组装核心、平台适配器和 Node 运行时；
- 将进度输出到终端；
- 设置退出码。

CLI 不包含平台解析规则和业务流程。

### 5.2 `packages/core`

只负责：

- 统一数据类型；
- 核心能力契约；
- 任务阶段和状态流转；
- 降级顺序；
- 产物组织规则。

它是 CLI 和 APK 共同使用的核心。

### 5.3 `packages/platforms`

只负责：

- 判断链接是否属于本平台；
- 解析短链接和标准链接；
- 获取页面/API数据；
- 提取可用媒体源、字幕和元数据；
- 转换为 `PlatformContent`。

平台适配器不直接将文件写入磁盘，也不负责运行ASR。

### 5.4 `packages/node-runtime`

只供电脑 CLI 使用，后续包含：

- HTTP和流式文件下载；
- 本地目录与产物保存；
- FFmpeg/FFprobe调用；
- 音频提取；
- 本地ASR调用；
- 必要时的浏览器降级。

它不是未来 APK 的依赖。

### 5.5 `android`

等核心流程稳定后由 Capacitor 生成。自定义 Kotlin 能力按职责分成少量插件：

- `DownloadPlugin`：前台/后台下载和进度；
- `FilePlugin`：应用目录、MediaStore、SAF；
- `MediaPlugin`：媒体信息、抽音频、转码和字幕合成；
- `TranscribePlugin`：端侧ASR；
- `SharePlugin`：保存、分享和目标 App 唤起。

Android 插件不得包含平台页面解析业务。

## 6. 核心数据契约

### 6.1 平台适配器

```ts
interface PlatformAdapter {
  readonly platform: "douyin" | "xiaohongshu" | "bilibili" | "kuaishou";
  readonly supportLevel: "stable" | "experimental";
  matches(url: string): boolean;
  resolve(url: string, http: HttpClient): Promise<ResolvedLink>;
  parse(link: ResolvedLink, http: HttpClient): Promise<PlatformContent>;
}
```

### 6.2 标准化内容

```ts
interface PlatformContent {
  platform: SupportedPlatform;
  sourceUrl: string;
  canonicalUrl?: string;
  title?: string;
  description?: string;
  author?: string;
  coverUrl?: string;
  videos: MediaSource[];
  images: MediaSource[];
  subtitles: SubtitleSource[];
  raw: unknown;
}
```

除平台、原始链接和原始结果外，大多数字段允许缺失。

### 6.3 运行环境契约

共享核心通过以下接口使用外部能力：

- `HttpClient`；
- `MediaDownloader`；
- `MediaTranscriber`；
- `ArtifactStore`；
- `ProgressReporter`。

以后 Node 和 Android 分别实现这些接口，而不是复制主流程。

`HttpClient`同时提供GET和可重放字符串请求体的POST。GET默认有限重试；POST默认只发送一次，只有像快手作品详情这样的只读查询才能显式设置`maxAttempts`。CLI由`NodeHttpClient`实现，未来APK使用Capacitor/Kotlin原生HTTP实现，平台适配器不直接调用全局`fetch`，从而避开WebView CORS与受限请求头问题。

## 7. 任务阶段与状态

固定七个顶层阶段：

1. `detect-platform`：识别平台；
2. `resolve-link`：处理分享文本、短链和跳转；
3. `parse-content`：提取原始内容；
4. `select-media`：选择最佳可用媒体源；
5. `download-media`：下载视频及必要素材；
6. `obtain-transcript`：平台字幕优先，否则本地ASR；
7. `save-artifacts`：保存统一产物和任务结果。

每个阶段只有以下状态：

- `pending`；
- `running`；
- `succeeded`；
- `degraded`；
- `failed`。

复杂平台内部步骤可以写入 `detail`，不增加主流程状态数量。

## 8. 视频源与去水印规则

第一阶段的“去水印”定义为获取无水印媒体源，不做画面内容修复：

```text
平台候选媒体源
    ↓
优先无水印地址
    ↓
优先更高画质和更完整音轨
    ↓
没有无水印源时保留可用源并标记 hasWatermark=true
```

不得为了宣称“去水印成功”对未知来源进行模糊、裁切或破坏画质的处理。

逐帧修复型去水印只有在真实需求确认后才单独立项。

## 9. 文稿获取规则

文稿来源按以下顺序选择：

1. 平台官方/作者上传字幕；
2. 下载媒体后进行本地ASR；
3. ASR不可用时保留标题、描述、页面正文作为降级文本。

输出至少包括：

- `transcript.txt`：纯文本；
- `subtitle.srt`：存在时间轴时生成；
- `segments.json`：存在分段或逐词信息时生成；
- 文稿来源及模型/字幕元数据。

语音转写使用独立业务状态：

```text
transcribed  已获得有效口播文字
no_speech    ASR成功完成，但没有检测到有效口播
failed       转写请求或部分必要分段失败，无法得出无口播结论
```

`no_speech`是正常完成结果，不属于错误或降级。此时保存带状态的`transcript.json`，不生成伪造的`transcript.txt`和`draft.txt`，不使用平台描述冒充语音转写。所有分段状态只在一个共享聚合函数中汇总，平台和前端不得重复推断。

## 10. 任务产物规范

```text
workspace/tasks/{task-id}/
├── task.json
├── raw/
│   ├── response.json
│   └── page.html
├── metadata.json
├── media/
│   ├── video.mp4
│   ├── audio.wav
│   └── cover.jpg
├── transcript/
│   ├── transcript.txt
│   ├── subtitle.srt
│   └── segments.json
└── task.log
```

规则：

- 已成功产出的文件不因后续失败而删除；
- 文件名必须经过安全处理；
- 原始结果和标准化结果分开保存；包含临时签名URL的平台只保存足够排障的安全投影；
- `metadata.json`中的URL移除查询参数，下载专用请求头不落盘；完整临时地址只在当次下载请求内存中使用；
- Cookie、Token不得写入日志或 `task.json`；
- 中间缓存可以清理，最终产物不能被自动覆盖。

## 11. 配置与敏感信息

项目只提交 `.env.example`，不提交真实 `.env`。

本地 Cookie、账号状态和模型放入：

```text
workspace/cookies/
workspace/models/
```

这些目录默认被 Git 忽略。任何日志输出都必须移除 Cookie、Authorization、Token 和签名参数。

Android 阶段再决定敏感数据使用系统 Keystore 还是应用私有存储。

### 11.1 分享文本与前端调用契约

CLI、React页面和系统分享入口必须共同调用 `packages/core` 的输入检查能力：

```ts
inspectInput(rawText): InputInspection
runIngest({ input: rawText }): Promise<IngestResult>
```

`inspectInput`只用于粘贴后的即时预览；正式执行时流水线必须再次规范化输入。共享核心负责提取第一个受支持链接、补全HTTPS、平台识别和忽略多余链接，前端不得复制正则规则。

小红书内容通过 `contentType` 区分：

- `video`进入视频、音频和文稿流程；
- `image_text`下载全部可用图片并保存正文，不调用ASR；
- `unknown`保留已经解析到的元数据并返回结构化问题。

### 11.2 结构化问题与前端通知

任务问题统一使用 `TaskIssue`，核心字段为稳定错误码、严重程度、阶段、用户文案、是否可重试和建议动作。任务结果、任务记录和失败进度事件使用同一结构；CLI中文输出不属于通信协议。

未来React/Capacitor页面按以下规则展示：

- `error`显示阻断弹窗，`warning`显示非阻断提示；
- `edit_input`、`retry`、`configure_ai`、`free_storage`等动作由统一错误展示层转换成按钮；
- 页面业务不得通过中文字符串判断错误；
- 原始粘贴文字不持久化，日志URL移除查询参数；
- API Key、Authorization、Cookie、Token、签名参数和base64音频禁止进入进度、任务结果和日志。

完整错误码和建议动作见[错误码与前端通知约定](错误码与前端通知约定.md)。

## 12. 基础质量门禁

当前只采用简单门禁：

- TypeScript 严格类型检查；
- ESLint；
- `core` 和 `platforms` 禁止导入 Node 模块；
- 每个平台使用少量脱敏固定样本测试解析；
- 主流程验证成功、降级和失败三种路径；
- 每个平台保留少量公开链接进行手动冒烟验证；
- 中文文件统一使用 UTF-8。

不要求每次检查都运行真实平台网络测试或本地大模型。

统一基础检查命令：

```powershell
pnpm check
```

## 13. 开发顺序

### 阶段一：工程骨架

- 固定目录、契约和基础门禁；
- CLI 可显示帮助和未实现状态；
- 不编写实际平台逻辑。

### 阶段二：单平台最小闭环

- 优先从抖音或小红书选一个平台；
- 跑通解析、下载、原始结果保存；
- 使用一个公开样本验证。

### 阶段三：统一文稿

- 平台已有字幕优先；
- 接入一个本地ASR实现；
- 输出 TXT、SRT 和分段JSON。

### 阶段四：补齐稳定平台并隔离实验性平台

- 以适配器形式迁入其他开源项目中验证有效的实现；
- 每个平台独立测试和维护。
- 尚未完成跨时间、跨网络验收的平台固定标记为`experimental`，不能宣称正式稳定支持。

### 阶段五：接入Android

- 创建 Capacitor Android工程；
- Kotlin实现下载、文件、媒体和ASR能力；
- 手机页面调用同一套核心流程；
- CLI继续作为开发诊断入口。

## 14. 禁止事项

- 不把整个第三方项目直接复制进主仓库；
- 不复制无许可证或禁止商业使用的代码；
- 不让平台适配器直接操作界面；
- 不把 Node/Python方案伪装成可在 APK 中直接运行；
- 不在主流程里为某个平台写特殊分支；
- 不静默吞掉错误或降级；
- 不在没有真实运行证据时宣称平台能力可用；
- 不在基础链路尚未稳定时建设复杂数据库、队列或插件系统。
