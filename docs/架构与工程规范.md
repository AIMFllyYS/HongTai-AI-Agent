# 宏泰 AI：架构与工程规范（全局唯一基线）

> 状态：独立 APK 的架构基线。最后校对 2026-08-21。当前能力、发布成熟度和修复队列以[当前能力与发布状态](当前能力与发布状态.md)为准；源码树以[项目架构解析](项目架构解析.md)为准。本文件定义不随单次验收变化的边界。
>
> 编码：所有源代码、文档、资源清单和 JSON 一律使用 UTF-8。不得引入 Unicode 替换字符（U+FFFD）或以错误编码重写中文。

## 1. 术语与项目边界

本项目不是传统的“Web 前端 + 远程后端”。为消除歧义，工程沟通统一使用下列术语：

| 非正式说法 | 本项目术语 | 职责 |
| --- | --- | --- |
| 前端 | **应用界面层（Presentation / UI）** | React 页面、交互、展示状态和可访问性 |
| 后端 | **本地应用逻辑层（Application / Domain）** | 任务编排、平台解析、AI Flow、Schema、错误和业务规则 |
| Kotlin / Android | **平台运行时与原生能力层（Platform Runtime）** | Android 私有文件、Keystore、网络、Photo Picker 和必要媒体 I/O |

交付物是独立运行的 Android APK。它可以访问公开内容平台和用户配置的 OpenAI 兼容服务，但本项目不拥有远程 Web 后端。首版不做账号、登录、云同步、远程任务队列、多端同步或多供应商档案。

## 2. 首版目标与反膨胀原则

产品必须让甲方安装 APK 后完成下列真实路径：

1. 保存一个 OpenAI 兼容连接；
2. 粘贴公开作品分享文本，看到真实七阶段进度和真实成功/失败结果；
3. 查看真实媒体、正文、文稿和问题，并由用户确认后运行真实内容拆解；也可选择一个本地 MP4，复用同一 Pipeline、ASR 证据与拆解 Flow 自动完成拆解；
4. 选择一张舌象或面部图片，获得真实观察报告并追问一次；
5. 从一份正式内容拆解出发，用 Agent 模式导入本机素材、或用爆款复刻按清单绑定素材，生成制作计划并在手机本地合成竖屏 MP4；可微调计划、删除素材、成片或项目；
6. 将正式拆解中的结构保存为独立本地模板，并可自定义、编辑和删除；发布没有路由入口，能力标记保持 `planned`。

稳定的含义是**路径少、数据来源唯一、输入输出明确**，不是提前堆叠更多框架。新表、新状态、新插件、新依赖或新抽象只能在一个真实用户路径已经证明需要它时加入。

## 3. 最小独立 APK 架构

```text
React 应用界面层（apps/web）
        │ 只读取安全 DTO，发起用户事件
        ▼
ThinAppRuntime（packages/capacitor-runtime）
        │ 只组合既有 Flow 与 Android I/O 端口；不复制业务规则
        ▼
共享 TypeScript 本地应用逻辑层
packages/core + packages/platforms + packages/ai
        │
        ▼
Android 具名 I/O 端口
SecureSettings · LocalFiles · LocalStorage · NativeHttp · MediaTools
        │
        ▼
Android Keystore、应用私有目录、Photo Picker、网络与必要媒体能力
```

`IngestPipeline` 是 APK 中唯一的采集任务执行器。`ContentAnalysisFlow`、`DiagnosisFlow` 分别是内容拆解与图片观察的唯一业务 Flow。视频制作另有：`ProductionPlanningFlow`（模型输出 v2 形状 JSON 加贴纸选择）、`ReplicaBlueprintFlow`（拍摄清单）、`AssetInsightFlow`（素材画面描述，无修复轮），以及不调用模型的 `createAvatarCaptionPlan`。规划器 JSON 经 TypeScript `withSubtitleTimeline` 组装并校验为 `production-plan.v3` 后，才能交给 `MediaTools`/Media3 执行本地渲染；旧的 `production-plan.v2`/`v1` 只保留读取与渲染兼容。内容拆解与图片观察在正常路径各使用一次紧凑的结构化流式调用；一份响应按稳定顶层字段投影为五个展示板块（内容拆解五个字段一一对应，图片观察八个字段按组合成五个板块），完整文档无效时最多进行一次文本格式修复。它们是简单 AI 调用，不是 Agent、工具调用循环或动态工作流。平台解析、七阶段、Prompt、Zod Schema、一次格式修复、reasoning 投影与隔离、医疗安全规则只能存在于共享 TypeScript 本地应用逻辑层；Capacitor 和 Kotlin 不复制平台解析、Prompt、Schema 或七阶段，也不复制 AI 状态机或制作计划规则。

Provider 的 SSE/UTF-8 `content_delta` 和 reasoning delta 都是传输流，不直接等同于正式业务结果。**在结构化文档生成路径上**（内容拆解、图片观察报告等产出受 Zod 约束的 JSON 文档的调用），`packages/ai` 只在单一 JSON 响应的指定顶层字段或字段组完整闭合，并通过对应 Zod 与语义校验后，才产生累计的 `structured-generation-progress.v1` 板块结果；reasoning delta 只能投影为同一 DTO 中运行期、非持久化的 `thinking` 文本。`packages/capacitor-runtime` 只按业务 ID 转发、合并和重放活动快照并实施 single-flight。页面不得解析半截 JSON、猜字段名或把逐字符动画伪装成已验证业务结果。五个展示板块全部完成后仍须校验原有正式文档 Schema，再原子保存正式结果。

**自由文本对话路径是明确例外。** 图片观察的追问不产出结构化文档，模型输出就是最终形态的纯文本，不存在「半截 JSON」这一风险。因此 `packages/ai` 可以把文本增量作为版本化事件（当前是 `DiagnosisStreamEvent` 的 `content_delta`）向上逐段发出，页面也可以据此逐段渲染助手气泡。例外仅在同时满足以下条件时成立：增量必须封装为版本化 DTO，页面不得触碰原始供应商响应对象或传输帧；增量只是渲染，持久化仍以校验后的 `DiagnosisMessage` 为准；reasoning delta 不适用本例外，仍只能进入运行期非持久化投影。任何输出受 Schema 约束的路径都不得援引本例外。

开发期 CLI 继续通过 `packages/node-runtime` 调用同一套共享逻辑：

```text
apps/cli → 共享 TypeScript 本地应用逻辑层 → packages/node-runtime
```

CLI 只用于开发回归，不能成为 APK 的服务端或隐式运行依赖。若 UI 需要机器可读输出，增加版本化 DTO/JSON 适配，不能解析中文终端文案。

## 4. 分层硬规则

1. `packages/core`、`packages/ai` 和 `packages/platforms` 不得导入 Node、浏览器、Capacitor 或 Android API。
2. `packages/platforms` 只识别、规范化和解析公开链接；不得写文件、调用 UI、持有 API Key、拼 Prompt 或绕过平台风控。
3. `packages/ai` 只保留 AI 协议、Prompt、Schema、Flow 与安全规则；不得读取 Android URI、访问 Keystore 或处理页面文案。
4. `packages/capacitor-runtime` 只能把共享端口映射为 Android I/O；不得新增另一套 Pipeline、任务状态机、平台解析或 AI Flow。
5. Kotlin 只负责系统 I/O：Key 保存、私有文件、用户选择媒体、HTTP/下载、必要媒体工具。它不得包含业务规则、Prompt、Schema、平台解析或 UI 决策。
6. UI 只能通过 `AppRuntime` 消费版本化 DTO；不得直接读原生插件、文件路径、Key、请求头、Cookie、原始平台响应或数据库行。

## 5. 平台端口：保持窄而具名

| 端口 | 允许做的事 | 禁止做的事 |
| --- | --- | --- |
| `SecureSettings` | 将 API Key 写入/替换到 Keystore 保护槽位，返回“是否已配置” | 返回完整 Key、在日志中输出 Key、解释业务状态 |
| `LocalFiles` | 读写受控应用私有目录、原子更新 JSON、删除具名业务根或已结束观察根、生成展示 URI | 解析平台内容、持久化 Cookie、接受任意路径或把临时 URI 当长期产物 |
| `LocalStorage` | 扫描应用私有目录并返回不含路径的占用 DTO；按一次扫描产生的 opaque id 删除单个明确可清理媒体/缓存文件 | 返回路径或 URI、删除 JSON/报告/计划等数据文件、递归删除业务根、把估算值伪装成实际文件大小 |
| `FileMedia` | 唤起系统选择器，校验并将单张图片、制作素材或单个 MP4 复制到受控私有目录 | 决定任务状态、解析模板、接受任意路径或在主线程复制大文件 |
| `NativeHttp` | 发起受控 HTTP、流式下载、必要 AI 请求与进度回调 | 平台页面解析、Prompt、Schema、错误文案判断 |
| `MediaTools` | 采集侧探测媒体、抽取音频；制作侧按已验证的 `production-plan.v3`（兼容读取 v2/v1）执行本地合成，并可按策略抽出 insight 帧 | 自行决定任务流程、生成制作计划、伪造进度 |

以上六名是契约测试锁定的概念端口。当前 Kotlin 实现为十个自定义插件：`SecureSettings`、`DeviceSettings`（只返回编译期版本）、`LocalData`（公开档案与 AI 元数据）、`LocalFiles`、`LocalStorage`、`NativeNetwork`（对应 `NativeHttp`）、`FileMedia`、`MediaRuntime`（采集 `MediaTools`）、`ProductionRuntime`（成片、TTS、`insightFrames`）。官方 `@capacitor/app` 只提供生命周期，不进入业务端口表。

首版不实现 SQLCipher 任务数据库、分析数据库、诊断数据库、数据库迁移或数据库恢复。首版不实现通用任务执行器、第二份七阶段 Runner、后台续跑、前台服务通知、自动重试或自动重放。应用使用官方 Capacitor App 生命周期信号识别真实的 inactive→active 边沿；只有确认 WebView/进程确实失去原执行上下文时，才由各状态所有者把持久化未终态写为可解释的中断终态。外部相机、Photo Picker、视频选择器等受控系统 Activity 正常返回时保留原 WebView 和仍有效的 Promise，只结束对应外部操作登记并刷新必要的安全 DTO。

## 6. 本地数据与安全

### 6.1 保存位置

| 数据 | 位置 | 规则 |
| --- | --- | --- |
| 显示名、门店信息、Base URL、模型名、公开设置状态 | Android 私有偏好 | 不保存完整 API Key |
| API Key | Android Keystore 保护的安全槽位 | 只写；React 只能得到已配置状态和更新时间 |
| 任务快照 | `tasks/<taskId>/task.json` | 原子写入；只保存安全 DTO |
| 任务事件 | `tasks/<taskId>/events.jsonl` | 先写入、再通知 UI；顺序号单调递增 |
| 媒体、正文、文稿、正式分析 JSON | `tasks/<taskId>/` | 应用私有目录，不暴露内部路径 |
| 观察报告与追问 | `observations/<sessionId>/` | 图片先导入私有目录，再调用共享 Flow |
| 存储分析快照 | `LocalStorage` 扫描应用私有目录 | 只向 UI 返回 `storage-analysis.v1`；数据文件标记为不可删除，媒体/缓存只能按 opaque id 单文件删除 |
| 制作项目、用户素材、计划与成片 | `productions/<projectId>/` | 素材由系统选择器导入；`plan.json` 为组装后的 v3（兼容读旧 v2/v1）；成片原子保存。insight 派生帧只活在项目私有目录，不进提示词路径 |
| 复刻清单 | `tasks/<taskId>/replica-blueprint.json` | 只写终态；进程被杀不留「生成中」 |
| 内容模板 | `templates/<templateId>/template.json` | 只保存有界的名称、摘要、公式、步骤和变量槽；不复制原视频、reasoning 或供应商原始响应 |
| 随包贴纸 | `apps/web/public/decorations/{id}.png` | Capacitor 同步进 APK assets；缺图映射 `PRODUCTION_DECORATION_MISSING` |
| 任务发现 | `tasks/<taskId>/` 子目录 | 当前实现通过私有任务目录枚举读取；不得凭空依赖不存在的 `tasks/index.json`，未来新增索引必须可由目录重建 |

文件更新使用临时文件后替换。写入失败不删除已有成功产物，也不伪造完成记录。Cookie、Authorization、签名 URL、下载请求头、完整 API Key、base64 媒体和供应商原始响应不得进入正式 JSON、UI、日志、Git 或测试快照。供应商 reasoning 只能通过 `structured-generation-progress.v1.thinking` 在当前运行内存中展示，不得进入正式 JSON、本地运行审计、日志、Git 或测试快照。

### 6.2 任务语义

公网链接和本地视频采集的顶层阶段都只有七个，名称与既有 `TaskStage` 一致：

1. `detect-platform`；
2. `resolve-link`；
3. `parse-content`；
4. `select-media`；
5. `download-media`；
6. `obtain-transcript`；
7. `save-artifacts`。

阶段状态只能是 `pending`、`running`、`succeeded`、`degraded`、`failed`。内容拆解使用独立 `analysisStatus`，永不成为第八阶段。`speechStatus=no_speech` 表示 ASR 正常完成但无有效口播，不是失败或降级。

本地视频任务使用 `sourceKind=local_video`，正式拆解来源使用 `platform=local_upload`，不得冒充公网平台。无需平台识别、链接解析或网络下载的阶段仍保存为七阶段中的真实完成事件，并明确说明本地输入不需要对应网络动作；音频提取、ASR、证据保存和拆解继续复用既有实现。

首版任务状态使用 `queued`、`running`、`succeeded`、`degraded`、`failed`、`interrupted`。持久化模型可兼容读取历史 `cancelled` 状态，但当前 standalone runtime 不提供成功取消运行中任务的用户能力；UI 不得承诺“停止”可用。当前不承诺后台续跑或自动重试；用户重新执行时创建新任务，旧任务和产物不覆盖。冷启动或后台返回后的恢复映射为：公网采集 `running → interrupted`；尚未启动或正在运行的本地视频采集 `queued/running → interrupted`；内容拆解 `running → failed` 并同步任务 `analysisStatus=failed`；观察报告 `running → failed`；制作项目 `planning/rendering → failed`。这些转换均附加 `TASK_INTERRUPTED`、保留已有产物并且幂等，不能仅靠页面文案假定已经恢复。

### 6.3 Android 照片权限边界

当前“拍摄图片”通过 `MediaStore.ACTION_IMAGE_CAPTURE` 启动外部相机应用，并通过未导出的 `FileProvider` 只向该 Activity 临时授予 capture URI 的读写权；当前“选择图片”在 Android 13 及以上使用系统 Photo Picker，在更低版本使用 `ACTION_OPEN_DOCUMENT` 的单项 URI 授权。因此本应用本身不直接控制相机传感器，也不扫描共享相册，不声明 `CAMERA`、`READ_MEDIA_IMAGES`、`READ_EXTERNAL_STORAGE` 或 `MANAGE_EXTERNAL_STORAGE`。Android/OEM 设置页没有可列出的危险权限组、因而省略“权限”板块或显示“未允许任何权限”，是当前最小权限设计的正常表现。`INTERNET` 以及 Media3 依赖合并带入的 `ACCESS_NETWORK_STATE`、`WAKE_LOCK` 都是安装时普通权限，不弹运行时授权框，也不扩大照片访问边界。

若未来改为应用内 CameraX 取景或自行枚举共享媒体，必须作为独立范围声明对应权限、实现运行时请求/拒绝/再次询问处理并完成物理真机验收；不得仅为让设置页出现权限入口而增加权限。

`inspectInput(rawText)` 是分享文本、粘贴和系统分享的唯一输入预检。UI 只展示它给出的链接、平台、忽略链接和实验性提示，不复制正则或平台判断。

## 7. AppRuntime：应用界面层唯一入口

页面只依赖组合接口：

```ts
interface AppRuntime {
  profile: ProfileService;
  deviceSettings: DeviceSettingsService;
  storage: StorageService;
  aiSettings: AiSettingsService;
  tasks: TaskService;
  analysis: AnalysisService;
  diagnosis: DiagnosisService;
  production: ProductionService;
  replica: ReplicaService;
  recovery: RuntimeRecoveryService;
  templates: TemplateService;
  features: FeatureCapabilityRegistry;
}
```

| 服务 | 页面可做的事 | 页面永远得不到的内容 |
| --- | --- | --- |
| `profile` | 读取/更新本地档案、导入头像 | 内部路径、Key、原生对象 |
| `aiSettings` | 读取公开配置、保存公开配置、写入 Key、按将使用的能力测试连接 | 完整 Key、Authorization、reasoning |
| `deviceSettings` | 读取当前运行 APK 的 `versionName` 与 `versionCode` | 设备标识、系统属性、任何可用于追踪的指纹 |
| `storage` | 读取真实的本机文件占用；按当前扫描快照定向删除单个媒体/缓存文件 | 私有路径、原生 URI、可删除数据文件、未经扫描的任意路径 |
| `tasks` | 预检、创建、列表、详情、订阅真实进度和有限的任务投影变更；删除终态任务 | Cookie、签名 URL、原始请求头、raw 平台响应 |
| `analysis` | 用户确认后运行/读取 `content-analysis.v1`；组合本地 MP4 选择、采集和自动拆解；按 `taskId` 订阅运行期深度思考与已校验板块进度 | 供应商响应对象、原始 content URI、未校验业务字段 |
| `diagnosis` | 创建单模式会话、读取报告、追问和历史；删除已结束观察会话；按 `sessionId` 订阅运行期深度思考与已校验板块进度 | 原始图片路径、密钥、供应商响应对象、未校验医疗相关字段；进行中的会话不可删除 |
| `production` | 基于正式拆解创建项目、导入/删除素材（可带 `requirementOrder`）、生成计划、`updatePlan` 微调、订阅真实合成进度、读取/删除成片和删除项目 | 任意文件路径、模型原始响应、伪造进度、调用方传入的 cue 毫秒 |
| `replica` | 对成功拆解生成拍摄清单、读取终态、用清单合计秒数创建制作项目 | 未拆解却假装已有清单、画面与清单的机器核对（当前不做） |
| `recovery` | 检查依赖当前 WebView 的执行和各所有者的未终态；冷启动时请求幂等中断恢复 | 私有文件、第二套业务状态机、自动重放能力 |
| `templates` | 从正式拆解复制结构，或新建、读取、编辑和删除独立本地模板 | 原视频、供应商响应、reasoning、任意私有路径 |
| `features` | 查询 `available` / `planned` | 不适用 |

返回值必须是版本化 DTO。私有 URI 只通过受控展示 URI 交给页面；页面不得假定 `file://` 或 `content://` 可直接显示。

`analysis.run/importVideo` 与 `diagnosis.runReport` 对同一业务 ID 使用 single-flight；活动运行只在内存中保留最新累计板块快照与推理文本，新订阅者立即获得一次重放，终态后清除。板块半成品与推理文本不属于可恢复业务状态，不新增中间结果文件；进程或 WebView 丢失后按既有恢复契约进入明确终态，重试会重新生成完整文档。

`tasks.subscribeChanges` 只在任务投影持久化成功后发送有限的 `upsert/deleted` 事件，不广播每个下载字节或 SSE delta。页面在初次列表读取期间按本地事件游标重放窄变更，并用请求序列拒绝过期读取；这用于消除读取与订阅竞态，不是第二个权威状态源。

## 8. UI 真实数据规范

1. 拆解首页提供两种真实来源：分享文案实时调用 `inspectInput()`；本地 MP4 调用 `analysis.importVideo()`。两者均创建带 taskId 的真实任务，不复刻正则、Pipeline 或结果组件。
2. 处理页逐项渲染真实的七阶段事件、顺序号和状态；不得伪造百分比、时长或成功结果。
3. 详情页依据真实 `contentType` 渲染视频或图文；不存在的媒体、正文、文稿或结论显示空态。互动量始终占五格（点赞/收藏/评论/分享/播放）：解析到非负整数则显示该整数，否则显示「未解析到」，不得用 42、1.2w、2.4 万之类假数据填格。
4. 公网采集成功后才显示“AI 自动拆解”，用户确认后调用 `analysis.run(taskId)`；本地 MP4 导入在获得真实 ASR 证据后自动调用同一 Flow。无证据时不得生成拆解。
5. 观察会话一次只选择舌象或面部、一张私有图片。报告展示图片质量、可见观察、需医院核实的不确定初步判断、日常参考、建议、安全提示、局限、免责声明和真实追问历史。起始页用副标题和页底免责，报告页顶部与底部展示免责。
6. 不使用“智能诊疗”“诊断结果”“整体健康评分”等确诊或评分文案。观察页标题写「AI 智能诊断」；正文允许需医院核实的不确定初步判断，禁止确诊口吻、概率数字、处方和健康评分。
7. 制作页只接受已成功的 `content-analysis.v1`。Agent 入口按模式要求至少三份画面素材或一份带原声视频；爆款复刻走 `/replica/:taskId`，不在制作首页复制向导。导出微调在 `/create/:projectId/edit`，只调 `production.updatePlan`。计划和渲染失败均保留真实错误，不伪造视频。项目状态按 `projectId` 保持单一权威来源，进程中断不能永久显示“渲染中”。
8. 删除制作素材会同时清除引用它的计划与成片；只删除成片时保留已验证计划；删除项目清除其受控私有根。规划/渲染中拒绝删除，失败不得伪造成功或连带删除其他项目。
9. 模板页只保存正式拆解中已验证的可复用结构或用户自定义字段；模板保存后独立于来源任务，删除任务不会级联删除模板。
10. 制作成片固定为竖屏 720×1280、30fps、H.264/AAC MP4；旁白优先使用 AI 连接中已配置的云端 TTS，旧连接未配置时回退 Android 系统 TTS，字幕和画面合成使用 Media3。发布没有路由，不得画成已接通。`/playbook` 只对照设计标本，禁止混入真实任务或诊察结果。
11. `/tasks/:taskId`、`/processing`、`/analysis` 是同一 `TaskPage` 的别名，处理中与已完成不得拆成互不通信的页面。
12. 页面由稳定 `TaskIssue.code` 和 `action` 映射提示与下一步，不能根据中文异常文本、HTTP 文本或 DOM 文案做逻辑分支。
13. 内容拆解与图片观察页面只显示 `structured-generation-progress.v1`：`thinking` 可作为可折叠“深度思考”展示当前运行的原始推理文本；五个业务板块仍只显示通过字段级 Zod 与语义校验的白名单结果。等待板块使用流光骨架，成功板块可渐显，但不得显示原始 JSON、字符数、伪百分比、预计耗时、供应商响应对象或未校验业务内容。
14. 首页、任务详情、拆解结果、观察历史和观察报告在健康状态下通过窄订阅自动更新；固定轮询、WebSocket 和后台常驻连接不属于首版。只有读取或订阅失败时才显示“重新读取”恢复动作，`useAppResume` 仅作为返回前台后的兜底重读。
15. 页面动效以[动效规范](动效规范.md)为准：底部 Sheet 与加号共用 Overlay 上滑+遮罩；真实读取未完成时用骨架占位，不得用全屏转圈伪装进度。AI 五板块流光骨架仍只表示结构化生成进度，不是页面懒加载。
16. 最近拆解与最近观察共用 `useLongPress` 和 `RecentRecordActionsSheet`。长按只负责打开操作菜单；「取消」关闭菜单；删除动作必须先通过页面终态判断，再由 `TaskService.delete` / `DiagnosisService.deleteSession` 在端侧再次校验，不能把进行中记录伪装成可删除或已取消。

## 9. AI、平台与媒体边界

- 首版仅一个 OpenAI 兼容连接，支持 Base URL、文本/视觉/ASR 模型、ASR transport 与必要 JSON 开关。固定的小米 MiMo 与阶跃星辰预设只在 Provider 边界映射各自的推理字段和 token 参数，高级自定义连接继续走通用兼容回退；业务 Flow 不耦合供应商。
- `.env` 只用于开发机 CLI 回归，不能进入 APK、Git、日志、截图或 ADB 参数。APK 必须通过设置页写入自身安全槽位。
- `FetchAiTransport` 是 `packages/ai` 唯一持钥类，仅经 `@hongtai/ai/node` 导出，供 CLI 与 `packages/node-runtime` 使用。根导出或 APK 路径（`packages/capacitor-runtime`、`apps/web`）一旦导入 `@hongtai/ai/node`，该隔离即失效；APK 必须继续使用不持有密钥的 `CapacitorAiTransport`。这是受控例外，不得上移到 APK 路径或当作泄漏删除。
- `AiGenerateRequest` 不携带 `AbortSignal`。首版执行中取消会抛 `TASK_CANCEL_FAILED`；生成路径只靠每次传输尝试超时，默认最多约 3×90s，不补取消契约。
- 文本、视觉、ASR 的真实调用彼此独立；只在用户实际使用该功能前或用户显式点击测试时验证，不能用一种成功推断其他能力成功。
- 内容拆解只使用真实转写 segment 或图文 paragraph 作为证据。证据不足时返回诚实空结果。
- 内容拆解与图片观察各有一个公共规则 Prompt 和一个生成 Prompt；正常路径固定一次模型调用，完整文档无效时最多一次格式/语义修复，不建立 Prompt DSL、动态注册表或 Agent 循环。
- 结构化文档生成路径上，只有完整闭合且通过字段级 Schema 与语义校验的板块结果可以进入公共进度事件；Provider reasoning delta 可以进入版本化、运行期内存 `thinking` DTO，content delta、原始响应对象和未校验字段不能进入页面。
- 自由文本对话路径（图片观察追问）是上一条的例外：文本增量可经版本化事件 DTO 逐段上屏，但原始响应对象、传输帧和 reasoning delta 仍不得进入页面，持久化仍以校验后的消息为准。判定标准是输出有无 Schema 约束，不是调用是否流式。
- 制作计划只引用当前项目已导入的素材 ID，镜头顺序连续且总时长必须精确等于目标时长；模型不得填写字幕毫秒。TypeScript 验证通过后 Kotlin 才可执行。复刻项目还必须让第 i 镜使用已绑定清单项的第 i 项（相对顺序压紧，跳过项不留空镜）。
- 旁白合成有且只有两条路径：AI 连接中已配置的云端 TTS，以及作为回退的 Android 系统 TTS（优先选择已安装的同语言离线 Voice）。首次合成失败时只重试一次，不再引入第三套合成实现。H.264 输出以旋转后的显示尺寸 720×1280 验收。
- 舌象/面部功能是日常观察参考，不输出疾病诊断、处方、概率或综合健康评分。
- 只处理公开单条作品；不处理 Cookie、登录、批量采集或绕过风控。快手始终标记为 `experimental`。
- 不实现逐帧去水印。无可用无水印媒体源时，只保留真实可用结果与事实提示。

## 10. 测试、提交与交付

1. 每个新增行为先写失败测试、确认失败、写最小实现、再确认通过。
2. 本仓库只使用根项目目录，不创建 Git worktree 或复制式隔离工作区；功能可用普通分支管理，每个纵向阶段只暂存其对应路径，禁止 `git add .`，验证后本地提交，不自动推送。
3. 新能力必须落在已有用户路径上：采集、拆解、观察、Agent 制作、爆款复刻、模板或设置。富迪素材库只是页头离线弹层。不要把未授权的发布、登录或云同步画成已接通。
4. Android 只保留 Release 产品交付路径；不构建、不交付、不归档 Debug APK。Gradle 内部测试变体不是产品版本。
5. `android/app/build.gradle.kts` 是 `versionName` 和 `versionCode` 的唯一源码权威；构建脚本读取并核对，不复制硬编码值。
6. 通过全部 Release 后验后，构建脚本按版本化名称保存到 `output/apk-archive/`；历史 APK 不覆盖，同版本不同字节必须失败并推进版本号。
7. **完整 APK 交付前**至少运行：TypeScript 类型检查、定向测试、Web build、Release 单元测试、`lintRelease`、`assembleRelease`、`git diff --check`、UTF-8/敏感信息扫描；单层变更按[任务执行模板](任务执行模板.md)选择受影响范围的验证。
8. 真机未连接时只能报告“Release 候选已构建”，不能声称真机验证或正式发布。真机可用后记录设备、API 版本、APK SHA-256、安装结果和实际链路证据，并验证团队签名、递增 `versionCode` 和不带降级参数的正常升级路径。

## 11. 禁止事项

- 将应用界面层和本地应用逻辑层误称为传统远程前后端，并以此引入无授权云端服务；
- 在 Capacitor/Kotlin 复制 `IngestPipeline`、平台解析、Prompt、Schema 或第二个状态机；
- 用 mock、硬编码进度、假指标、假上传、假生成、假发布或假诊断冒充可用能力；
- 用正则从未闭合 JSON 猜字段、让页面解析 Provider delta，或用逐字符效果冒充已验证业务进度；
- 为未来可能性预建数据库、迁移、泛化后台服务、第二套恢复状态机或其他泛化框架；
- 把 Node、桌面 FFmpeg、浏览器自动化伪装成 APK 原生能力；
- 未经用户明确确认删除已有产物、自动重跑中断任务，或无证据宣称平台、AI、APK 或真机能力可用；
- 在任何页面、日志、Git、测试快照或报告泄露密钥、Cookie、Token、签名 URL 或 base64 媒体；把供应商 reasoning 持久化、写入日志/测试/Git，或绕过版本化运行期 DTO 直接暴露响应对象。
