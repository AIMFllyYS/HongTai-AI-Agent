# 文档索引与职责

> 最后校对：2026-08-21。本文解决“该读哪一份文档”，不重复业务实现细节。

## 阅读顺序

1. [`../AGENTS.md`](../AGENTS.md)：所有 AI 与开发任务的短执行规则。
2. [当前能力与发布状态](当前能力与发布状态.md)：现在能做什么、不能分发什么、当前风险在哪。
3. [架构与工程规范](架构与工程规范.md)：跨模块架构、安全、数据和验收契约。
4. [项目架构解析](项目架构解析.md)：完整源码树和每个源文件的职责。
5. 按任务选择具体指南、错误码、CLI 文档或历史验收证据。

若文件冲突，优先级为：用户明确任务要求 → `AGENTS.md` → 未归档 `docs/Hong/新设计/hongtai-mobile.pen`（页面层视觉与可落地功能） → 活文档中的架构/状态契约 → 代码与测试的已验证事实 → 历史验收记录 → 归档画板、stitch 原稿与旧计划。发现冲突时不得静默省略稿面，应更新活文档或建立 Issue。

## 长度与维护规则

- 一个文档只回答一类问题：规则、当前状态、操作、历史证据或实施计划。
- 文档开始服务不同读者、同时包含实时规则和历史日志，或超过约 250 行且无法快速定位时，优先按职责拆分并交叉链接。
- 不因凑行数机械拆分；避免复制同一表格或规则。概览链接到权威细节，细节不要重新解释概览。
