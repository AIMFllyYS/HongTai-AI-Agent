# 版本与发布流程

> 最后校对：2026-08-15。本项目只保留一套工作目录和一条 Release APK 交付路径。

## 1. 唯一工作目录

所有开发、测试、提交和构建都在仓库根目录执行：

```text
D:\projects\Dev-Tools\HongTai-AI-Agent
```

- 不为本仓库创建 Git worktree、`.worktrees` 或复制式隔离目录。
- 普通功能可以在分支上开发，但仍使用同一个项目目录；阶段验证后本地提交，确认后合并回 `main`。
- 不用 `git add .`，不覆盖无关文件，不自动推送远端。

## 2. 唯一版本来源

Android 版本只在 `android/app/build.gradle.kts` 的 `defaultConfig` 中维护：

```kotlin
versionCode = 20
versionName = "0.1.12"
```

- `versionName` 是用户看到的版本；默认只递增第三位，例如 `0.1.6` 到 `0.1.7`。
- `versionCode` 是 Android 判断能否升级的整数；每个交给用户安装的新候选都必须递增，禁止回退或复用。
- Release 构建脚本从 Gradle 源码读取包名和版本，再核对 APK；README、测试和文档不得成为第二份版本配置。
- `download.html` 只代表已经公开并完成回验的版本，因此可以暂时落后于源码候选。

## 3. 只构建 Release

项目不再构建、交付或归档 Debug APK。唯一构建命令是：

```powershell
Set-Location 'D:\projects\Dev-Tools\HongTai-AI-Agent'
.\scripts\build-android-release.ps1
```

脚本依次执行 Web production build、Capacitor sync、Release 单元测试、`lintRelease`、`assembleRelease`、16 KiB zipalign、包身份、版本、正式证书和 SHA-256 校验。Gradle 的临时输出位于：

```text
android\app\build\outputs\apk\release\app-release.apk
```

全部后验通过后，脚本自动复制为唯一交付名并保存在统一目录：

```text
output\apk-archive\HongTai-AI-Agent-release-v<versionName>.apk
```

- 例如 v0.1.12 固定为 `HongTai-AI-Agent-release-v0.1.12.apk`。
- 归档目录保留每个仍可获得的历史 Release APK，不用新版本覆盖旧版本。
- 同版本、同字节重复构建可以复用现有归档；同版本出现不同字节时立即失败，必须推进 `versionName` 和 `versionCode` 后重新构建。
- APK 属于本地二进制产物并保持 Git 忽略；代码仓库只提交生成规则、测试和哈希验收记录。
- 已经遗失的历史 APK 不允许用新源码重建后冒充旧版本。

Gradle 内部单元测试或 instrumentation 可能仍使用测试变体；它们不是产品版本，不得传给用户，也不得写成“Debug 版本已发布”。

## 4. 两个发布状态

本项目只区分：

1. **Release 候选**：代码和 APK 已构建验证，可以交给用户上机端测，但尚未公开。
2. **正式发布**：物理设备端测通过，公开 APK 与本地候选逐字节一致，下载页已更新并在线回验。

没有独立的 Debug 产品版本。端测发现问题时，在当前源码版本继续修复；若已经产生并交付过可安装候选，则下一次交付递增 `versionCode`，避免手机把两个不同 APK 误认为同一构建。

## 5. 正式发布门禁

- `pnpm check` 与 Web production build 通过；
- Release 单元测试、lint、构建、签名和 SHA-256 通过；
- 真实 Android 手机不卸载、不使用 `-d`，通过正常覆盖安装；
- 本地数据保留，冷启动、相册/视频选择、AI 调用和前后台返回通过；
- 用户确认端测结果；
- 公开上传后重新下载并核对大小和 SHA-256；
- 最后更新 `download.html`、当前状态、CHANGELOG 和验收记录。

缺少任一项时，只能称为 Release 候选，不能称为正式发布。
