# 视频工作流管理闭环设计

> 日期：2026-08-12。用户已明确授权无人值守执行，因此本文在完成仓库证据核对、方案比较和自审后，直接作为本轮实施决策，不再等待逐段确认。

## 1. 目标

把当前“公网作品拆解 → 导入素材 → 本地合成”的窄链路补成一个可以长期使用的本地闭环：

1. 视频合成项目中的素材、成片和整个项目都可以被用户明确删除，删除同时作用于页面状态和 Android 私有文件；
2. AI 拆解除公网链接外，也可由用户从系统文件选择器上传一段本地 MP4，复用既有转写、证据和 `content-analysis.v1`；
3. 正式拆解中的 `reusableTemplate` 可以保存到模板管理页，之后可自定义、删除，并在来源任务删除后继续独立存在；
4. 底部五个入口都对应真实能力，原“素材”占位页迁移为“模板”工作区，旧 `/assets` 地址只保留兼容跳转；
5. 删除、上传和编辑均保持本地优先、单一权威状态、UTF-8 和失败不伪造成功的现有契约。

## 2. 第一性原理

### 2.1 用户需要的不是更多按钮，而是可逆和可控

本地视频与素材体积大。如果用户只能持续上传和合成，却不能删除，应用最终会出现三个问题：私有空间不可回收、错误素材会永久污染制作计划、用户无法确认自己的资料是否真的被移除。因此删除必须是领域动作，不是只从 React 数组中隐藏一项。

### 2.2 “上传视频自动拆解”必须仍然以证据为基础

本地视频与公网视频的来源不同，但拆解所需的真实证据相同：私有视频 → 音频提取 → ASR segment → 忠实文稿 → `content-analysis.v1`。不应为本地上传再造第二套 Prompt、Schema 或页面结果组件，也不能把文件名、标题或模型猜测当作转写证据。

### 2.3 模板是结构化方法，不是另一份原视频

模板管理的最小长期模型，是复制正式拆解中的公式、步骤和变量槽位，允许用户改名和编辑。模板保存后不再依赖来源任务；删除来源视频不会悄悄删掉用户已经整理的模板。第一版不建设素材市场、云模板、文件夹系统或数据库。

### 2.4 页面应按用户任务分组

底部导航承担的是五种稳定用户意图，而不是代码目录：

| 入口 | 用户意图 | 页面归属 |
| --- | --- | --- |
| AI | 日常图片观察 | 保留现有观察入口 |
| 拆解 | 公网链接或本地视频形成正式拆解 | 在同一首页提供两种真实输入 |
| 制作 | 管理制作项目、素材、计划与成片 | 删除素材/成片/项目都留在制作上下文 |
| 模板 | 保存、编辑、删除可复用结构 | 由原“素材”占位页迁移而来 |
| 设置 | 本地档案与 AI 连接 | 保持不变 |

计划中的自动发布不进入底部导航，也不伪装成可用功能。

## 3. 方案比较

### 方案 A：只补页面按钮

React 直接过滤素材和项目，模板继续用 fixture 或内存状态。改动小，但重启后数据恢复、私有文件回收、计划引用完整性全部失效，属于假删除，否决。

### 方案 B：扩展现有 AppRuntime 与私有文件端口（采用）

在共享 TypeScript 契约中加入窄而明确的删除、本地视频导入和模板服务；现有 `IngestPipeline` 增加本地视频输入分支；Kotlin 只负责系统选择器、受控文件复制和删除。它复用现有任务、ASR、AI Flow、DTO 和页面组件，不引入数据库或第二媒体内核，改动与目标成正比。

### 方案 C：立即实现通用素材库与 `edit-project.v1`

这会同时引入素材生命周期、时间线、版本校验、撤销/重做和编辑导出。它符合长期调研方向，但远超本轮“能上传、能删除、能自定义模板”的验收边界，也会把一个修复扩成完整编辑器，暂不采用。

## 4. 领域与数据设计

### 4.1 本地视频来源

任务新增明确来源字段：

```ts
type TaskSourceKind = "public_link" | "local_video";
```

历史任务缺少该字段时按 `public_link` 读取。本地视频任务不冒充任一平台；正式拆解文档的来源平台使用显式值 `local_upload`。页面显示“本地上传”，不显示伪造 URL。

`AnalysisService.importVideo()` 是一键入口：

1. 让 Android 系统选择器选择一个 MP4；
2. 原子复制到新任务的 `media/video.mp4`；
3. 让既有 `IngestPipeline` 运行固定七阶段，其中无需联网的阶段明确记录“本地输入无需平台解析/下载”；
4. 复用 MediaTools、ASR 与文稿保存；
5. 采集成功或降级且存在证据时，自动调用现有 `ContentAnalysisFlow`；
6. 返回 taskId 和可等待的正式拆解结果，不制造百分比。

选择取消不留下空任务；进程中断按现有 `interrupted` 语义处理，不承诺后台续跑。

### 4.2 制作删除语义

`ProductionService` 新增：

```ts
removeAsset(projectId, assetId)
removeOutput(projectId)
delete(projectId)
```

规则：

- `planning` 或 `rendering` 时拒绝删除；同一 `projectId` 的变更 single-flight；
- 删除被制作计划引用的素材时，同时清除旧计划和旧成片，项目回到 `draft`；
- 删除成片只清除输出文件和输出 DTO，已验证计划保留，项目回到 `ready`；
- 删除项目清除整个 `productions/<projectId>/`，包括素材、计划、音频临时目录和成片；
- 原生存储操作失败时不报告成功，现有成功产物不被其他项目连带删除。

### 4.3 任务删除语义

`TaskService.delete(taskId)` 只允许终态任务，删除 `tasks/<taskId>/` 下的视频、转写、拆解和事件。运行中的任务拒绝删除；生产项目和模板只保留已经复制的结构化内容或自己的素材，不沿引用级联删除。

### 4.4 模板模型

```ts
interface ContentTemplateRecord {
  templateId: string;
  name: string;
  summary: string;
  formula: string;
  steps: readonly string[];
  variableSlots: readonly string[];
  sourceTaskId?: string;
  createdAt: string;
  updatedAt: string;
}
```

`TemplateService` 提供 `list/get/createFromAnalysis/create/update/delete`。所有字段有长度和数量上限；页面只消费 DTO。数据写入 `templates/<templateId>/template.json`，先写临时文件再替换。

## 5. Android I/O 边界

- `FileMediaPlugin` 增加单个 MP4 选择入口；文件必须来自 `content://`，最大 250 MB，具有 MP4 `ftyp` 头、可探测视频轨和正时长；复制在专用后台执行器完成。
- `LocalFilesPlugin` 增加受控的 task/production/template 删除与模板读写端口。所有 ID 和相对路径继续通过 allowlist 校验，绝不接受任意绝对路径。
- 制作素材/成片删除由受控 production 路径执行；失败只清理本次临时文件，不删除其他成功产物。
- Kotlin 不解释模板内容、制作状态或中文业务规则；这些决定仍由共享 TypeScript 服务做出。

## 6. 页面交互

### 6.1 AI 拆解首页

保留现有公网链接卡片，在其前方增加“上传本地视频并自动拆解”主入口。用户选择后进入现有真实七阶段进度页；完成后可打开同一个 `TaskAnalysisPage` 和 `ContentAnalysisDocument`。任务历史用“本地上传视频”代替 URL。

### 6.2 视频合成页

- 每个素材卡片有带可访问名称的删除按钮；
- 成片预览区有“删除成片”；
- 当前项目有“删除项目”，历史列表中不混入不可恢复的滑动手势；
- 删除采用明确二次确认区，避免误触；
- 删除素材后旧计划/成片立即从 DTO 中消失，用户看到为什么需要重新生成计划。

### 6.3 模板页

- 顶部可从已完成拆解中选择并保存模板，也可新建空白自定义模板；
- 列表显示名称、摘要、步骤和变量槽；
- 编辑区允许修改名称、摘要、公式、逐行步骤和逐行变量；
- 删除前明确确认；空态引导用户先完成拆解或创建空白模板；
- `/assets` 兼容到 `/templates`，底部标签改为“模板”。

## 7. 错误、并发与安全

- 页面只按稳定 `TaskIssue.code/action` 展示失败，不解析 Kotlin 或供应商文案；
- 选择取消映射为 `MEDIA_SELECTION_CANCELLED`，不是通用失败；
- 本地视频无口播时保存 `no_speech` 事实，不生成无证据拆解；
- 删除动作按 taskId/projectId single-flight，运行中拒绝；
- 不记录源 content URI、私有绝对路径、API Key、供应商 reasoning 或视频字节；
- 删除不做跨实体级联，避免模板或其他项目被意外清除。

## 8. 验收证据

自动化：

- 本地视频 pipeline 的七阶段、ASR 证据和 `local_upload` Schema 测试；
- 任务取消/终态删除、制作素材/成片/项目删除和并发拒绝测试；
- 模板导入、自定义、持久化恢复和删除测试；
- Android MP4 导入策略、路径校验和安全删除 JVM 测试；
- `pnpm check`、Web build、Android unit test、lint 和 debug APK build。

端测：

- 桌面浏览器与约 390px 视口检查五个导航、上传入口、模板编辑和删除确认；
- 可用 Android 设备或模拟器上安装当前 HEAD 的 Debug APK，真实选择一个本地 MP4，观察任务生成、自动拆解、模板保存/编辑/删除、制作素材/成片/项目删除和重启后状态；
- 若本机没有物理设备，只能分别报告浏览器与 Android 模拟器证据，不声称物理真机通过。

## 9. 明确不做

- 不实现时间线、片段剪切、撤销/重做或 `edit-project.v1`；
- 不建设通用素材库、模板市场、云同步、账号或远程后端；
- 不自动发布、不绕过平台登录/风控、不逐帧去水印；
- 不把本地视频伪装成某个平台内容；
- 不删除用户未明确选择的任务、模板、项目或现有 `HongTai.zip`。
