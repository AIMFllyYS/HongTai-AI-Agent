# 移动端页面视觉对齐与响应式治理设计

> 状态：已确认的实施设计
>
> 视觉参考：`D:\projects\Dev-Tools\HongTai-AI-Agent\docs\Hong\stitch_ai`
>
> 首要验收设备：Android 手机竖屏，精细覆盖 360–430px，基准 393×852

## 1. 目标与原则

本轮不重新设计应用界面层，也不直接复用 Stitch 生成的 HTML、Tailwind CDN、远程字体或示例业务代码。设计资产只用于判断页面层级、视觉密度、色彩、形状、间距与组件关系。

实施采用“设计骨架 + 真实功能”的混合策略：

- 与设计稿差异明显的页面，回归设计稿的层级和布局语言；
- 与设计稿结构接近的页面，保留现状并修复粗糙、重叠、溢出和响应式问题；
- 页面继续消费现有 `AppRuntime` 和正式文档，不恢复假数据、假账号、假任务或假成功状态；
- 不修改七阶段采集流程、平台解析、AI Prompt、报告 Schema 或任务状态语义；
- 复用现有组件和语义 token，禁止为单页复制一套近似按钮、卡片或标题样式。

## 2. 冻结区

以下已经确认效果良好的能力本轮不得回退、替换或重新设计：

- 页面到达上下边界后的 Android 风格滑动反馈；
- 主导航页面之间的左右滑动和相邻页面跟手效果；
- 已缩小的顶部应用栏与底部导航栏尺寸；
- 顶部通知的圆角、五秒倒计时、缓动进出和上滑关闭；
- 顶部与底部安全区处理及固定导航行为。

页面调整只能发生在固定导航之间的内容区。若内容区样式与冻结区发生冲突，应修正内容区，而不是扩大导航或移除手势。

## 3. 页面分级

### 3.1 回归设计稿层级

#### 设置首页、本地档案与 AI 设置

- 以 `_9` 的个人中心、配置分组、折叠设置和清晰行项目作为视觉参考；
- 使用真实本地档案状态、头像、名称、门店和经营信息替代设计稿中的假 PRO 账号；
- 文本、视觉、ASR 使用当前真实配置和独立探测状态；API Key 仍只写入，不回传页面；
- TTS 属于原始产品方向，必须保留稳定设置入口和能力槽位；本轮状态固定为 `planned`/“尚未接入”，不展示假供应商、假声音或假探测成功；
- 不恢复登录、退出登录、版本更新、意见反馈等当前没有真实能力的行项目。

#### 舌象与面部观察

- 继续使用 `Warm Soft Tech` 的高留白、薄描边、暖白与薄荷绿层次；
- 根据真实单模式会话、图片选择、报告结构和追问历史调整组件，不复制旧稿中的综合健康评分、诊断结论或专家咨询；
- 拍照、选择图片、生成报告和追问必须保持现有真实运行时边界。

### 3.2 保留现有结构并精修

#### 采集首页

#### 任务处理、任务详情与内容拆解

- 七阶段事件、媒体、文稿、问题、分析文档和错误全部继续来自仓储；

### 3.3 只统一外观的预留页面

- 禁用动作必须清晰、可读，不使用低对比度到无法辨认的文字。

## 4. 全局组件规则

### 4.1 按钮

- 主按钮移动端默认高度 52px，次按钮与普通操作按钮默认高度 44–48px；
- 同一操作组中的同级按钮必须等高；
- 主要动作默认占满可用宽度，双按钮在空间足够时等分，空间不足时整体纵向排列；
- 按钮标签不得被挤到第二行；不通过任意增大单个按钮解决长文案；
- 图标、文字、加载态和 disabled 状态使用共享组件处理。

### 4.2 卡片与表单

- 标准卡片圆角 16px，大容器最多 20–24px；使用薄边框和低透明深绿色环境阴影；
- 表单控件圆角 12px，最小可操作高度 44px；标签、帮助文字和错误信息必须形成稳定垂直节奏；
- 技术码、URL、模型名和任务 ID 允许安全断行，但不得撑破卡片；
- 页面不得通过固定高度裁切动态中文内容。

### 4.3 字体与间距

- 中文继续使用已打包的 Noto Sans SC；不依赖 Google Fonts；
- 页面正文不低于可读尺寸，说明文字不得因缩小而变成廉价的灰色细字；
- 使用既有 4/8px 节奏，移动端页面水平边距保持 16px，重点页面可使用 20–24px 内部留白；
- 每页只能有一个主要视觉标题；应用栏标题与页面标题不得机械重复。

## 5. 响应式规则

- 360px、393px、430px 为精细验收宽度；任何一档不得出现横向页面滚动；
- 仅明确的媒体画廊或标签轨道允许局部横向滚动；
- 固定顶部、底部导航与内容区之间必须保留准确占位，页面最后一个操作和错误信息不能被底部导航遮挡；
- 两列组件在 360px 下无法保持可读宽度时切为单列；不得继续压缩文字和图标；
- 平板与桌面只要求稳定回流、合理最大宽度、无重叠和无溢出，不追求与手机相同的精细构图。

## 6. 数据与错误边界

- 页面只接收正式 view model 或 `AppRuntime` 返回数据；不得重新引入静态成功 fixture；
- `TaskIssue` 和应用错误继续通过统一顶部通知展示；页面内只保留确有上下文价值的状态说明；
- 长错误信息不得推高按钮、覆盖标题或改变导航高度；
- TTS 预留能力只展示 `planned` 状态，不触发请求、不保存虚构配置。

## 7. 验收方式

### 自动检查

- `pnpm check`；
- Web 生产构建；
- 页面路由、共享组件和能力边界既有测试不得回归；
- 新增响应式结构测试，检查按钮共享类、冻结交互仍挂载以及 TTS 只处于 `planned`。

### 浏览器与 APK 视觉验收

- 在 360×800、393×852、430×932 三档逐路由截图；
- 检查可见元素边界，任何非局部滚动组件不得超出视口；
- 检查同组按钮高度、按钮标签单行、标题和技术文本断行；
- 检查页面首尾内容不被固定导航遮挡；
- 在 Android 模拟器中抽查首页、设置、AI 配置、任务处理、任务详情、观察入口和报告追问；
- 验证上下边界反馈、左右切页和缩小后的两条导航保持现状。

## 8. 非目标

- 不实现真实 TTS 请求、语音选择或音频生成；
- 不接入制作、素材或发布能力；
- 不修改 CLI、本地应用逻辑层和 Kotlin 媒体/网络流程；
- 不为桌面端创建独立视觉系统；
- 不复制 Stitch HTML 中的远程依赖、示例状态或业务脚本。
