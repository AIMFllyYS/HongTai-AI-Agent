# 宏泰 AI 单页下载与更新日志设计规格

## 1. 目标

交付一个可直接上传或双击打开的独立 `download.html`，用于展示宏泰 AI 品牌、提供多个 Android APK 下载入口，并按时间向下浏览最近修复记录。

页面必须移动端优先，在约 390px 宽度下保持完整可用，同时在桌面浏览器中形成高完成度的宽屏构图。该页面是产品下载与修复记录入口，不接入账号、远程 API、数据库或应用运行时。

## 2. 范围与非目标

### 范围

- 将仓库正式 Logo 以 Base64 Data URL 内嵌到 HTML。
- 提供 v0.1.2 和 v0.1.1 两个真实 APK 下载链接。
- 将 v0.1.2 标记为推荐版本，但两版均明确标注为 Debug/测试版本。
- 展示来自 Git 提交记录的最近改进与准确提交时间。
- 使用单文件内联 HTML、CSS 和 JavaScript，不依赖框架、外部图片、外部字体或 CDN。
- 让后续维护者可在一个集中数据区新增、修改或删除版本和更新项。

### 非目标

- 不修改现有 React 应用、Android APK、版本号、签名或下载文件。
- 不声称这些 APK 已完成正式 Release 签名或物理真机验收。
- 不提供在线统计、下载计数、自动检测平台、二维码生成、后台管理或远程更新接口。
- 不把提交时间表述成 APK 正式发布时间。

## 3. 视觉方向

采用已确认的方案 A：高端“产品发布中心”。

- 品牌基调：温润浅色纸张质感与翡翠绿主色，呼应 Pulse Flow Logo 的青绿脉冲线条。
- 视觉记忆点：首屏以超大版本号和被克制留白包围的下载动作建立主次；向下滚动后，更新记录形成一条连续的“脉冲时间线”。
- 质感手段：细微噪点、柔和径向光晕、精细描边与层级阴影，不使用常见紫色渐变、玻璃卡片堆叠或通用 AI 官网模板。
- 字体策略：使用高质量中文本地字体栈，不拉取网络字体，以保证页面独立性、加载速度和中文稳定性。
- 动效策略：首屏分阶段入场、下载按钮轻量反馈、时间线滚动显现；在 `prefers-reduced-motion: reduce` 下关闭非必要动画。

## 4. 信息架构

页面按以下顺序组织：

1. 顶部品牌栏：Base64 Logo、宏泰 AI / Pulse Flow 名称、页面内“更新记录”锚点。
2. 首屏发布区：产品定位、推荐版本 v0.1.2、主要下载按钮、Debug/测试版事实提示。
3. 多版本下载区：v0.1.2 与 v0.1.1 的版本卡片、状态、主要变化与下载链接。
4. 更新日志区：按时间倒序显示真实提交时间、类别、标题和用户可理解的说明。
5. 页脚：Debug/测试版本边界、Android APK 提示与页面更新时间。

移动端使用单列顺序流；桌面端首屏采用左右不对称构图，下载卡片在视觉上靠近首屏上方。更新日志始终保持适合长文阅读的窄列宽。

## 5. 数据与维护方式

HTML 内联脚本顶部维护两个普通数组：

```js
const RELEASES = [];
const CHANGELOG = [];
```

`RELEASES` 每项包含 `version`、`recommended`、`status`、`summary` 和 `url`。首批数据为：

- v0.1.2：`https://husteread.com/storage/public/HongTai-AI-Agent-debug-v0.1.2-E8FE0BF5A3AE.apk`
- v0.1.1：`https://husteread.com/storage/public/HongTai-AI-Agent-debug-v0.1.1-15093BD71637.apk`

`CHANGELOG` 每项包含 ISO 时间、显示时间、类别、标题、说明和关联版本（若能准确关联）。首批记录使用仓库已核实的 Git 提交时间，并显示 `UTC+13`，避免时区歧义：

| 时间 | 提交 | 页面表述 |
| --- | --- | --- |
| 2026-08-11 20:17:27 UTC+13 | `a6bb6f5` | 增加一键 AI 配置并接入云端语音旁白 |
| 2026-08-11 18:33:52 UTC+13 | `441caa1` | 优化移动界面并开放系统 TTS 设置 |

动态内容使用 DOM API 与 `textContent` 渲染，不使用 `innerHTML` 拼接数据。数组为空时显示明确空态；下载链接缺失时按钮变为不可用状态，不伪造可下载结果。

## 6. 响应式与交互

- 基线支持 320px 以上手机宽度、约 390px 验收宽度和常见桌面宽度。
- 手机端触控目标不小于 44px；下载按钮全宽，版本卡片单列，不出现横向滚动。
- 桌面端内容最大宽度约 1200–1280px，首屏双栏，版本卡片可并排。
- 键盘可访问下载链接和页面锚点；焦点样式清晰可见。
- 使用语义化标题、`main`、`section`、`time`、`aria-label` 和合理颜色对比。
- JavaScript 不可用时，首屏主要下载链接仍保留在静态 HTML 中；增强脚本只负责扩展版本列表和更新时间线。

## 7. 真实性与错误边界

- 所有下载地址原样使用用户提供的 HTTPS 链接，并移除 v0.1.2 地址末尾的多余空格。
- 页面写明“Debug / 测试版本”，不使用“正式发布”“稳定版”或“真机已验证”等未经当前仓库状态证明的表述。
- 更新时间使用 Git 提交时间并明确标注时区与“代码提交时间”。
- 不展示 API Key、Cookie、Token、签名 URL、设备数据或内部路径。
- 不承诺浏览器一定直接保存跨域 APK；下载入口使用普通 HTTPS 链接，让服务器响应决定下载行为。

## 8. 验收

实现完成后至少验证：

1. HTML 是单文件，Logo 的 `src` 为 `data:image/...;base64,...`，不存在外部图片、脚本、样式或字体依赖。
2. 两个 APK 链接与用户提供地址逐字一致（忽略原始尾随空格），点击目标正确。
3. 桌面与约 390px 视口无横向溢出，主要内容、按钮与更新日志均可读可操作。
4. JavaScript 正常时两个数据区渲染完整；脚本禁用时推荐版本下载仍可用。
5. `prefers-reduced-motion`、键盘焦点和基本语义结构有效。
6. 文件为 UTF-8，中文无乱码且不含 U+FFFD。
7. 执行 HTML 结构/链接检查、浏览器视觉截图检查、`git diff --check` 和精确路径提交。
