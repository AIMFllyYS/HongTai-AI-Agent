# 宏泰 AI：项目整体架构方向

> 本文面向新成员快速解释当前 APK。具体硬约束以[架构与工程规范](架构与工程规范.md)为准；功能是否已接入、是否可发布以[当前能力与发布状态](当前能力与发布状态.md)为准。

## 项目形态

宏泰 AI 是本地优先的 Capacitor Android APK，而不是把远程网页套进 WebView：React 资源随 APK 打包，用户数据、任务产物和媒体保留在应用私有目录。应用只在用户发起操作时访问公开内容平台和用户配置的 OpenAI 兼容服务；项目不运营传统远程后端。

```text
Android APK
├── React 应用界面层（apps/web）
├── 共享 TypeScript 本地应用逻辑（packages/core、ai、platforms）
├── Capacitor 组合层（packages/capacitor-runtime，AppRuntime 含 replica）
└── Kotlin 平台运行时（android/app，九个自定义插件）
    ├── Keystore 与私有文件
    ├── Photo Picker / 外部相机与媒体导入
    ├── 受控 HTTP、下载、媒体探测与音频处理
    └── Media3 本地视频合成与 insight 抽帧
```

## 谁负责什么

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| React UI | 页面、交互、可访问性、真实 DTO 的展示 | 读取私有文件、解析平台页面、持有 Key |
| core | 领域模型、任务契约、状态与错误语义 | Android/浏览器/Node API |
| ai | Provider、Prompt、Schema、Flow、安全规则 | 原生 URI、Keystore、UI 决策 |
| platforms | 公开链接识别、规范化与解析 | 写文件、Cookie、Prompt、UI |
| Capacitor Runtime | 组合 Flow 和 Android I/O，提供 `AppRuntime` | 第二套 Pipeline 或状态机 |
| Kotlin | 系统 I/O、私有存储、网络、必要媒体能力 | 业务规则、平台解析、Prompt、Schema |

## 当前真实用户路径

1. 用户在设置页保存一个 OpenAI 兼容连接；密钥只进入 Keystore。
2. 用户粘贴公开作品分享内容，或上传本机 MP4；`IngestPipeline` 显示真实七阶段进度。
3. 用户确认后运行内容拆解（本地视频在获得 ASR 证据后自动跑同一 Flow），结果必须引用真实转写 segment 或图文 paragraph。
4. 用户选择舌象或面部单张图片，原生层导入私有目录，生成日常观察报告并允许追问。
5. 用户从成功拆解做视频：Agent 导入本机素材并生成计划，或爆款复刻按清单绑定后再规划；TypeScript 把规划器 v2 JSON 组装为 `production-plan.v3`，Media3 合成竖屏 MP4。可在 `/create/:projectId/edit` 微调。

富迪素材库是页头离线宣传弹层，不是素材管理，也不是 `features` 里的独立键。发布没有路由，`features.publish=planned`。不创建假任务或假结果。源码树见[项目架构解析](项目架构解析.md)。

## 数据与生命周期

- 公共设置保存在 Android 私有偏好；完整 API Key 保存在 Keystore。
- URL 任务、观察会话和视频制作项目各自保存在应用私有目录，UI 只得到受控展示 URI。
- 当前长任务仍依赖应用前台 WebView，不承诺后台续跑。官方 App 生命周期信号在后台返回时对账：仍依赖 WebView 的执行会受控重载，各领域服务把遗留 `running/planning/rendering` 转为 `interrupted/failed + TASK_INTERRUPTED`；已经保存的产物不删除、不覆盖、不自动重跑。
- 系统相机与 Photo Picker 属于外部 Activity：返回时保留当前 WebView 并刷新安全 DTO。当前路径使用系统授予的单次/单项 URI，不需要 `CAMERA` 或相册读取危险权限；设置页没有权限板块是最小权限模型的预期结果。
- 外部相机/相册、图片解码、视频渲染和网络解析是高风险边界；它们的当前修复队列见[当前能力与发布状态](当前能力与发布状态.md)。

## 技术取舍

- 不预建云同步、登录、远程队列、数据库迁移或第二个任务执行器。
- 不用 Node、桌面 FFmpeg 或浏览器自动化冒充 APK 原生能力。
- 重型媒体处理放在 Kotlin/Media3，而不是 React 主线程。
- 真正后台执行只在拆成可检查点、可幂等重试的原生工作单元后引入 WorkManager、用户发起的数据传输或带通知的前台服务；不把整套 TypeScript Flow 复制到 Kotlin。
- 新抽象、插件或依赖必须由真实用户路径证明需要；优先复用既有 DTO、Flow、组件和端口。
