# 宏泰 AI：项目整体架构方向

> 本文是便于快速理解的概览。具体工程约束、数据表、状态机、安全和验收规则以[架构与工程规范](架构与工程规范.md)为全局唯一基线；两者冲突时以前者为准。

## 项目形态

本项目计划采用 **Capacitor 混合架构**，从零开发一个可独立安装和运行的 Android APK。

最终 APK 不是简单打开云端网页，而是将 React、TypeScript 页面以及字体、图标等静态资源直接打包进 APK。安装后，应用页面不依赖 EdgeOne 或其他 Web 服务器加载。本项目不设置传统远程 Web 后端；外部内容平台与用户自配的 OpenAI 兼容服务是受控的网络依赖，不是本项目的服务端。

## 核心技术方向

项目以 **React + TypeScript** 作为主要开发技术，用于实现页面、交互、业务流程和大部分应用逻辑；通过 **Capacitor** 连接 Android 原生能力；只有必须依赖手机系统或本地高性能处理的部分才使用 **Kotlin** 开发。

整体结构大致如下：

```text
Android APK
├── React 应用界面层
├── 本地字体、图标和静态资源
├── 共享 TypeScript 应用逻辑层（任务、AI Flow、Schema、仓储契约）
├── Capacitor 原生桥接层
└── Kotlin 原生能力
    ├── Keystore 与 SQLCipher
    ├── 相册和文件访问
    ├── 视频信息读取与音频提取
    ├── 采集期音视频合并、PCM WAV 分段与媒体探测
    └── 长时间前台任务与硬件编解码
```

## 大致职责划分

TypeScript 主要负责：

- 本地档案、AI 设置和各主要功能页面；
- 页面状态、用户交互和业务流程；
- 链接解析、任务状态机、内容拆解与 AI 结果展示；
- 任务进度、错误提示和操作引导。

Kotlin 主要负责：

- Android 相册、文件系统和设备能力；
- URL 采集所需的本地视频、音频处理和媒体探测；
- Media3 / MediaCodec 等原生媒体能力；
- 可在退后台继续的前台任务；
- 后续确有需要的端侧原生能力。

视频裁剪、成片生成/保存、系统分享与目标 App 唤起属于制作或发布能力，首轮均为 `planned`，不在当前 Kotlin 运行时职责内。

预计项目绝大多数页面和业务代码使用 TypeScript，Kotlin 被控制在少量、职责明确的原生能力模块中。

## 已锁定架构基线

现阶段已锁定以下基础方向：

1. 产品首先以 Android APK 形式开发；
2. APK 内置本地页面资源，不以云端网页套壳作为运行基础；
3. React + TypeScript 是主要开发技术；
4. Capacitor 负责连接 TypeScript 与 Android 原生能力；
5. Kotlin 只承担文件、媒体处理、后台任务和系统交互等必要原生能力；
6. 视频处理等重型任务不直接放在 Web 页面中执行；
7. 页面只通过 `AppRuntime` 访问本地档案、AI 设置、任务、内容拆解、观察会话和能力注册表；
8. SQLCipher 保存结构化记录，媒体与正式 JSON 保存到应用私有文件目录，API Key 和数据库密钥由 Android Keystore 保护；
9. 首版没有登录、注册、云同步、远程任务队列或自动发布；制作、素材、发布明确为 `planned`；
10. 退后台的长任务由前台服务继续；中断后只允许用户手动重试，不自动续跑。

本文档不重复详细产品契约，完整范围见全局规范。
