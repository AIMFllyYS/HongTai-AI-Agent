# 宏泰AI智能体：项目整体架构方向

## 项目形态

本项目计划采用 **Capacitor 混合架构**，从零开发一个可独立安装和运行的 Android APK。

最终 APK 不是简单打开云端网页，而是将 React、TypeScript 页面以及字体、图标等静态资源直接打包进 APK。安装后，应用页面不依赖 EdgeOne 或其他 Web 服务器加载。

## 核心技术方向

项目以 **React + TypeScript** 作为主要开发技术，用于实现页面、交互、业务流程和大部分应用逻辑；通过 **Capacitor** 连接 Android 原生能力；只有必须依赖手机系统或本地高性能处理的部分才使用 **Kotlin** 开发。

整体结构大致如下：

```text
Android APK
├── React / TypeScript 页面与业务逻辑
├── 本地字体、图标和静态资源
├── 本地数据、素材和项目文件
├── Capacitor 原生桥接层
└── Kotlin 原生能力
    ├── 相册和文件访问
    ├── 视频信息读取与音频提取
    ├── 视频裁剪、拼接、转码和字幕合成
    ├── 长时间任务与硬件编码
    ├── 成片保存
    └── 系统分享及目标 App 唤起
```

## 大致职责划分

TypeScript 主要负责：

- 登录、业务档案和各主要功能页面；
- 页面状态、用户交互和业务流程；
- 模板编辑与 AI 结果展示；
- 剪辑方案组织；
- 任务进度、错误提示和操作引导。

Kotlin 主要负责：

- Android 相册、文件系统和设备能力；
- 本地视频、音频和字幕处理；
- Media3 等原生媒体能力；
- 长时间后台任务；
- 成片保存、系统分享和其他 App 唤起；
- 后续确有需要的端侧原生能力。

预计项目绝大多数页面和业务代码使用 TypeScript，Kotlin 被控制在少量、职责明确的原生能力模块中。

## 当前架构基线

现阶段只确定以下基础方向：

1. 产品首先以 Android APK 形式开发；
2. APK 内置本地页面资源，不以云端网页套壳作为运行基础；
3. React + TypeScript 是主要开发技术；
4. Capacitor 负责连接 TypeScript 与 Android 原生能力；
5. Kotlin 只承担文件、媒体处理、后台任务和系统交互等必要原生能力；
6. 视频处理等重型任务不直接放在 Web 页面中执行；
7. 具体功能、数据存储、AI 接入和各模块实现方式，后续逐项讨论后再确定。

本文档仅用于固定最基础的整体架构方向，防止后续讨论和开发过程中发生技术路线偏移，不代表完整产品方案或详细技术设计。
