## 为什么会乱

当前界面是按**系统对象**组织的：任务、任务详情、拆解报告、制作项目、模板，各占一个页面或一段区块。但用户脑子里只有三个动词：

1. 我要拆解一条爆款；
2. 我要做一条自己的视频；
3. 我要看看我以前弄过什么。

系统对象和用户动词对不上，就出现了这些具体症状：一个「拆解」要跨三个路由；首页两张编号 `01` / `02` 的卡片暗示「先做 1 再做 2」，实际却是二选一；「模板」「制作页里的素材」「富迪素材库」三个词指向三种不同的东西；页头有个点了没反应的通知铃。

新用户的判断依据只有「屏幕上现在最显眼的东西是什么」。所以规则要定在「显眼度」和「层级」上，而不是定在「信息完整度」上。

## 四条硬规则

### 规则一：层级按「对象关系」分配，不按「内容多少」分配

| 层 | 什么时候用 | 判据 |
| --- | --- | --- |
| 底部导航（路由） | 用户切换到**另一件事** | 换了对象，且用户可能从任何地方直接过来 |
| 页面路由 | 进入**某一个具体对象** | 有 ID，能被历史记录指向 |
| Tab | 同一个对象的**不同视角** | 换 Tab 不改变「我在看哪个东西」 |
| 弹层 | **不改变当前对象**的辅助信息 | 关掉之后用户回到原处，什么都没变。形态与手势见[动效规范](动效规范.md)：选择栏目用底部 Sheet（点选、拖把手、下滑、点遮罩）；加号新建也是同一张 Sheet，不是另一种菜单 |

按这张表判定，结论是固定的：

- 「原始文稿」与「AI 自动拆解」是同一条作品的两个视角 → **Tab**，不是两个路由。
- 「粘贴链接」与「上传视频」是同一个动作（开始拆解）的两种来源 → **Tab**，不是两张并列的卡片。
- 阶段页的「分镜文稿 / 配音 / 合成 / 成片」是同一个制作项目的连续阶段 → **同一路由的阶段状态**，不是四个路由；分镜卡就地承载逐句编辑与微调，不再用「预览 / 文案 / 素材」三个 Tab 分摊同一项目。
- 「处理中」与「已完成」是同一个任务的两个时间态 → **同一路由的状态**，不是两个路由。
- 「富迪素材库」是不改变任何对象的宣传信息 → **弹层**，入口在页头右上角，不占底部导航。

### 规则二：任何一屏，任何时刻，只有一个主按钮

主按钮是**当前这件事的下一步**，同一时刻只能有一个：

- 拆解首页：内容流里的「开始拆解 / 选择视频并拆解」。它不是底栏按钮，也不是加号。
- 制作工作台、观察确认等阶段页：仍可用 `AppShell` 的 `contextualAction`。
- 底栏中间加号打开「新建」弹层，含义是换一件事，不是当前页的主按钮。动画走共享 Overlay 上滑+遮罩，可点可拖可滑关。

推论：

- 主按钮的**文案随阶段变化**，用户永远不需要判断「这一步该点哪个」。
- 其余动作降级为次要按钮、行内动作或页头 `⋮` 菜单。
- 破坏性动作（删除）永远不做主按钮，且保留二次确认。
- 不用 `01` / `02` 这类编号暗示顺序，除非它们**真的**是必须依次完成的步骤。

### 规则三：不让用户自己找下一步

- 状态变化就地反映在当前屏幕上，不要求用户点「查看详情」「查看结果」才能看到已经产生的东西。
- 一个流程走完，下一步动作必须已经出现在底部操作条上。
- 同一件事只能有一条路径。公网链接和本地视频必须落在同一套页面结构里，历史记录点进去也是同一个地方。

### 规则四：不渲染没有行为的控件

看起来能点、点了没反应的东西，会让用户认为整个应用没做完。页头通知铃、未接入的发布入口、闲置的 Tab 组件都属于此类。要么接上真实行为，要么不渲染。

## 目标结构

冷启动 `BrandSplash` 不是导航层：对齐未归档 S0，展示应用图标、产品名「宏泰 AI 智能体」与标语「让 AI 帮你把内容做好」。不写版本脚注、不写「正在启动」。动效见[动效规范](动效规范.md)第 6 节。进首页后仍没有固定品牌顶栏。

### 底部导航：4 个滑动 Tab + 中间加号

```
┌──────────────────────────────────────┐
│  观察    拆解     ＋     模板    设置 │
│   ◉      ◉      ■      ◉      ◉   │
└──────────────────────────────────────┘
  /observation/new
         /
                    /templates
                            /settings
加号打开弹层，不占滑动位：
  智能成片 → /create?entry=agent
  爆款复刻 → /create?entry=replica
  拆解新链接 → /?intent=paste
```

路由匹配只认 pathname；`?entry=`、`?intent=`、`?sourceId=` 只作入口意图，由目标页消费后从地址栏去掉。

滑动只覆盖观察、拆解、模板、设置。制作、复刻从加号进入；这些路由上加号高亮，并关闭左右滑（旧微调路由 `/create/:projectId/edit` 退役为兼容重定向，见「制作页」）。底栏内容区约 48px（另加系统安全区）。中间加号是栏内 32px 方圆（圆角 `--radius-plus` / 12px），上下留白，垂直中线与左右图标组对齐，不做成贴满栏高的大方块。第 6 格「富迪素材库」仍不占底栏，入口在观察、拆解、模板页头像左侧，以及制作页页头。

```
│ │▣ │职场穿搭爆款逻辑   │ › │ │
```

切到「上传视频」时，输入区换成未归档 S2 的整块上传区卡片：浅底圆角、居中白底视频图标、标题「选择一段 MP4 视频」、两行说明（先识别口播 / 最大 250MB · 只保存在本机）。主按钮变成「选择视频并拆解」。两种来源共用同一个主按钮位置。导入进度就地显示，不新开页面。稿上的「全部」没有对应路由，不渲染。

「最近拆解」记录支持长按打开统一的 `记录操作` Sheet。Sheet 的「取消」只关闭菜单；「删除记录」只对已进入终态的任务开放，进行中的 `queued/running` 记录显示锁定原因。终态删除会二次确认，并由 `runtime.tasks.delete(taskId)` 删除该任务的私有媒体与产物；任务、报告和结构化数据的删除边界由运行时再次校验，不能由页面文案代替。

### 任务页 `/tasks/:id`：一个路由，两种状态

处理中和已完成是同一个页面的两种状态，**自动切换，不需要用户点任何东西**。

```
状态 A：处理中                    状态 B：已完成
┌──────────────────────────┐     ┌──────────────────────────┐
│ ←   拆解详情          ⋮  │     │ ←   拆解完成          ⋮  │
├──────────────────────────┤     ├──────────────────────────┤
│ ┌──────────────────────┐ │     │ ┌──────────────────────┐ │
│ │🎬抖音·视频   ⟳进行中 │ │     │ │[封面] 标题           │ │
│ │[封面] 标题…          │ │     │ │  @作者 · 03:42       │ │
│ └──────────────────────┘ │     │ └──────────────────────┘ │
│ ┌──────────────────────┐ │     │ ┌──────────────────────┐ │

│ │ ✓ 解析作品           │ │     │ └──────────────────────┘ │
│ │ ⟳ 获取文稿           │ │     │ ┌─────────┬────────────┐ │
│ │ ○ 保存产物           │ │     │ │原始文稿 │ AI 拆解   │ │
│ └──────────────────────┘ │     │ │         │  ▔▔▔▔▔   │ │

│                          │     │ │"如果你还在手动整理…" │ │

└──────────────────────────┘     └──────────────────────────┘
```

要点：

- 处理中不给主按钮。用户此时唯一该做的事是等待或离开，底部只有一句「任务在后台运行，可以放心离开此页」。真实进度仍是七个采集阶段，不会改成假的 4 步 Pipeline。
- 采集完成但还没跑 AI 拆解时，「AI 拆解」Tab 内是空态，底部主按钮为「开始 AI 拆解」。用户不需要理解 `analysisStatus` 这种内部概念。
- 图文任务第一个 Tab 名为「图文正文」。
- 「按清单复刻」「重新拆解」「删除」放页头「更多操作」Sheet，不占底部主按钮位。稿上的「分享结果」没有真实能力，不渲染。
- 三个旧路径全部保留为别名，指向同一个页面组件：`/tasks/:id/processing` 与 `/tasks/:id` 按状态自动呈现，`/tasks/:id/analysis` 打开时默认选中「AI 拆解」Tab。Tab 状态可从 URL 恢复，刷新和返回都不丢。
- 拆解成功后顶栏为「拆解完成」，思考中或尚未拆解时顶栏为「拆解详情」。底部主操作在拆解成功后只有「用它做视频」；「存为模板」与「按清单复刻」放在页头「更多操作」Sheet。
- 摘要卡下始终渲染点赞/收藏/评论/分享/播放五格。解析到非负整数则显示该整数，否则「未解析到」；本地上传没有平台统计，五格都是「未解析到」。

### 制作页 `/create`

> 2026-08-28 起，本节按 spec [`rebuild-production-pipeline`](../.trae/specs/rebuild-production-pipeline/spec.md)（文稿先行管线 + 阶段化 Agent 页）描述信息架构；源码层已实现并通过 `pnpm check` 与 web build（浏览器/真机视觉走查与发版验收未完成），落地状态以[当前能力与发布状态](当前能力与发布状态.md)登记为准，未落地能力不得画成已接通。

新建时第一屏只给两张入口卡，不是三种制作方式并列。加号「智能成片 / 爆款复刻」经 `?entry=` 直达对应表单；表单页头与未归档 S6 一致（智能成片 / 爆款复刻 +「更换」），选入口与工作台仍为「制作」+ 素材库。

1. **智能成片**：一句话需求必填，可导入自己的照片/视频素材；AI 流式生成分镜文稿，用户逐句核对确认后逐句配音、本地合成。来源拆解、主文字、文字预设、贴纸建议折叠进「高级项」（默认收起，可展开）；不再有预设时长四选一，时长由分镜文稿与实测配音音频驱动，总时长 15–60 秒为软边界，超界时提示回改文稿或用户确认后继续。口播切片是这张卡流程里的二次选项（上传自带原声的口播 MP4 + 逐字稿，校验时长上限，只烧字幕），不是第三张顶层卡。内部入口 id 仍是 `agent`。
2. **爆款复刻**：必须先有成功拆解；选中来源后进入既有 `/replica/:taskId` 向导。没有拆解时说明先去采集并运行 AI 自动拆解，并提供去拆解的入口。边界：拆解只是智能成片的可选增强（参考输入），不再是建项目的前置条件——未选任何拆解也能直接用一句话需求发起智能成片。

```
│ 🎬 制作           [🎁素材]│     │ 智能成片            更换│

│ │ 逐句核对后本地合成    │ │     │ ▸ 高级项（来源拆解 / 主  │
│ └──────────────────────┘ │     │   文字 / 文字预设 / 贴纸）│
│ ┌──────────────────────┐ │     ├──────────────────────────┤

│ └──────────────────────┘ │

                                 ┌──────────────────────────┐
                                 │ 爆款复刻            更换│
                                 │ 参考哪条拆解 → 按清单复刻│
                                 │ 没有拆解：去拆解一条     │
                                 └──────────────────────────┘
```

选入口时不显示底部主按钮。底部主按钮上方不挂悬浮阻断文案；缺一句话需求由表单本体的空态与禁用主按钮表达，不再把 6+ 个决策一次性抛给用户。

**阶段化 Agent 会话页。** 项目创建后，工作台呈现为阶段化 Agent 会话：需求 → 分镜文稿 → 配音 → 合成 → 成片。每阶段有且只有一个明确产物与一个主按钮；已完成阶段的产物保持可见、可回改；回改触发受影响阶段的诚实重建——改某句文案只需该句重新配音，其余句保持已就绪，不整链重跑、不伪造完成。Agent 与复刻做成的项目共用卡片、历史与阶段页。

| 阶段 | 产物 | 主按钮 | 回改与失败语义 |
| --- | --- | --- | --- |
| 需求 | 一句话需求与已导入素材（表单页） | 创建制作项目（爆款复刻为「按清单复刻」） | 修改需求则后续阶段逐阶段重建确认 |
| 分镜文稿 | 逐句分镜卡：口播文案、素材绑定建议、贴纸建议、预估时长；预估总时长实时可见 | 确认文稿，开始配音（生成中显示流式进度） | 逐句编辑文案与素材绑定，预估时长随之更新 |
| 配音 | 逐句已就绪配音（持久化 narration 资产）与句级/词级时间戳 | 开始合成（逐句合成中显示进度） | 改句 → 该句重新配音，其余句保持已就绪；单句失败可单独重试，已成功句保持就绪，不伪造成功 |
| 合成 | 9:16 成片（真实渲染进度事件） | 进度条（按钮禁用） | 失败保留旧成片与可解释恢复路径，主按钮按 `TaskIssue.action` 决定 |
| 成片 | 可播放成片 | 再做一条 | 删除成片、删除项目（行内） |

要点：

- 分镜文稿流式生成：提交一句话需求（可选带参考拆解与素材 insight）后逐句分镜卡流式出现，用户逐句核对；未选任何拆解也可直接发起。
- 时长由文稿与实测音频驱动：每镜时长 = 对应句实测 TTS 音频时长，总时长 = Σ实测时长，15–60 秒为软边界；不再有「镜头总和精确等于预设目标」的硬约束。
- 字幕 cue 边界来自实测：Provider 支持原生时间戳时直用；OpenAI 兼容路径用 Whisper 词级转写反查，UI 诚实标注 `asr-fallback` 精度差异；不再按字符比例估算。
- 微调能力合并进分镜卡：逐镜文案、素材绑定、贴纸、字幕模板、语速、BGM 音量在分镜卡上就地编辑；独立微调路由 `/create/:projectId/edit` 退役为兼容重定向，跳转到阶段页对应位置；存量项目卡片入口同样指向阶段页。
- 合成阶段只展示真实渲染进度事件（沿用 synthesize_narration / export 阶段流），无假进度；旧 v3 项目按原计划时长只读兼容渲染，存量项目不失效。
- 预览区固定在页面上部，9:16 居中，最大宽度约 280px，未出片时显示占位或首帧。合成进度与 `project.issue` 显示在预览区附近，不依赖 5 秒后消失的顶部通知。

**口播切片（原「数字人」模式）。** 模式名从「数字人」改为「口播切片」，语义保持现状：用户自带口播 MP4 + 逐字稿 + 时长上限校验，只烧字幕。UI 文案不得暗示 app 内生成数字人形象或口型；云数字人（云 API，BYO-Key）为 Phase 2 另立 spec，未立项前不得画成已接通。

### 富迪素材库入口

```
┌──────────────────────────────┐
│ 拆解              🎁  林     │
│                   ↑   ↑      │
│              素材库  头像    │
└──────────────────────────────┘
```

- 位置：观察、拆解、模板三个主 Tab 页头，头像左侧；制作页页头右上角仍保留同一入口。
- 视觉：三维礼盒贴纸 +「素材库」胶囊，走 design token，不硬编码色值。
- 动效：低频、有间隔的轻微弹跳和晃动；`prefers-reduced-motion: reduce` 时完全静止；不遮挡内容、不抢焦点、不改变点击命中区。
- 形态：仍是居中弹层，可 Esc 关闭，焦点管理正确。遮罩与进出场走同一 Overlay（`placement="center"`），不手写第二套 backdrop。打开后展示随包宣传图，不是可检索、可导入的素材管理系统。

### 模板页 `/templates`

页头「模板」，副标题「套用验证过的结构，快速开拍同款」，右上素材库入口在头像左侧。空白模板从空态「创建空白模板」进入，不占页头。推荐区左侧是搜索框、右侧仍是 hint「本机精选 · 滑动查看」，按名称、摘要或公式过滤本机模板，不编造结果。横滑卡和「全部模板」列表都来自 `runtime.templates.list()`；有 `sourceTaskId` 的模板读取来源任务真实 `content.cover`，远程解析优先使用安全封面图，本地视频使用受控视频 URI 的 `preload="metadata"` 首帧；来源媒体已清理时显示「原视频封面不可用」，自定义模板才使用色块+公式，不用 Unsplash。徽章写「我的」。卡片 meta 为「N 个可替换位 · 使用次数未解析到」。筛选 chip「全部 / 职场 / 到店 / 带货 / 知识」按名称、摘要或公式关键字过滤，无匹配显示「未解析到这类模板」，不藏 chips。「使用」打开本页编辑器：`/create` 没有 template 参数，不得假跳转制作。底栏「从拆解结果保存新模板」走真实 `createFromAnalysis`。禁止写「2.4 万人」「1.8 万人」「9600 人」或官方热度。

### 设置页 `/settings`

页头只写「设置」，没有副标题。资料行 48px 头像 + 名字 +「门店 · 行业」。分组与未归档 S8 一致：

- 通用：我的资料、AI 服务、通知提醒（本机开关，关掉后不再弹出页内通知）
- 外观：深色模式（跟随系统 / 浅色 / 深色；深色是浅色 NA2 的 token 映射，小控件走 `--palette-brand-tint` 等深薄荷井，不得留下浅色 `#fff` / `#e6f7f1` 井）、主题色（当前只有品牌绿，可点开展示，不假装有第二套色）
- 数据：清理缓存（点击进入 `/settings/storage` 存储分析页；扫描应用私有目录的真实文件大小，按拆解任务、观察、制作、模板、缓存与应用配置分组；媒体/缓存可逐项二次确认删除，任务、报告、计划、模板等数据文件明确显示为不可删除）
- 其他：关于（`runtime.deviceSettings.getAppInfo()` 的版本号）、隐私说明（本机 Keystore 文案）

AI 服务右侧用 `textModel` 与 `hasApiKey`，不写死供应商名。页脚写本机应用数据与 Android Keystore。未归档 S8 没有「检查更新 / 用户协议」，不补假入口。关于页顺序为：本机版本卡 →「更新日志 / 设计稿对照」两行（同一 `settings-list`）→「本版要点」（当前安装版本的本地说明）。并可进入：

- `/settings/app-info/updates`：用 iframe 嵌入官方更新站 `https://husteread.com/HongTai/download.html`（标题「更新日志」，需要网络；不是应用内假「检查更新」）
- `/playbook`：设计稿对照；该路由不出现在底栏

### 观察页 `/observation/new` 与报告

页头标题用「AI 智能诊断」，副标题「舌象或面部，结果仅供日常参考」，右上素材库入口在 36px 白描边头像左侧，头像进设置。分段为「面部观察 | 舌象观察」，默认面部。采集卡用稿上的面/舌样张作底板，空态只保留拍摄说明，落在照片区内底部并略上移，白色荧光、常规字重，四角取景框为白，并叠加镭射扫光；页内按钮是「拍摄照片 / 相册选择」。选图后打开确认 Sheet，点「确认使用」后 `createSession` 并立刻进入 `/observation/:sessionId` 的进行中页（未归档 S9b「AI 正在观察」：真图扫光、青绿角标、深度思考、五模块状态、胶囊「取消本次观察」，无底栏、无体征数字）。生成由该页 `runReport` 启动；完成后同一地址切到 S10 观察报告。取消只返回起始页，后台本次生成仍可能跑完并写入会话，不得写成「已停止 AI」。起始页采集卡只服务选图，不再挂生成进度。起始页副标题已承担「日常参考」，完整免责只放页底，不再在标题下重复长文案；报告页顶部与底部展示免责声明。隐私句：「图片只保存在本机，不会上传或公开」。历史区标题「最近观察」，卡片按 `M/Observation Card`，缩略图用该次真实图片，不编 fixture 标签；卡片支持长按打开与拆解相同的 `记录操作` Sheet，只有 `succeeded/failed` 会话可以二次确认后调用 `runtime.diagnosis.deleteSession(sessionId)` 删除，`pending/running` 始终显示不可删除原因。成功报告是详情页：无底栏，页底固定胶囊输入条，可直接打字；发出追问或已有历史时聚焦输入，则打开 rise Overlay「AI 追问」（拖动手把收起、右上关闭、Esc/点遮罩关闭）。对话只出现在该悬浮窗。助手回复按简单 Markdown 渲染（标题、列表、加粗、行内代码），复制仍写入原始文本；不提供未接通的「有用」反馈。宿主层底栏由路由 `showNav` 控制：一级 Tab 默认显示，观察会话详情（进行中/报告）关闭；后续详情页同样在路由表关闭，不再在 `App` 层强制常驻。报告允许不确定的初步判断或证候倾向，供用户到医院正规核实；禁止确诊口吻、概率数字、处方、用药剂量和整体健康评分。

## 本轮不做

- 不重建整页素材库（搜索、分类封面网格）。模板页按未归档 S7 展示本机结构，不造官方热度，也不把「使用」假跳到没有 template 参数的制作入口。
- 不做时间轴、逐帧剪辑或转场编辑器。`docs/superpowers/specs/2026-08-12-video-workflow-management-design.md:176` 明确不做时间线，`docs/手机端基础视频编辑器与口播自动剪辑调研.md:18` 也写明当前不具备。
- 不新增未授权的 `AppRuntime` 服务。互动量已进入 `TaskContentDetail` 可选字段，页面只读该投影，不解析平台原始 JSON。
- 不做云数字人（云 API 生成数字人形象/口型）：Phase 2 未立项（spec `rebuild-production-pipeline`），不得画成已接通；「口播切片」只消费用户自带的口播 MP4 与逐字稿。智能成片建项目不再以拆解为前置，爆款复刻仍以一条成功拆解为输入。
