# 交互信息架构规范

> 定稿：2026-08-17；2026-08-21 按 `docs/Hong/新设计/hongtai-mobile.pen` 未归档画板校正底栏、拆解、制作、模板、设置与观察。本文回答「一个东西应该出现在哪一层」，是 [#88](https://github.com/AIMFllyYS/HongTai-AI-Agent/issues/88)、[#89](https://github.com/AIMFllyYS/HongTai-AI-Agent/issues/89)、[#90](https://github.com/AIMFllyYS/HongTai-AI-Agent/issues/90) 的验收基准。
>
> 当前视觉权威是 `hongtai-mobile.pen` 未归档画板。对象层级仍沿用本文；与 stitch 原稿不同的地方写在「与原始设计稿的差异」。视觉 token 见 `apps/web/src/styles/tokens.css`（NA2/NA3）。

## 为什么会乱

当前界面是按**系统对象**组织的：任务、任务详情、拆解报告、制作项目、模板，各占一个页面或一段区块。但用户脑子里只有三个动词：

1. 我要拆解一条爆款；
2. 我要做一条自己的视频；
3. 我要看看我以前弄过什么。

系统对象和用户动词对不上，就出现了这些具体症状：一个「拆解」要跨三个路由；首页两张编号 `01` / `02` 的卡片暗示「先做 1 再做 2」，实际却是二选一；「模板」「制作页里的素材」「富迪素材库」三个词指向三种不同的东西；页头有个点了没反应的通知铃。

新用户的判断依据只有「屏幕上现在最显眼的东西是什么」。所以规则要定在「显眼度」和「层级」上，而不是定在「信息完整度」上。

## 四条硬规则

### 规则一：层级按「对象关系」分配，不按「内容多少」分配

| 层 | 什么时候用 | 判据 |
| --- | --- | --- |
| 底部导航（路由） | 用户切换到**另一件事** | 换了对象，且用户可能从任何地方直接过来 |
| 页面路由 | 进入**某一个具体对象** | 有 ID，能被历史记录指向 |
| Tab | 同一个对象的**不同视角** | 换 Tab 不改变「我在看哪个东西」 |
| 弹层 | **不改变当前对象**的辅助信息 | 关掉之后用户回到原处，什么都没变 |

按这张表判定，结论是固定的：

- 「原始文稿」与「AI 自动拆解」是同一条作品的两个视角 → **Tab**，不是两个路由。
- 「粘贴链接」与「上传视频」是同一个动作（开始拆解）的两种来源 → **Tab**，不是两张并列的卡片。
- 「预览 / 文案 / 素材」是同一个制作项目的三个视角 → **Tab**。
- 「处理中」与「已完成」是同一个任务的两个时间态 → **同一路由的状态**，不是两个路由。
- 「富迪素材库」是不改变任何对象的宣传信息 → **弹层**，入口在页头右上角，不占底部导航。

### 规则二：任何一屏，任何时刻，只有一个主按钮

主按钮是**当前这件事的下一步**，同一时刻只能有一个：

- 拆解首页：内容流里的「开始拆解 / 选择视频并拆解」。它不是底栏按钮，也不是加号。
- 制作工作台、观察确认等阶段页：仍可用 `AppShell` 的 `contextualAction`。
- 底栏中间加号打开「新建」弹层，含义是换一件事，不是当前页的主按钮。

推论：

- 主按钮的**文案随阶段变化**，用户永远不需要判断「这一步该点哪个」。
- 其余动作降级为次要按钮、行内动作或页头 `⋮` 菜单。
- 破坏性动作（删除）永远不做主按钮，且保留二次确认。
- 不用 `01` / `02` 这类编号暗示顺序，除非它们**真的**是必须依次完成的步骤。

### 规则三：不让用户自己找下一步

- 状态变化就地反映在当前屏幕上，不要求用户点「查看详情」「查看结果」才能看到已经产生的东西。
- 一个流程走完，下一步动作必须已经出现在底部操作条上。
- 同一件事只能有一条路径。公网链接和本地视频必须落在同一套页面结构里，历史记录点进去也是同一个地方。

### 规则四：不渲染没有行为的控件

看起来能点、点了没反应的东西，会让用户认为整个应用没做完。页头通知铃、未接入的发布入口、闲置的 Tab 组件都属于此类。要么接上真实行为，要么不渲染。

## 目标结构

### 底部导航：4 个滑动 Tab + 中间加号

```
┌──────────────────────────────────────┐
│  观察    拆解     ＋     模板    设置 │
│   ◉      ◉      ■      ◉      ◉   │
└──────────────────────────────────────┘
  /observation/new
         /
                    /templates
                            /settings
加号打开弹层，不占滑动位：
  智能成片 → /create?entry=agent
  爆款复刻 → /create?entry=replica
  拆解新链接 → /?intent=paste
```

滑动只覆盖观察、拆解、模板、设置。制作、复刻、微调从加号进入；这些路由上加号高亮，并关闭左右滑。第 6 格「富迪素材库」仍不占底栏，入口在制作页页头右上角。

### 拆解首页 `/`

来源用分段 Tab 切换。大标题在内容区，没有固定品牌顶栏。主按钮只有一个，跟在输入区后面，不钉在底栏。

```
┌──────────────────────────────┐
│ 拆解                      林 │
│ 让 AI 帮你看懂爆款逻辑        │
│                              │
│ │ 粘贴链接 │ 上传视频 │      │ ← 分段 Tab
│ 🔗 粘贴作品链接         粘贴 │
│ ✓ 已识别 抖音 · v.douyin…   │
│ 支持抖音、小红书、B站；快手… │
│ ┌──────────────────────────┐ │
│ │        开始拆解          │ │ ← 唯一主按钮
│ └──────────────────────────┘ │
│ 最近拆解                      │
│ ┌──┬──────────────────┬───┐ │
│ │▣ │职场穿搭爆款逻辑   │ › │ │
│ └──┴──────────────────┴───┘ │
├──────────────────────────────┤
│ 观察  拆解   ＋   模板  设置 │
└──────────────────────────────┘
```

切到「上传视频」时，输入区换成选择说明与限制（单个 MP4、最大 250MB、只保存在本机），主按钮变成「选择视频并拆解」。两种来源共用同一个主按钮位置。导入进度就地显示，不新开页面。稿上的「全部」没有对应路由，不渲染。

### 任务页 `/tasks/:id`：一个路由，两种状态

处理中和已完成是同一个页面的两种状态，**自动切换，不需要用户点任何东西**。

```
状态 A：处理中                    状态 B：已完成
┌──────────────────────────┐     ┌──────────────────────────┐
│ ←   拆解详情          ⋮  │     │ ←   拆解完成          ⋮  │
├──────────────────────────┤     ├──────────────────────────┤
│ ┌──────────────────────┐ │     │ ┌──────────────────────┐ │
│ │🎬抖音·视频   ⟳进行中 │ │     │ │[封面] 标题           │ │
│ │[封面] 标题…          │ │     │ │  @作者 · 03:42       │ │
│ └──────────────────────┘ │     │ └──────────────────────┘ │
│ ┌──────────────────────┐ │     │ ┌──────────────────────┐ │
│ │ ✓ 识别链接           │ │     │ │   ▶  视频播放器      │ │
│ │ ✓ 解析作品           │ │     │ └──────────────────────┘ │
│ │ ⟳ 获取文稿           │ │     │ ┌─────────┬────────────┐ │
│ │ ○ 保存产物           │ │     │ │原始文稿 │ AI 拆解   │ │
│ └──────────────────────┘ │     │ │         │  ▔▔▔▔▔   │ │
│ ⓘ 任务在后台运行，       │     │ ├─────────┴────────────┤ │
│   可以放心离开此页        │     │ │开场钩子 00:00-00:15  │ │
│                          │     │ │"如果你还在手动整理…" │ │
│                          │     │ │[痛点共鸣][利益前置]  │ │
│                          │     │ │痛点铺垫 00:15-01:20  │ │
│                          │     │ │…                     │ │
│                          │     │ └──────────────────────┘ │
├──────────────────────────┤     ├──────────────────────────┤
│      （无主按钮）         │     │      用它做视频         │
├──────────────────────────┤     ├──────────────────────────┤
│ AI  拆解  ＋  模板  设置│     │ AI  拆解  ＋  模板  设置│
└──────────────────────────┘     └──────────────────────────┘
```

要点：

- 处理中不给主按钮。用户此时唯一该做的事是等待或离开，底部只有一句「任务在后台运行，可以放心离开此页」。真实进度仍是七个采集阶段，不会改成假的 4 步 Pipeline。
- 采集完成但还没跑 AI 拆解时，「AI 拆解」Tab 内是空态，底部主按钮为「开始 AI 拆解」。用户不需要理解 `analysisStatus` 这种内部概念。
- 图文任务第一个 Tab 名为「图文正文」。
- 「按清单复刻」「重新拆解」「删除」放页头「更多操作」Sheet，不占底部主按钮位。稿上的「分享结果」没有真实能力，不渲染。
- 三个旧路径全部保留为别名，指向同一个页面组件：`/tasks/:id/processing` 与 `/tasks/:id` 按状态自动呈现，`/tasks/:id/analysis` 打开时默认选中「AI 拆解」Tab。Tab 状态可从 URL 恢复，刷新和返回都不丢。
- 拆解成功后顶栏为「拆解完成」，思考中或尚未拆解时顶栏为「拆解详情」。底部主操作在拆解成功后只有「用它做视频」；「存为模板」与「按清单复刻」放在页头「更多操作」Sheet。

### 制作页 `/create`

新建时第一屏只给两张入口卡，不是三种制作方式并列。加号「智能成片 / 爆款复刻」经 `?entry=` 直达对应表单；表单页头与未归档 S6 一致（智能成片 / 爆款复刻 +「更换」），选入口与工作台仍为「制作」+ 素材库。

1. **智能成片**：导入自己的照片/视频，选定时长，写旁白和字幕后本地合成。数字人口播是这张卡流程里的二次选项（上传已录好原声的 MP4 + 口播稿，只烧字幕），不是第三张顶层卡。内部入口 id 仍是 `agent`。
2. **爆款复刻**：必须先有成功拆解；选中来源后进入既有 `/replica/:taskId` 向导。没有拆解时说明先去采集并运行 AI 自动拆解，并提供去拆解的入口。

```
状态 A1：选入口                 状态 A2：Agent 表单
┌──────────────────────────┐     ┌──────────────────────────┐
│ 🎬 制作           [🎁素材]│     │ 智能成片            更换│
├──────────────────────────┤     ├──────────────────────────┤
│ 这次走哪条路？            │     │ 这次想讲什么？            │
│ ┌──────────────────────┐ │     │ 经营需求 / 参考哪条拆解  │
│ │ 智能成片           ›│ │     │ □ 数字人口播（二次选项）│
│ │ 导入照片或视频，写旁白│ │     │ 主文字 / 文字预设 / 时长 │
│ │ 需逐镜核对            │ │     ├──────────────────────────┤
│ └──────────────────────┘ │     │ │   🎥 创建制作项目     │ │
│ ┌──────────────────────┐ │     └──────────────────────────┘
│ │ 爆款复刻             ›│ │
│ │ 按清单逐项绑素材      │ │     状态 A3：爆款复刻选来源
│ └──────────────────────┘ │     ┌──────────────────────────┐
└──────────────────────────┘     │ 爆款复刻            更换│
                                 │ 参考哪条拆解 → 按清单复刻│
                                 │ 没有拆解：去拆解一条     │
                                 └──────────────────────────┘
```

项目进行中 / 已完成仍是原来的工作台（9:16 预览、三 Tab、阶段主按钮），Agent 与复刻做成的项目共用卡片、历史和导出微调页 `/create/:projectId/edit`。选入口时不显示底部主按钮。

底部主按钮按阶段推进，任一时刻只显示一个：

| 阶段 | 主按钮 | 次要动作 |
| --- | --- | --- |
| 没有项目（Agent） | 创建制作项目 | 更换入口 |
| 没有项目（爆款复刻） | 按清单复刻 | 更换入口；无拆解时「去拆解一条」 |
| 有项目、无素材 | 添加素材 | 删除项目（行内） |
| 有素材、无计划 | AI 生成制作计划 | 删除素材（行内） |
| 有计划、无成片 | 开始本地合成 | 重新生成计划 |
| 合成中 | 进度条（按钮禁用） | — |
| 已有成片 | 再做一条 | 删除成片、删除项目（行内） |
| 失败 | 重试 | 按 `TaskIssue.action` 决定 |

预览区固定在页面上部，9:16 居中，最大宽度约 280px，未出片时显示占位或首帧。合成进度与 `project.issue` 显示在预览区附近，不依赖 5 秒后消失的顶部通知。

### 富迪素材库入口

```
┌──────────────────────────────┐
│ 🎬 制作新视频      ┌────────┐│
│                    │🎁 素材库││ ← 浅红、低频轻晃
│                    └────────┘│
```

- 位置：制作页页头右上角（`AppShell` 的 `headerAction`）。
- 视觉：浅红色，走 design token，不硬编码色值。
- 动效：低频、有间隔的轻微晃动或脉冲；`prefers-reduced-motion: reduce` 时完全静止；不遮挡内容、不抢焦点、不改变点击命中区。
- 形态：仍是居中弹层，可 Esc 关闭，焦点管理正确。

### 模板页 `/templates`

只展示本机已保存的结构。页头「模板」，副标题「套用验证过的结构，快速开拍同款」。可以从成功拆解保存新模板，也可以新建空白模板并编辑公式、步骤和变量槽。

稿上的「推荐模板 / 官方 / 热度人数」没有本机真实数据，不渲染。

### 设置页 `/settings`

页头「设置」，副标题「资料与 AI 配置都保存在本机」。通用里只有「我的资料」和「AI 服务」；其他里只有「关于」，版本号来自 `runtime.deviceSettings.getAppInfo()`。AI 服务副文案用 `textModel` 与 `hasApiKey`，不写死供应商名。

稿上的通知提醒、深色模式、清理缓存、检查更新、用户协议没有对应真实能力，不渲染。密钥说明仍写本机应用数据与 Android Keystore。

### 观察页 `/observation/new` 与报告

页头用「观察」，不用稿上的「AI 诊断」。添加图片打开 Sheet：拍摄照片、相册选择、取消；主按钮仍是「生成观察报告」。历史区标题为「最近观察」。报告追问进入 Sheet，不提供「复制」或「有用」。

## 与原始设计稿的差异

设计稿没有预见后来新增的能力，以下差异是有意的，执行时按本文为准。

| 项 | 原始设计稿 | 本规范 | 理由 |
| --- | --- | --- | --- |
| 底栏项数 | `DESIGN.md:169` 写 4 项；`_1/code.html:248-268` 画 5 项含「制作」 | 4 个滑动 Tab + 中间加号；制作从加号进入 | `hongtai-mobile.pen` 未归档底栏与 S14；制作不是日常切换的事 |
| 第一项名称 | 「AI」 | 「观察」 | 与真实能力一致，避免把观察理解成通用 AI 助手 |
| 第四项名称 | 「素材」，进入整页素材库 `_6` | 「模板」 | 整页素材库依赖尚未实现的封面、分类与素材管理；模板工作区是真实能力 |
| 首页来源 | `_1` 只有粘贴链接 | 增加「上传视频」Tab | 本地视频拆解是设计稿之后新增的真实能力，属于同一动作的第二种来源 |
| 结果页 Tab | `_5:231-236` 三 Tab「爆款结构 / 文字稿 / 模板库」 | 采用新稿两 Tab「原始文稿 / AI 拆解」 | 「模板库」与底栏「模板」重复；两 Tab 与运行时真实产物一一对应；文案按 `hongtai-mobile.pen` 为「AI 拆解」 |
| 结果页底部动作 | `_5:311-319`「保存模板 / 重新拆解」 | 底栏仅「用它做视频」；存为模板 / 按清单复刻 / 重新拆解 / 删除进「更多操作」Sheet | 「重新拆解」是纠错动作不是下一步；「用它做视频」承接拆解与制作接通；稿上「分享结果」省略 |
| 制作页模板选择 | `_7:175-206` 横向 9:16 模板封面卡 | 横向「参考哪条拆解」卡 | 模板封面依赖不存在的封面图；参考拆解是当前建项目的真实前置 |
| 制作页模式 | `_7` 单表单里「素材剪辑+配音 / 数字人」并列 | 第一屏两张卡：智能成片 / 爆款复刻；数字人口播留在智能成片流程内 | 爆款复刻已是独立向导；把数字人升成第三张卡会让用户以为三条对等产品路径。智能成片文案不得写「看懂素材」 |
| 制作页素材筛选 | `_7:209-216` 来源 chip | 不做 | 素材没有来源分类这一属性 |
| 制作完成动作 | `_7:297-305`「继续优化 / 发布视频」 | 「再做一条」 | 发布能力为 `planned`，不得给出未接入的入口 |
| 首页能力卡 | `_1:159-176` 四张能力卡 | 不做 | 已按 `docs/superpowers/specs/2026-08-07-mobile-ui-reference-alignment-design.md:57` 有意删除，属虚假能力展示 |
| 详情页互动数据 | `_2:181-202` 点赞/收藏/评论/分享 | 不做 | [前端显示板块对接清单](前端显示板块对接清单.md) 禁止硬编码互动量 |
| 模板页官方推荐 | 新稿 S7 有推荐/官方/热度 | 只保留本机模板 | 没有官方模板源或热度人数 |
| 设置页系统能力 | 新稿 S8 有深色模式、清缓存、检查更新、用户协议 | 省略这些行 | 没有对应真实能力 |
| 观察页标题 | 新稿写「AI 诊断」 | 「观察」 | 产品只提供日常观察参考，不得改成诊断 |

## 本轮不做
